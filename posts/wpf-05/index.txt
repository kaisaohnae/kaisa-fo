24:T3eb3,<h1>화면 전환과 다이얼로그 패턴</h1>
<blockquote>
<p>요약: ContentControl과 DataTemplate로 ViewModel을 갈아 끼워 화면을 전환하고, 대화상자는 서비스로 추상화하는 방법을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 언제 어떤 전환인가</h2>
<p>WPF에는 웹 라우터가 없다. 화면 흐름을 초기에 고른다.</p>
<table>
<thead>
<tr>
<th>방식</th>
<th>맞는 경우</th>
</tr>
</thead>
<tbody><tr>
<td>Window를 여러 개</td>
<td>독립 도구 창, 팝업 편집기</td>
</tr>
<tr>
<td><code>Frame</code> + <code>Page</code></td>
<td>마법사, 뒤로 가기 스택이 필요할 때</td>
</tr>
<tr>
<td><code>UserControl</code> + <code>ContentControl</code></td>
<td>단일 메인 셸. 메뉴만 바뀌는 업무 앱</td>
</tr>
</tbody></table>
<p>작은·중간 앱은 <strong>현재 ViewModel을 바꾸고 ContentControl이 View를 고르는 방식</strong>이 단순하다. ViewModel이 UI 타입을 몰라도 된다.</p>
<p>대화상자(<code>MessageBox</code>, 파일 선택)를 ViewModel에서 직접 호출하면 테스트가 실제 창을 연다. <strong>인터페이스 뒤</strong>로 숨긴다.</p>
<hr>
<h2>2. 핵심 개념</h2>
<table>
<thead>
<tr>
<th>개념</th>
<th>한 줄</th>
</tr>
</thead>
<tbody><tr>
<td><code>CurrentViewModel</code></td>
<td>셸이 지금 보여줄 화면 상태</td>
</tr>
<tr>
<td><code>ContentControl</code></td>
<td><code>Content</code>에 넣은 객체를 화면에 표시한다</td>
</tr>
<tr>
<td>DataTemplate</td>
<td>그 객체의 타입 → 어떤 View XAML인지 매핑</td>
</tr>
<tr>
<td><code>IDialogService</code></td>
<td>확인/알림을 ViewModel이 UI API 없이 요청하는 창구</td>
</tr>
<tr>
<td><code>IFileDialogService</code></td>
<td>열기/저장 경로. 마찬가지로 추상화</td>
</tr>
</tbody></table>
<p><code>Frame.Navigate(typeof(Page))</code>는 View 타입을 코드가 알게 된다. MVVM과 섞이면 책임이 흐려진다. 셸+DataTemplate을 기본선으로 둔다.</p>

<hr>
<h2>5. 주의 / 흔한 실수</h2>
<ul>
<li><strong>ViewModel에서 <code>new SettingsView()</code>.</strong> View 타입이 VM에 들어간다. DataTemplate만 View를 안다.</li>
<li><strong><code>MessageBox.Show</code>를 명령 한가운데.</strong> CI·단위 테스트가 멈춘다.</li>
<li><strong>Frame+Page와 ContentControl을 한 셸에 혼용.</strong> 뒤로 가기 스택이 두 개가 된다. 하나를 고른다.</li>
<li><strong>전환마다 무거운 ViewModel을 무조건 <code>new</code>.</strong> 입력 중이던 설정이 날아간다. 유지가 필요하면 필드로 들고 있는다.</li>
<li><strong>커스텀 다이얼로그 Window의 DataContext를 안 넘김.</strong> 바인딩이 비고, 확인 결과를 닫힌 창에서 읽지 못한다. 결과를 서비스 반환값으로 받는다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>전환 구조는 초기에 정할수록 싸다. <strong>CurrentViewModel + DataTemplate + DialogService</strong>가 실무에서 단순하다.</p>
<ul>
<li>화면 전환 → 셸 ViewModel의 현재 VM 교체</li>
<li>View 선택 → <code>DataTemplate DataType</code></li>
<li>알림·파일 → 인터페이스, WPF 구현은 한곳</li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li>홈/설정 버튼으로 <code>ContentControl</code> 내용이 바뀌는지 확인한다.</li>
<li>설정에서 <code>DarkTheme</code>를 켠 뒤 홈에 갔다 와도 값이 남게, <code>SettingsViewModel</code>을 필드로 재사용한다.</li>
<li>삭제 명령에 <code>IDialogService.Confirm</code>을 넣고, 취소를 누르면 목록이 그대로인지 확인한다.</li>
</ol>
