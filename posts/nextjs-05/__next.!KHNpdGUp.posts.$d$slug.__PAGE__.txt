3:T2a54,<h1>SSG·generateStaticParams·정적 export</h1>
<blockquote>
<p>요약: 빌드할 때 HTML을 미리 만들고, 동적 주소는 generateStaticParams로 목록을 넘기며, 정적 내보내기 제약을 확인한다.</p>
</blockquote>
<hr>
<h2>1. 왜 이 주제가 필요한가</h2>
<p>검색엔진과 카카오·슬랙 미리보기는 <strong>첫 응답 HTML</strong>을 본다. 빌드 시점에 제목과 본문이 들어 있으면 공유·SEO가 안정적이다. CDN(가까운 서버에서 파일을 나눠 주는 망)에도 올리기 쉽다.</p>
<p><strong>SSG(Static Site Generation, 빌드할 때 HTML을 고정하는 방식)</strong> 가 그 수단이다. <code>/posts/hello</code>처럼 칸이 바뀌는 주소도, 미리 어떤 slug가 있는지 알려 주면 같은 방식으로 만들 수 있다.</p>
<hr>
<h2>2. 한 줄 규칙</h2>
<p>공개되는 모든 slug를 <code>generateStaticParams</code>에 넣는다. 페이지에서 <code>await params</code>를 써도 정적 HTML이다.</p>
<p>정적 내보내기(<code>output: &#39;export&#39;</code>)는 서버가 없다. 빌드 때 읽을 수 있는 데이터만 쓴다.</p>
<hr>
<h2>3. 예제</h2>
<h3>generateStaticParams</h3>
<pre><code class="hljs language-tsx"><span class="hljs-comment">// lib/posts.ts</span>

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">getAllPosts</span>(<span class="hljs-params"></span>): <span class="hljs-title class_">Post</span>[] {
  <span class="hljs-keyword">return</span> <span class="hljs-variable constant_">POSTS</span>;
}

<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">getPost</span>(<span class="hljs-params"><span class="hljs-attr">slug</span>: <span class="hljs-built_in">string</span></span>): <span class="hljs-title class_">Post</span> | <span class="hljs-literal">undefined</span> {
  <span class="hljs-keyword">return</span> <span class="hljs-variable constant_">POSTS</span>.<span class="hljs-title function_">find</span>(<span class="hljs-function">(<span class="hljs-params">p</span>) =&gt;</span> p.<span class="hljs-property">slug</span> === slug);

<pre><code class="hljs language-tsx"><span class="hljs-comment">// app/posts/[slug]/page.tsx</span>
<span class="hljs-keyword">import</span> {notFound} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next/navigation&#x27;</span>;

  <span class="hljs-keyword">return</span> <span class="hljs-title function_">getAllPosts</span>().<span class="hljs-title function_">map</span>(<span class="hljs-function">(<span class="hljs-params">post</span>) =&gt;</span> ({<span class="hljs-attr">slug</span>: post.<span class="hljs-property">slug</span>}));

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> <span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">PostPage</span>(<span class="hljs-params">{params}: <span class="hljs-title class_">Props</span></span>) {

  <span class="hljs-keyword">const</span> post = <span class="hljs-title function_">getPost</span>(slug);
  <span class="hljs-keyword">if</span> (!post) <span class="hljs-title function_">notFound</span>();

  <span class="hljs-keyword">return</span> (
    <span class="language-xml"><span class="hljs-tag">&lt;<span class="hljs-name">article</span>&gt;</span>

<p><code>npm run build</code> 로그에서 <code>/posts/hello</code>가 ●(정적)으로 찍히는지 확인한다. <code>ƒ</code>는 서버가 필요한 동적 라우트다.</p>
<p><code>await params</code>는 Next.js 15 API다. 페이지를 CSR(브라우저에서 JS로 그리는 방식)로 바꾸지 않는다. <code>generateStaticParams</code>가 있으면 해당 slug는 미리 렌더된 HTML이 나온다.</p>
<h3>빌드에 없는 slug</h3>
<pre><code class="hljs language-tsx"><span class="hljs-keyword">export</span> <span class="hljs-keyword">const</span> dynamicParams = <span class="hljs-literal">false</span>;</code></pre>
<p><code>dynamicParams</code>가 <code>false</code>면 <code>generateStaticParams</code>에 없는 주소는 404다. 문서·블로그는 보통 알려진 slug만 빌드한다.</p>
<p>기본값 <code>true</code>면 빌드에 없던 slug를 서버가 그때 만들 수 있다. 정적 내보내기에서는 서버가 없으므로 이 경로에 기대지 않는다.</p>
<h3>정적 내보내기</h3>
<pre><code class="hljs language-ts"><span class="hljs-comment">// next.config.ts</span>
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> {<span class="hljs-title class_">NextConfig</span>} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next&#x27;</span>;

<span class="hljs-keyword">const</span> <span class="hljs-attr">nextConfig</span>: <span class="hljs-title class_">NextConfig</span> = {
  <span class="hljs-attr">output</span>: <span class="hljs-string">&#x27;export&#x27;</span>,
  <span class="hljs-attr">trailingSlash</span>: <span class="hljs-literal">true</span>,
  <span class="hljs-attr">images</span>: {
    <span class="hljs-attr">unoptimized</span>: <span class="hljs-literal">true</span>,
  },
};

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> nextConfig;</code></pre>
<p>결과는 <code>out/</code> 아래 HTML·JS·CSS다. GitHub Pages, S3, 일반 웹 서버에 올린다.</p>
<p>되는 것:</p>
<ul>
<li>빌드 시 마크다운·공개 API를 읽어 HTML 생성</li>
<li><code>generateStaticParams</code>로 만든 상세 페이지</li>
<li>클라이언트에서 외부 API를 치는 화면(SEO 본문이 필요 없을 때)</li>
</ul>
<p>안 되는 것(대표):</p>
<ul>
<li>요청마다 도는 Route Handler</li>
<li>미들웨어로 세션을 검사하는 보호</li>
<li>ISR·<code>revalidateTag</code> 같은 런타임 재검증</li>
<li>서버만 가능한 이미지 최적화(그래서 <code>unoptimized</code>)</li>
</ul>
<p>호스팅에 서버가 있으면 <code>output: &#39;export&#39;</code>를 켜지 않는 편이 기능이 넓다. 정적만 필요하면 켜서 단순화한다.</p>
<h3>notFound</h3>
<pre><code class="hljs language-tsx"><span class="hljs-keyword">import</span> {notFound} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next/navigation&#x27;</span>;

<span class="hljs-keyword">const</span> post = <span class="hljs-title function_">getPost</span>(slug);
<span class="hljs-keyword">if</span> (!post) <span class="hljs-title function_">notFound</span>();</code></pre>
<p><code>notFound()</code>는 <code>not-found.tsx</code>를 렌더한다. <code>throw new Error</code>와 다르다. 없는 글은 404, 파일 읽기 실패는 <code>error.tsx</code>로 나눈다.</p>
<p>목록·sitemap·<code>generateStaticParams</code>에 같은 slug 집합을 쓴다. 한쪽만 빠지면 죽은 링크가 생긴다.</p>

<hr>
<h2>정리</h2>
<p>SSG는 “주소 목록을 빌드에 알려 주고 HTML을 미리 굽는 것”이다. 동적 칸은 <code>generateStaticParams</code>가 그 목록이다.</p>
<p>정적 내보내기는 서버 기능을 포기하는 선택이다. 공개 문서에 맞고, 로그인·웹훅에는 보통 맞지 않는다.</p>
<hr>
<h2>연습</h2>
<ol>
<li><code>[slug]</code> 세 개를 SSG로 빌드한 뒤 <code>out/posts/hello/index.html</code>에 제목이 있는지 연다.</li>
<li>페이지를 <code>await params</code>로 바꿔도 빌드 로그가 정적(●)인지 확인한다.</li>
<li><code>output: &#39;export&#39;</code>를 켠 뒤 깨지는 API·미들웨어·이미지를 목록으로 적는다.</li>
</ol>
