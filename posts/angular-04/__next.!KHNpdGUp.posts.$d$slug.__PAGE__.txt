3:T46cc,<h1>라우팅과 리액티브 폼</h1>
<blockquote>
<p>요약: provideRouter와 lazy loadComponent로 화면을 나누고, 가드·FormBuilder로 진입 조건과 입력 검증을 구성하는 방법을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 왜 라우터와 폼인가</h2>
<p>SPA에서 주소는 화면의 이름이다. 새로고침·공유 링크가 같은 화면을 열어야 한다.</p>
<p>폼은 입력을 클래스로 들고 검증한다. 템플릿의 <code>ngModel</code>만으로는 필드가 늘고 조건이 겹치면 추적이 어렵다. <strong>복잡한 검증·동적 필드</strong>는 Reactive Forms(리액티브 폼)가 맞다. 검색 한 칸은 <code>ngModel</code>로도 충분하다.</p>
<table>
<thead>
<tr>
<th>구성</th>
<th>역할</th>
</tr>
</thead>
<tbody><tr>
<td><code>Routes</code></td>
<td>path ↔ 컴포넌트</td>
</tr>
<tr>
<td><code>loadComponent</code></td>
<td>그 화면 JS를 나중에 받는다</td>
</tr>
<tr>

<td>이동 전에 로그인·권한을 검사한다</td>
</tr>
<tr>

<td>필드 묶음. 값·유효·에러를 한 객체로 본다</td>
</tr>

<h2>5. 주의 / 흔한 실수</h2>
<ul>
<li><strong><code>loadComponent</code> 없이 모든 페이지를 정적 import.</strong> 초기 번들에 관리자 화면이 포함된다.</li>
<li><strong>가드에서 <code>true</code>/<code>false</code>만 반환하고 URL을 안 바꿈.</strong> <code>false</code>는 이동만 취소한다. 로그인 페이지로 보내려면 <code>UrlTree</code>를 반환한다.</li>
<li><strong>라우트 <code>id</code>와 <code>input()</code> 이름 불일치.</strong> <code>withComponentInputBinding</code>은 이름이 같아야 한다.</li>
<li><strong><code>form.value.email</code>이 <code>string | undefined</code>.</strong> <code>nonNullable</code> 또는 <code>getRawValue()</code>를 쓴다. disabled 컨트롤은 <code>value</code>에서 빠진다.</li>
<li><strong>제출 버튼을 <code>invalid</code>로만 disable.</strong> 오류 문구가 안 보여 사용자가 이유를 모른다. <code>touched</code>와 메시지를 병행한다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>URL은 라우터가, 입력은 폼 모델이 책임진다.</p>
<ul>
<li>화면 분할 → <code>loadComponent</code></li>
<li>진입 조건 → <code>CanActivateFn</code> + <code>createUrlTree</code></li>
<li>파라미터 → <code>withComponentInputBinding</code> + <code>input()</code></li>
<li>검증 → <code>FormBuilder</code> + <code>Validators</code></li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li><code>/posts/1</code>에 비로그인으로 진입해 <code>/login?redirect=...</code>로 가는지 확인한다. 로그인 후 원래 글로 돌아오게 한다.</li>
<li>이메일 형식이 틀릴 때 <code>emailErr</code> 문구가 필드 아래에 붙는지 확인한다.</li>
