24:T3149,<h1>리스트·키·성능의 기본</h1>
<blockquote>
<p>요약: 긴 목록은 빌더로 그리고, 키로 아이템 정체성을 지키면 스크롤이 버틴다.</p>
</blockquote>
<hr>
<h2>1. 왜 / 언제</h2>
<p>피드·검색 결과·채팅처럼 아이템이 많으면 <code>Column</code> + <code>map</code>은 한 번에 모든 자식을 만든다. 스크롤이 버벅이고 메모리만 는다.</p>
<p><code>ListView.builder</code>는 화면에 보이는 근처만 위젯으로 만든다. 이것이 기본이다.</p>
<p>같은 타입 행이 재배열되면 또 다른 문제가 생긴다. 입력 중이던 글자가 다른 행으로 옮겨 간다. 원인은 레이아웃이 아니다. Flutter가 <strong>누가 같은 위젯인지</strong>를 자리로만 맞춰서다. 그때 키가 필요하다.</p>
<hr>
<h2>2. 핵심</h2>
<p>키는 위젯의 이름표다.</p>
<p>Flutter는 리빌드할 때 이전 트리와 새 트리를 맞춘다. 기본 규칙은 타입과 위치다. 같은 자리의 <code>ListTile</code>은 같은 것으로 본다. 목록이 섞이면 3번 자리의 State가 새 3번 아이템에 붙는다.</p>
<p>키를 주면 타입+키로 맞춘다. 서버 id처럼 <strong>안 바뀌는 값</strong>을 <code>ValueKey</code>로 붙인다. 인덱스를 키로 쓰면 재배열과 함께 키가 바뀌므로 의미가 없다.</p>
<table>
<thead>
<tr>
<th>키</th>
<th>언제</th>
</tr>
</thead>
<tbody><tr>
<td><code>ValueKey(id)</code></td>
<td>리스트 아이템, 폼 필드. 값이 안정적이어야 한다.</td>
</tr>
<tr>
<td><code>ObjectKey(obj)</code></td>
<td>동일 인스턴스로 구분할 때.</td>
</tr>
<tr>
<td><code>UniqueKey()</code></td>
<td>매번 새 위젯으로 강제해 상태를 리셋할 때.</td>
</tr>
<tr>
<td><code>GlobalKey</code></td>
<td>다른 서브트리에서 State에 접근할 때. 남용하면 비싸다.</td>
</tr>
</tbody></table>
<p>빌더 리스트는 <code>itemBuilder</code>가 index마다 위젯을 돌려준다. 화면에 안 보이면 만들지 않는다. 타일은 가볍게 둔다. 무거운 차트·큰 이미지를 행 안에 중첩하지 않는다.</p>
<p>상위 <code>setState</code>가 리스트 전체를 다시 돌리지 않게 행을 Stateless로 분리한다. 변하지 않는 서브트리는 <code>const</code>다.</p>
<p>네트워크 이미지는 크기와 캐시를 지정한다. 원본 해상도를 스크롤에 그대로 넣지 않는다.</p>

<p>이 필드를 리스트에서 순서를 바꾸면, 키가 없을 때 컨트롤러가 잘못된 행에 남는다. 각 행에 <code>ValueKey(label)</code> 또는 항목 id를 준다.</p>
<h3>스크롤 성능</h3>
<pre><code class="hljs language-dart"><span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">AvatarTile</span> <span class="hljs-keyword">extends</span> <span class="hljs-title">StatelessWidget</span> </span>{
  <span class="hljs-keyword">const</span> <span class="hljs-title class_">AvatarTile</span>({<span class="hljs-keyword">super</span>.key, <span class="hljs-keyword">required</span> <span class="hljs-keyword">this</span>.url, <span class="hljs-keyword">required</span> <span class="hljs-keyword">this</span>.title});

  <span class="hljs-keyword">final</span> <span class="hljs-title class_">String</span> url;
  <span class="hljs-keyword">final</span> <span class="hljs-title class_">String</span> title;

  <span class="hljs-meta">@override</span>
  <span class="hljs-title class_">Widget</span> <span class="hljs-title function_">build</span>(<span class="hljs-title class_">BuildContext</span> context) {
    <span class="hljs-keyword">return</span> <span class="hljs-title class_">ListTile</span>(
      leading: <span class="hljs-title class_">Image</span>.<span class="hljs-title function_">network</span>(
        url,
        width: <span class="hljs-number">40</span>,
        height: <span class="hljs-number">40</span>,
        fit: <span class="hljs-title class_">BoxFit</span>.cover,
        cacheWidth: <span class="hljs-number">80</span>,
      ),
      title: <span class="hljs-title class_">Text</span>(title, maxLines: <span class="hljs-number">1</span>, overflow: <span class="hljs-title class_">TextOverflow</span>.ellipsis),
    );
  }
}</code></pre>
<p><code>cacheWidth</code>는 디코드 크기를 제한한다. 디스플레이 픽셀을 고려해 논리 크기의 2배 정도가 흔하다.</p>
<p>고정 높이 행이면 <code>itemExtent</code>를 준다. 스크롤 오프셋 계산이 싸진다.</p>
<pre><code class="hljs language-dart"><span class="hljs-title class_">ListView</span>.<span class="hljs-title function_">builder</span>(
  itemExtent: <span class="hljs-number">56</span>,
  itemCount: items.length,
  itemBuilder: (<span class="hljs-title class_">BuildContext</span> context, <span class="hljs-built_in">int</span> index) {
    <span class="hljs-keyword">return</span> <span class="hljs-title class_">PostTile</span>(
      key: <span class="hljs-title class_">ValueKey</span>&lt;<span class="hljs-title class_">String</span>&gt;(items[index].id),
      post: items[index],
    );
  },
);</code></pre>
<p><code>RepaintBoundary</code>는 측정 후에 쓴다. 추측으로 모든 행에 씌우지 않는다. DevTools Performance와 rebuild 하이라이트로 먼저 본다.</p>

<p><code>Sliver</code>는 커스텀 스크롤(헤더 고정, 그리드 혼합)이 필요할 때 쓴다. 일반 목록은 <code>ListView.builder</code>로 시작한다.</p>

<h2>정리</h2>
<p>리스트 성능은 마법이 아니다. <strong>빌더 + 키 + 작은 타일</strong>의 합이다. 키는 자리 대신 정체성을 알려 주는 이름표다.</p>

<h2>연습</h2>
<ol>
<li>200개 항목을 <code>Column</code>과 <code>ListView.builder</code>로 각각 그려 스크롤을 비교한다.</li>
<li>입력 필드 리스트를 재배열하고, id 키 전후에 텍스트가 따라오는지 확인한다.</li>
<li>타일을 Stateless로 분리하고 <code>const</code> 생성자를 붙인다.</li>
<li>네트워크 이미지에 <code>width</code>/<code>height</code>/<code>cacheWidth</code>를 지정한다.</li>
