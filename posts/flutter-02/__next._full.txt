24:T2ba9,<h1>Stateless와 Stateful 위젯</h1>
<blockquote>
<p>요약: 화면은 위젯 트리이고, 기억할 값이 있으면 Stateful, 없으면 Stateless다.</p>
</blockquote>
<hr>
<h2>1. 왜 / 언제</h2>
<p>새 화면을 만들 때 먼저 고르는 것은 레이아웃이 아니다. <strong>이 위젯이 스스로 기억할 값이 있는가</strong>다.</p>
<p>탭 횟수, 입력 중인 글자, 애니메이션 진행도처럼 시간이 지나며 바뀌는 값이 있으면 Stateful이다. 제목 텍스트처럼 부모가 준 값만 보여 주면 Stateless다.</p>
<p>선택이 어긋나면 두 가지가 생긴다. 상태가 없는 화면을 Stateful로 만들거나, 전역 스토어에 버튼 하나 로딩을 올려 트리를 통째로 다시 그린다.</p>
<hr>
<h2>2. 핵심</h2>
<p>화면에 보이는 모든 것은 위젯이다. 위젯은 다른 위젯을 자식으로 담는다. 이렇게 이어진 구조를 <strong>위젯 트리</strong>라고 한다.</p>
<p>위젯은 도면에 가깝다. “이렇게 그려라”는 설명이다. Flutter는 이 설명을 자주 다시 만든다. 부모가 다시 그려지면 자식 위젯 객체도 새로 생길 수 있다.</p>
<p>실제 살아 있는 자리는 따로 있다.</p>
<table>
<thead>
<tr>
<th>층</th>
<th>역할</th>
</tr>
</thead>
<tbody><tr>
<td>Widget</td>
<td>UI 설명. 값처럼 자주 재생성된다.</td>
</tr>
<tr>
<td>Element</td>
<td>트리에 꽂힌 자리. 위젯과 State를 연결한다.</td>
</tr>
<tr>
<td>RenderObject</td>
<td>크기·위치·그리기.</td>
</tr>
</tbody></table>
<p>처음에는 위젯 트리만 이해해도 충분하다. 다만 <strong>변하는 값을 위젯 필드에 두면 리빌드 때 날아간다</strong>는 점만 기억한다. 그 값은 <code>State</code> 객체가 들고 있다.</p>
<p><code>StatelessWidget</code>은 <code>build</code>만 있다. 입력이 바뀌면 부모가 새 위젯을 내려 주고, 그때 다시 그린다.</p>
<p><code>StatefulWidget</code>은 위젯과 <code>State</code>가 한 쌍이다. 위젯은 설정값(생성자 파라미터)을 받는다. <code>State</code>가 가변 값을 들고 <code>setState</code>로 자기 <code>build</code>를 다시 돌린다.</p>
<p>키(<code>Key</code>)는 같은 타입 위젯이 여러 개일 때 자리를 구분하는 이름표다. 리스트에서 본격적으로 다룬다. 커스텀 위젯에는 <code>super.key</code>를 받는다.</p>
<hr>
<h2>3. 예제</h2>
<h3>Stateless — 주어진 값만 그린다</h3>
<pre><code class="hljs language-dart"><span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">TitleText</span> <span class="hljs-keyword">extends</span> <span class="hljs-title">StatelessWidget</span> </span>{
  <span class="hljs-keyword">const</span> <span class="hljs-title class_">TitleText</span>({<span class="hljs-keyword">super</span>.key, <span class="hljs-keyword">required</span> <span class="hljs-keyword">this</span>.text});

  <span class="hljs-keyword">final</span> <span class="hljs-title class_">String</span> text;

  <span class="hljs-meta">@override</span>
  <span class="hljs-title class_">Widget</span> <span class="hljs-title function_">build</span>(<span class="hljs-title class_">BuildContext</span> context) {
    <span class="hljs-keyword">return</span> <span class="hljs-title class_">Text</span>(text);
  }
}</code></pre>
<p><code>text</code>는 이 위젯이 만들지 않는다. 부모가 준다. 부모가 다른 <code>text</code>를 넘기면 새 <code>TitleText</code>가 만들어지고 <code>build</code>가 다시 돈다.</p>
<h3>Stateful — 이 위젯이 값을 기억한다</h3>
<pre><code class="hljs language-dart"><span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">Counter</span> <span class="hljs-keyword">extends</span> <span class="hljs-title">StatefulWidget</span> </span>{
  <span class="hljs-keyword">const</span> <span class="hljs-title class_">Counter</span>({<span class="hljs-keyword">super</span>.key, <span class="hljs-keyword">this</span>.step = <span class="hljs-number">1</span>});

  <span class="hljs-keyword">final</span> <span class="hljs-built_in">int</span> step;

  <span class="hljs-meta">@override</span>
  <span class="hljs-title class_">State</span>&lt;<span class="hljs-title class_">Counter</span>&gt; <span class="hljs-title function_">createState</span>() =&gt; <span class="hljs-title class_">_CounterState</span>();
}

<span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">_CounterState</span> <span class="hljs-keyword">extends</span> <span class="hljs-title">State</span>&lt;<span class="hljs-title">Counter</span>&gt; </span>{
  <span class="hljs-built_in">int</span> count = <span class="hljs-number">0</span>;

  <span class="hljs-keyword">void</span> <span class="hljs-title function_">_increment</span>() {
    <span class="hljs-title function_">setState</span>(() {
      count += widget.step;
    });
  }

  <span class="hljs-meta">@override</span>
  <span class="hljs-title class_">Widget</span> <span class="hljs-title function_">build</span>(<span class="hljs-title class_">BuildContext</span> context) {
    <span class="hljs-keyword">return</span> <span class="hljs-title class_">TextButton</span>(
      onPressed: _increment,
      child: <span class="hljs-title class_">Text</span>(<span class="hljs-string">&#x27;<span class="hljs-subst">$count</span>&#x27;</span>),
    );
  }
}</code></pre>
<p><code>widget.step</code>은 부모 설정값이다. <code>count</code>는 State가 기억한다. <code>setState</code>는 “값이 바뀌었으니 이 State의 <code>build</code>를 다시 돌려라”는 신호다. 앱 전체가 아니라 <strong>그 State 아래 서브트리</strong>가 다시 그려진다.</p>
<p>범위를 작게 유지한다. 화면 루트에서 <code>setState</code>하면 불필요한 위젯까지 다시 돈다.</p>

<p>컨트롤러를 <code>dispose</code>하지 않으면 화면을 떠나도 애니메이션이 남는다.</p>
<hr>
<h2>4. 흔한 실수</h2>
<table>
<thead>
<tr>
<th>실수</th>
<th>이유</th>
<th>대안</th>
</tr>
</thead>
<tbody><tr>
<td>모든 화면을 Stateful로 만든다</td>
<td>리빌드 범위가 커진다</td>
<td>상태가 있는 잎만 Stateful</td>
</tr>
<tr>
<td><code>build</code> 안에서 컨트롤러를 생성한다</td>
<td>리빌드마다 새 객체가 생긴다</td>
<td><code>initState</code>에서 만들고 <code>dispose</code></td>
</tr>
<tr>
<td><code>setState</code> 없이 필드를 바꾼다</td>
<td>화면이 안 바뀐다</td>
<td>값 변경은 <code>setState</code> 안에서</td>
</tr>
<tr>
<td>unmounted 뒤 <code>setState</code></td>
<td>비동기 콜백에서 예외</td>
<td><code>if (!mounted) return;</code></td>
</tr>
<tr>
<td>로그인·장바구니를 State에 둔다</td>
<td>화면이 바뀌면 값이 사라진다</td>
<td>공유 상태는 별도 계층</td>
</tr>
</tbody></table>
<p><code>const</code>를 붙일 수 있는 위젯은 붙인다. 부모가 다시 그려져도 입력이 같으면 그 서브트리는 재사용할 수 있다.</p>
<p>전역 상태는 이 글의 주제가 아니다. 이 위젯이 기억할 값만 Stateful로 둔다.</p>
<hr>
<h2>정리</h2>
<p>상태가 없으면 Stateless다. <strong>이 위젯이 기억할 값이 있으면 Stateful</strong>이다. 위젯은 도면이고, 기억은 <code>State</code>가 맡는다. 전역 값은 화면 State가 아니라 별도 계층으로 뺀다.</p>
<hr>
<h2>연습</h2>
<ol>
<li>제목만 받는 <code>TitleText</code>를 Stateless로 만든다.</li>
<li>같은 화면에 카운터를 Stateful로 두고 <code>setState</code> 범위를 카운터만으로 좁힌다.</li>
<li><code>AnimationController</code>를 <code>initState</code>에서 만들고 <code>dispose</code>에서 해제한다.</li>
<li>비동기 지연 뒤 <code>setState</code>하기 전에 <code>mounted</code>를 검사한다.</li>
</ol>
