24:T3997,<h1>Spring Security 6 — 인증·인가·OAuth2·JWT</h1>
<blockquote>
<p>요약: SecurityFilterChain으로 API 인증·인가를 구성하고, JWT와 OAuth2 Resource Server를 구분해서 쓴다.</p>
</blockquote>
<hr>
<h2>1. 왜 Security 6인가</h2>
<p><strong>인증(Authentication)</strong> 은 누구인지 확인하는 것이고, <strong>인가(Authorization)</strong> 는 그 주체가 이 요청을 해도 되는지 판단하는 것이다.</p>
<p>Security 6는 <code>WebSecurityConfigurerAdapter</code>를 없애고 <strong><code>SecurityFilterChain</code> Bean</strong>으로 체인을 선언한다. <code>antMatchers</code>는 <code>requestMatchers</code>로 바뀌었다. 메서드 보안은 <code>@EnableMethodSecurity</code>다.</p>
<p>JSON API는 세션 쿠키가 기본값이 아니다. CSRF·세션 정책을 API 기준으로 다시 정한다.</p>
<hr>
<h2>2. 세션 없는 API 골격</h2>
<p>한 줄 정의: <code>SecurityFilterChain</code>은 요청이 컨트롤러에 닿기 전 <strong>필터 순서와 허용 규칙</strong>을 조립하는 설정이다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Configuration</span>
<span class="hljs-meta">@EnableWebSecurity</span>
<span class="hljs-meta">@EnableMethodSecurity</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">SecurityConfig</span> {

    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">SecurityFilterChain</span> <span class="hljs-title function_">securityFilterChain</span><span class="hljs-params">(HttpSecurity http)</span> <span class="hljs-keyword">throws</span> Exception {
        http
            .csrf(csrf -&gt; csrf.disable())
            .sessionManagement(sm -&gt;
                sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -&gt; auth
                .requestMatchers(<span class="hljs-string">&quot;/actuator/health&quot;</span>, <span class="hljs-string">&quot;/api/auth/**&quot;</span>,
                        <span class="hljs-string">&quot;/v3/api-docs/**&quot;</span>, <span class="hljs-string">&quot;/swagger-ui/**&quot;</span>)
                    .permitAll()
                .requestMatchers(HttpMethod.GET, <span class="hljs-string">&quot;/api/posts/**&quot;</span>).permitAll()
                .anyRequest().authenticated()
            )
            .httpBasic(Customizer.withDefaults());

        <span class="hljs-keyword">return</span> http.build();
    }

    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">PasswordEncoder</span> <span class="hljs-title function_">passwordEncoder</span><span class="hljs-params">()</span> {
        <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">BCryptPasswordEncoder</span>();
    }
}</code></pre>
<p><strong>CSRF(Cross-Site Request Forgery)</strong> 는 브라우저가 쿠키를 자동으로 보낼 때 위조 요청을 막는 보호다. 쿠키 세션이 없으면 보통 끈다. 쿠키 기반 로그인 웹앱에서 끄면 구멍이 난다.</p>
<p>비밀번호는 <code>PasswordEncoder</code>로만 저장한다. <code>httpBasic</code>은 데모용이다.</p>
<hr>
<h2>3. UserDetailsService</h2>
<p>한 줄 정의: 로그인 식별자(이메일 등)로 <strong>사용자와 권한</strong>을 로드하는 포트다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">CustomUserDetailsService</span> <span class="hljs-keyword">implements</span> <span class="hljs-title class_">UserDetailsService</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> UserAccountRepository repository;

    <span class="hljs-type">public</span> <span class="hljs-title function_">CustomUserDetailsService</span><span class="hljs-params">(UserAccountRepository repository)</span> {
        <span class="hljs-built_in">this</span>.repository = repository;
    }

    <span class="hljs-meta">@Override</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">UserDetails</span> <span class="hljs-title function_">loadUserByUsername</span><span class="hljs-params">(String username)</span> <span class="hljs-keyword">throws</span> UsernameNotFoundException {
        <span class="hljs-type">UserAccount</span> <span class="hljs-variable">account</span> <span class="hljs-operator">=</span> repository.findByEmail(username)
                .orElseThrow(() -&gt; <span class="hljs-keyword">new</span> <span class="hljs-title class_">UsernameNotFoundException</span>(username));
        <span class="hljs-keyword">return</span> User.builder()
                .username(account.getEmail())
                .password(account.getPasswordHash())
                .roles(account.getRole().name())

    }

<p><code>.roles(...)</code>는 <code>ROLE_</code> 접두사를 붙인다. DB에 이미 <code>ROLE_USER</code>로 저장했다면 <code>.authorities(...)</code>를 쓴다.</p>
<hr>
<h2>4. JWT</h2>
<p>한 줄 정의: <strong>JWT(JSON Web Token)</strong> 는 서명된 JSON 클레임이다. 서버가 세션을 저장하지 않고, 클라이언트가 <code>Authorization: Bearer</code>로 보낸다.</p>
<p>흐름: <code>POST /api/auth/login</code> → access(+ refresh) → 필터가 검증 → <code>SecurityContext</code>에 <code>Authentication</code>.</p>
<pre><code class="hljs language-java"><span class="hljs-keyword">public</span> <span class="hljs-type">String</span> <span class="hljs-title function_">createAccessToken</span><span class="hljs-params">(String subject, Collection&lt;String&gt; roles)</span> {
    <span class="hljs-type">Instant</span> <span class="hljs-variable">now</span> <span class="hljs-operator">=</span> Instant.now();
    <span class="hljs-keyword">return</span> Jwts.builder()
            .subject(subject)
            .claim(<span class="hljs-string">&quot;roles&quot;</span>, roles)
            .issuedAt(Date.from(now))
            .expiration(Date.from(now.plus(<span class="hljs-number">15</span>, ChronoUnit.MINUTES)))
            .signWith(secretKey)
            .compact();
}</code></pre>
<p>Access는 5~15분, Refresh는 HttpOnly 쿠키 또는 안전한 저장소에 두고 회전한다. 서명 키는 환경변수다. 라이브러리는 <code>jjwt</code> 또는 <code>spring-security-oauth2-jose</code>(Nimbus)다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Component</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">JwtAuthFilter</span> <span class="hljs-keyword">extends</span> <span class="hljs-title class_">OncePerRequestFilter</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> JwtTokenProvider tokenProvider;

    <span class="hljs-type">public</span> <span class="hljs-title function_">JwtAuthFilter</span><span class="hljs-params">(JwtTokenProvider tokenProvider)</span> {
        <span class="hljs-built_in">this</span>.tokenProvider = tokenProvider;
    }

    <span class="hljs-meta">@Override</span>
    <span class="hljs-keyword">protected</span> <span class="hljs-type">void</span> <span class="hljs-title function_">doFilterInternal</span><span class="hljs-params">(HttpServletRequest request, HttpServletResponse response,
                                    FilterChain filterChain)</span> <span class="hljs-keyword">throws</span> ServletException, IOException {
        <span class="hljs-type">String</span> <span class="hljs-variable">token</span> <span class="hljs-operator">=</span> resolveBearer(request);
        <span class="hljs-keyword">if</span> (token != <span class="hljs-literal">null</span> &amp;&amp; tokenProvider.valid(token)) {
            <span class="hljs-type">Authentication</span> <span class="hljs-variable">auth</span> <span class="hljs-operator">=</span> tokenProvider.toAuthentication(token);
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        filterChain.doFilter(request, response);
    }
}</code></pre>
<p>필터는 <code>UsernamePasswordAuthenticationFilter</code> 앞에 넣는다. 만료·서명 실패를 삼키고 통과시키면 익명으로 보호 자원에 닿는다.</p>
<p>자체 파서보다 <strong>Authorization Server가 발급한 JWT를 Resource Server로 검증</strong>하는 편이 안전하다.</p>

<h2>5. 메서드 인가</h2>
<p>URL 매처만으로는 리소스 소유권을 표현하기 어렵다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@PreAuthorize(&quot;hasRole(&#x27;ADMIN&#x27;)&quot;)</span>
<span class="hljs-meta">@DeleteMapping(&quot;/{id}&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">delete</span><span class="hljs-params">(<span class="hljs-meta">@PathVariable</span> Long id)</span> { }

<p>소유권 검사는 서비스에서도 한 번 더 한다. 경로 변수만 믿으면 IDOR가 난다.</p>

<h2>6. OAuth2 Resource Server / Login</h2>
<p><strong>OAuth2 Resource Server</strong>는 Keycloak·Auth0·Cognito·Spring Authorization Server가 준 JWT를 표준으로 검증한다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">security:</span>
    <span class="hljs-attr">oauth2:</span>
      <span class="hljs-attr">resourceserver:</span>
        <span class="hljs-attr">jwt:</span>
          <span class="hljs-attr">issuer-uri:</span> <span class="hljs-string">https://auth.example.com/realms/demo</span></code></pre>
<pre><code class="hljs language-java">http.oauth2ResourceServer(oauth2 -&gt; oauth2.jwt(Customizer.withDefaults()));</code></pre>
<p>브라우저 소셜 로그인은 OAuth2 Login(클라이언트)이다. API 서버의 Bearer 검증과 역할이 다르다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">security:</span>
    <span class="hljs-attr">oauth2:</span>
      <span class="hljs-attr">client:</span>
        <span class="hljs-attr">registration:</span>
          <span class="hljs-attr">google:</span>
            <span class="hljs-attr">client-id:</span> <span class="hljs-string">${GOOGLE_CLIENT_ID}</span>
            <span class="hljs-attr">client-secret:</span> <span class="hljs-string">${GOOGLE_CLIENT_SECRET}</span>
            <span class="hljs-attr">scope:</span> <span class="hljs-string">openid,</span> <span class="hljs-string">profile,</span> <span class="hljs-string">email</span></code></pre>

<h2>7. CORS와 운영</h2>
<p>SPA가 다른 오리진이면 <code>CorsConfigurationSource</code>를 명시한다. <code>*</code> origin과 <code>allowCredentials</code>는 브라우저가 거부한다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Bean</span>
<span class="hljs-type">CorsConfigurationSource</span> <span class="hljs-title function_">corsConfigurationSource</span><span class="hljs-params">()</span> {
    <span class="hljs-type">CorsConfiguration</span> <span class="hljs-variable">config</span> <span class="hljs-operator">=</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">CorsConfiguration</span>();
    config.setAllowedOrigins(List.of(<span class="hljs-string">&quot;https://app.example.com&quot;</span>));
    config.setAllowedMethods(List.of(<span class="hljs-string">&quot;GET&quot;</span>, <span class="hljs-string">&quot;POST&quot;</span>, <span class="hljs-string">&quot;PUT&quot;</span>, <span class="hljs-string">&quot;PATCH&quot;</span>, <span class="hljs-string">&quot;DELETE&quot;</span>));
    config.setAllowedHeaders(List.of(<span class="hljs-string">&quot;*&quot;</span>));
    config.setAllowCredentials(<span class="hljs-literal">true</span>);
    <span class="hljs-type">UrlBasedCorsConfigurationSource</span> <span class="hljs-variable">source</span> <span class="hljs-operator">=</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">UrlBasedCorsConfigurationSource</span>();
    source.registerCorsConfiguration(<span class="hljs-string">&quot;/api/**&quot;</span>, config);
    <span class="hljs-keyword">return</span> source;
}</code></pre>
<p>Actuator는 <code>health</code> 외 노출을 줄이고 인증한다. 로그인에는 rate limit을 둔다.</p>
