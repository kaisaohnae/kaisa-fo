24:T392a,<h1>인증·보안 저장소·디바이스 권한</h1>
<blockquote>
<p>요약: 로그인 토큰은 SecureStore에 두고, 카메라·앨범·알림 권한은 필요할 때만 요청한다.</p>
</blockquote>
<hr>
<h2>1. 왜 지금 권한과 저장소를 나누나</h2>
<p>웹은 쿠키·httpOnly로 세션을 숨길 여지가 있다. 앱은 토큰을 기기에 둬야 자동 로그인이 된다. 일반 저장소에 넣으면 백업·루팅·로그에 노출되기 쉽다.</p>
<p><strong>SecureStore</strong>는 운영체제 보안 저장소에 작은 비밀 값을 넣는 Expo 모듈이다. iOS는 Keychain, Android는 Keystore 계열이다. access token처럼 짧은 비밀에 쓴다.</p>
<p>권한(카메라, 앨범, 알림)은 앱 시작 시 한꺼번에 묻지 않는다. <strong>쓰는 화면에서</strong> 이유를 말한 뒤 시스템 다이얼로그를 띄운다.</p>
<hr>
<h2>2. 핵심 개념</h2>

</tr>

</tr>
</tbody></table>
<p>세션은 Provider 한 곳이 소유한다. 시작 시 SecureStore에서 토큰을 읽고 <code>/me</code>로 복구한다. 실패하면 지운다.</p>
<p>생체 인증은 <strong>로컬 잠금</strong>이다. 서버 로그인을 대체하지 않는다. 지문 성공이 곧 API 인증은 아니다.</p>
<p>웹 타깃이면 SecureStore가 없다. <code>Platform</code> 분기 또는 쿠키 세션이 필요하다.</p>
<p>권한 거부 후에는 설정 앱으로 보내는 UI가 필요하다. 시스템 다이얼로그는 한 번 거절되면 다시 안 뜨는 경우가 많다.</p>

<h2>5. 정리</h2>
<p>인증은 <strong>토큰 위치 + 세션 복구 + 권한 시점</strong>이다. UI보다 이 세 가지가 먼저다.</p>
<ul>
<li>비밀은 SecureStore. 장바구니는 AsyncStorage도 된다.</li>
<li>스플래시가 끝날 때까지 가드를 보류한다.</li>
<li>권한 문구는 코드와 <code>app.json</code>에 같이 있다.</li>
</ul>

<li>이미지 피커 거절 시 설정 안내를 만든다.</li>
