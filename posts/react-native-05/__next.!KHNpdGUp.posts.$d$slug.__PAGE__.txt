3:T390b,<h1>네트워킹 — Fetch, React Query, 에러 처리</h1>
<blockquote>
<p>요약: 서버 데이터는 fetch 래퍼와 React Query로 가져와 로딩·에러·재시도를 표준화한다.</p>
</blockquote>
<hr>
<h2>1. 왜 React Query인가</h2>
<p>게시글 목록·프로필은 <strong>서버가 원본</strong>이다. 모달 열림·토글은 <strong>클라이언트가 원본</strong>이다.</p>
<p>서버 상태를 <code>useState</code> + <code>useEffect</code>로 따라가면 캐시, 재시도, 화면 복귀 시 갱신을 직접 짜게 된다. <strong>TanStack Query</strong>(React Query)가 그 층을 표준화한다.</p>
<p>앱에는 <code>fetch</code> 한 곳이 있으면 된다. 상태 코드, JSON, 토큰 헤더를 화면마다 반복하지 않는다.</p>
<hr>
<h2>2. 핵심 개념</h2>

</tr>
<tr>
<td>클라이언트 상태</td>

<p><code>queryKey</code>가 캐시 주소다. 같은 키면 같은 데이터다. mutation이 성공하면 관련 키를 <code>invalidate</code>한다.</p>
<p>Expo 환경변수는 <code>EXPO_PUBLIC_*</code>만 클라이언트에 노출된다. API 베이스 URL은 공개돼도 된다. 비밀키는 넣지 않는다.</p>
<p>RN은 브라우저 탭 포커스가 없다. 앱이 다시 <code>active</code>가 될 때 Query에 알려 주면 목록이 신선해진다.</p>
<p>401은 토큰 갱신 또는 로그아웃이다. 토큰 저장은 다음 글의 SecureStore다.</p>

<h2>5. 정리</h2>
<p>네트워크 층은 <strong>얇은 <code>api()</code> + Query 훅</strong>이면 된다. 화면은 pending/error/empty만 그린다.</p>
<ul>
<li>서버 상태와 UI 상태를 섞지 않는다.</li>
<li>토큰은 헤더로만. 저장 위치는 SecureStore.</li>
<li>무한 스크롤은 <code>useInfiniteQuery</code> + <code>onEndReached</code>.</li>
</ul>
<h2>연습</h2>
<ol>
<li><code>api()</code>와 <code>ApiError</code>를 만든다.</li>
<li>게시글 목록 <code>useQuery</code>에 로딩·에러 UI를 붙인다.</li>
<li>생성 <code>useMutation</code> 후 목록을 invalidate한다.</li>
<li><code>useInfiniteQuery</code>와 FlatList를 연결한다.</li>
</ol>
