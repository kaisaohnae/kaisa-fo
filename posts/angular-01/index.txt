24:T2b34,<h1>Angular 스탠드얼론으로 프로젝트 시작하기</h1>
<blockquote>
<p>요약: NgModule 없이 standalone 컴포넌트와 app.config로 Angular 앱을 띄우고, 폴더·부트스트랩 기본선을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 언제 Angular인가</h2>
<p>Angular는 라우팅·DI(의존성 주입)·폼·빌드를 <strong>한 프레임워크</strong>로 제공하는 쪽에 가깝다. 팀 규칙과 폴더 구조가 처음부터 정해져 있으면 규모가 커져도 같은 모양이 유지된다.</p>
<p>신규 기본선은 <strong>standalone API</strong>다. NgModule은 옛 앱·일부 라이브러리에서만 만난다.</p>
<table>
<thead>
<tr>
<th>항목</th>
<th>NgModule 시대</th>
<th>지금</th>
</tr>
</thead>
<tbody><tr>
<td>앱 시작</td>
<td><code>AppModule</code> + <code>bootstrapModule</code></td>
<td><code>bootstrapApplication</code></td>
</tr>
<tr>
<td>컴포넌트 등록</td>
<td>모듈 <code>declarations</code></td>
<td>컴포넌트 <code>standalone: true</code> + <code>imports</code></td>
</tr>
<tr>
<td>전역 설정</td>
<td>모듈 <code>providers</code></td>
<td><code>app.config.ts</code>의 <code>providers</code></td>
</tr>
</tbody></table>
<p>standalone 컴포넌트는 <strong>자기 파일에서 필요한 것을 <code>imports</code>로 가져오는 화면 조각</strong>이다. 모듈 파일이 없어도 템플릿에 <code>RouterLink</code> 등을 쓸 수 있다.</p>
<hr>
<h2>2. 핵심 구조</h2>
<pre><code class="hljs"><span class="hljs-attribute">src</span>/

<p>최신 CLI는 파일명이 <code>app.ts</code>인 경우가 많다. 구 템플릿은 <code>app.component.ts</code>다. 역할은 같다.</p>
<hr>
<h2>3. 생성</h2>
<pre><code class="hljs language-bash">npm install -g @angular/cli
ng new my-app --defaults
<span class="hljs-built_in">cd</span> my-app
ng serve</code></pre>
<p>최근 CLI는 standalone가 기본이다. <code>--standalone</code> 플래그는 버전에 따라 불필요하거나 폐기됐다. <code>ng new --help</code>로 확인한다.</p>
<p>권장: TypeScript strict, 라우팅 포함. CSS는 팀 취향이다.</p>

<p>루트는 셸이다. 본문은 <code>router-outlet</code>이 채운다. <code>Home</code>을 쓰려면 라우트에 등록한다. 루트 <code>imports</code>에 넣을 필요는 없다.</p>
<p><code>standalone: true</code>는 Angular 19+에서 기본값이라 생략할 수 있다. 이 시리즈는 의도를 드러내기 위해 적는다.</p>
<hr>
<h2>5. NgModule을 언제 보는가</h2>
<ul>
<li>옛 튜토리얼의 <code>NgModule</code> / <code>declarations</code></li>
<li>아직 모듈만 제공하는 서드파티</li>
<li>점진 이관 중인 대형 코드베이스</li>
</ul>
<p>신규 화면은 standalone로 만든다. 라이브러리가 모듈만 주면 그 모듈을 컴포넌트 <code>imports</code>에 넣는다. 앱 전체를 다시 <code>AppModule</code>로 묶지 않는다.</p>
<hr>
<h2>6. 주의 / 흔한 실수</h2>
<ul>
<li><strong><code>declarations</code>를 standalone 컴포넌트에 찾기.</strong> 그 배열은 NgModule 전용이다. 자식은 <code>imports</code>에 넣는다.</li>
<li><strong>루트에 모든 페이지를 <code>imports</code>.</strong> 라우트 <code>component</code> / <code>loadComponent</code>로 연결한다.</li>
<li><strong><code>main.ts</code>에서 <code>platformBrowserDynamic().bootstrapModule(AppModule)</code>.</strong> Vue의 <code>new Vue</code>와 같이 옛 진입점이다.</li>
<li><strong>기능 폴더 없이 <code>app/</code>에 파일만 쌓기.</strong> 화면이 늘면 import 순환이 생긴다.</li>
<li><strong>시크릿을 <code>environment.ts</code> 프론트 파일에 넣기.</strong> 브라우저 번들에 포함된다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>Angular 시작은 모듈 미로가 아니다. <strong>standalone 컴포넌트 + <code>bootstrapApplication</code> + <code>app.config.ts</code></strong> 세 점을 고정한다.</p>
<ul>
<li>화면 → <code>@Component({ standalone: true, imports: [...] })</code></li>
<li>전역 도구 → <code>providers</code> in <code>app.config.ts</code></li>
<li>URL → <code>app.routes.ts</code></li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li><code>ng new</code>로 앱을 만들고 <code>Home</code>에 이름 문자열을 바인딩해 브라우저에서 확인한다.</li>
<li><code>about.ts</code> standalone 컴포넌트를 추가하고 <code>path: &#39;about&#39;</code> 라우트를 연결한다.</li>
<li><code>app.config.ts</code>의 <code>providers</code> 목록을 읽고, 라우터가 어디서 등록되는지 한 줄로 적는다.</li>
</ol>
