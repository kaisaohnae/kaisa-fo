<blockquote>
<p>요약: Virtual Threads와 이벤트·메시지 큐를 용도에 맞게 고르고, 커밋 이후 발행과 Outbox로 유실을 줄인다.</p>

<h2>1. 왜 전부 리액티브가 아닌가</h2>
<p>요청-응답 CRUD는 동기 MVC로 충분한 경우가 많다. 팀 숙련도와 블로킹 라이브러리(JPA, JDBC)를 보고 고른다.</p>

<h2>2. Virtual Threads</h2>
<p>한 줄 정의: Java 21의 <strong>Virtual Thread</strong>는 OS 스레드에 1:1로 묶이지 않는 가벼운 스레드다. 블로킹 I/O 대기 중에도 캐리어 스레드를 오래 점유하지 않는다. Boot 3.2+에서 Tomcat 요청에 붙는다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">threads:</span>
    <span class="hljs-attr">virtual:</span>
      <span class="hljs-attr">enabled:</span> <span class="hljs-literal">true</span></code></pre>
<p>CPU 바운드에는 효과가 작다. Java 21에서 오래 잡는 <code>synchronized</code>는 캐리어 <strong>pinning</strong>이 난다. 스레드 로컬을 크게 쓰는 라이브러리는 확인한다. 가상 스레드를 켜도 <strong>Hikari 풀 크기</strong>가 DB 동시 접속의 천장이다.</p>
<hr>
<h2>3. <code>@Async</code></h2>
<p>같은 JVM 안에서 “조금 나중에” 실행할 때만 쓴다. 재시도·DLQ·순서 보장이 없고, 프로세스가 죽으면 작업이 사라진다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Configuration</span>
<span class="hljs-meta">@EnableAsync</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">AsyncConfig</span> {

    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">TaskExecutor</span> <span class="hljs-title function_">taskExecutor</span><span class="hljs-params">()</span> {
        <span class="hljs-keyword">return</span> task -&gt; Thread.startVirtualThread(task);
    }
}</code></pre>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">MailService</span> {
    <span class="hljs-meta">@Async</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">sendWelcome</span><span class="hljs-params">(String email)</span> {
        <span class="hljs-comment">// SMTP</span>
    }
}</code></pre>
<p>중요한 후처리는 브로커로 넘긴다.</p>
<hr>
<h2>4. 애플리케이션 이벤트</h2>
<p>같은 앱에서 결합을 낮출 때 쓴다. <strong><code>@TransactionalEventListener(AFTER_COMMIT)</code></strong> 이 핵심이다. 커밋 전에 메일을 보내면 롤백된 주문에 환영 메일이 간다.</p>
<pre><code class="hljs language-java"><span class="hljs-keyword">public</span> <span class="hljs-keyword">record</span> <span class="hljs-title class_">OrderCreatedEvent</span><span class="hljs-params">(Long orderId, String email)</span> {}

<span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">OrderService</span> {
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> ApplicationEventPublisher publisher;
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> OrderRepository repository;

    <span class="hljs-type">public</span> <span class="hljs-title function_">OrderService</span><span class="hljs-params">(ApplicationEventPublisher publisher, OrderRepository repository)</span> {
        <span class="hljs-built_in">this</span>.publisher = publisher;
        <span class="hljs-built_in">this</span>.repository = repository;
    }

    <span class="hljs-meta">@Transactional</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">OrderResponse</span> <span class="hljs-title function_">create</span><span class="hljs-params">(CreateOrderRequest request)</span> {
        <span class="hljs-type">Order</span> <span class="hljs-variable">order</span> <span class="hljs-operator">=</span> repository.save(Order.create(request));
        publisher.publishEvent(<span class="hljs-keyword">new</span> <span class="hljs-title class_">OrderCreatedEvent</span>(order.getId(), order.getEmail()));
        <span class="hljs-keyword">return</span> OrderResponse.from(order);
    }
}

<span class="hljs-meta">@Component</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">OrderCreatedListener</span> {
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> MailService mailService;

    <span class="hljs-type">public</span> <span class="hljs-title function_">OrderCreatedListener</span><span class="hljs-params">(MailService mailService)</span> {
        <span class="hljs-built_in">this</span>.mailService = mailService;
    }

    <span class="hljs-meta">@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">on</span><span class="hljs-params">(OrderCreatedEvent event)</span> {
        mailService.sendWelcome(event.email());
    }
}</code></pre>
<p>기본 이벤트는 발행 스레드에서 돈다. 완전 분리하려면 <code>@Async</code> 또는 큐다. AFTER_COMMIT 리스너 실패는 주문 트랜잭션을 되돌리지 않으므로, 실패를 로그·재시도 없이 삼키지 않는다.</p>
<hr>
<h2>5. Kafka와 Outbox</h2>
<p>Kafka는 <strong>이벤트 로그</strong>—재생·파티션 순서·다중 소비자에 강하다. 메일·썸네일·리포트처럼 “일감 하나”를 경쟁 소비자가 나눠 가지면 RabbitMQ(또는 SQS)가 더 단순하다. 교환기·라우팅 키로 구독 대상을 나누는 작업 큐에 맞다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">kafka:</span>
    <span class="hljs-attr">bootstrap-servers:</span> <span class="hljs-string">${KAFKA_BROKERS}</span>
    <span class="hljs-attr">consumer:</span>
      <span class="hljs-attr">group-id:</span> <span class="hljs-string">demo-service</span>
      <span class="hljs-attr">auto-offset-reset:</span> <span class="hljs-string">earliest</span>
    <span class="hljs-attr">producer:</span>
      <span class="hljs-attr">key-serializer:</span> <span class="hljs-string">org.apache.kafka.common.serialization.StringSerializer</span>
      <span class="hljs-attr">value-serializer:</span> <span class="hljs-string">org.springframework.kafka.support.serializer.JsonSerializer</span></code></pre>
<pre><code class="hljs language-java">kafkaTemplate.send(<span class="hljs-string">&quot;order.created&quot;</span>, event.orderId().toString(), event);

<span class="hljs-meta">@KafkaListener(topics = &quot;order.created&quot;, groupId = &quot;mail-service&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">consume</span><span class="hljs-params">(OrderCreatedEvent event)</span> {
    mailService.sendWelcome(event.email());
}</code></pre>
<p>소비자는 멱등해야 한다. 스키마는 호환 규칙을 정하고, 실패는 재시도 후 <strong>DLT(Dead Letter Topic)</strong> 로 보낸다. 파티션 키가 순서 보장 범위다.</p>
<p><strong>Outbox</strong>: DB 커밋 후 Kafka 전송이 실패하면 상태가 갈라진다. 같은 트랜잭션에 비즈니스 행과 <code>outbox</code> 행을 쓰고, 별도 퍼블리셔(또는 Debezium CDC)가 브로커로 보낸 뒤 처리 완료를 표시한다.</p>
<pre><code class="hljs language-sql"><span class="hljs-keyword">CREATE TABLE</span> outbox (
    id           BIGSERIAL <span class="hljs-keyword">PRIMARY KEY</span>,
    aggregate_id <span class="hljs-type">BIGINT</span> <span class="hljs-keyword">NOT NULL</span>,
    event_type   <span class="hljs-type">VARCHAR</span>(<span class="hljs-number">100</span>) <span class="hljs-keyword">NOT NULL</span>,
    payload      JSONB <span class="hljs-keyword">NOT NULL</span>,
    created_at   TIMESTAMPTZ <span class="hljs-keyword">NOT NULL</span>,
    published_at TIMESTAMPTZ
);</code></pre>
<p><code>published_at IS NULL</code>인 행만 폴링한다. 전송 성공과 마킹을 한 작업으로 두고, 중복 발행에 대비해 소비자는 멱등이어야 한다.</p>
<hr>
<h2>6. WebFlux를 보는 시점</h2>
<p>동시 연결이 매우 많고 다운스트림이 모두 non-blocking이거나, SSE/WebSocket이 핵심이면 검토한다. JDBC/JPA 중심이고 블로킹 라이브러리가 많으면 MVC + Virtual Threads가 보통 낫다.</p>
<p>HTTP 클라이언트는 connect/read timeout을 명시한다. 가상 스레드여도 무한 대기는 큐와 풀을 채운다. 카프카 리스너 처리 시간과 큐 적체를 메트릭으로 본다.</p>
