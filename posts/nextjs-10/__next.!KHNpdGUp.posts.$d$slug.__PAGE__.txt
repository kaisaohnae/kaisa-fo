3:T25bb,<h1>배포 — Vercel·정적 호스팅·체크리스트</h1>
<blockquote>
<p>요약: 서버가 있는 배포와 HTML만 올리는 배포를 고르고, 환경변수·SEO·롤백을 체크리스트로 통과시킨다.</p>
</blockquote>
<hr>
<h2>1. 왜 이 주제가 필요한가</h2>
<p>Next.js는 어디에 올리느냐가 아키텍처다. Vercel처럼 서버가 있으면 Server Action·미들웨어·ISR을 쓸 수 있다. GitHub Pages처럼 파일만 받으면 <code>output: &#39;export&#39;</code>로 HTML을 구워야 한다.</p>
<p>기능을 나중에 넣고 호스팅을 바꾸면 데이터 페칭·인증을 다시 짠다. 배포 형태를 먼저 고르고, 아래 목록으로 빠뜨린 항목을 막는다.</p>
<hr>
<h2>2. 한 줄 규칙</h2>
<p>서버가 필요한 기능이 하나라도 있으면 PaaS/Node에 올린다. 공개 문서만이면 정적 내보내기로 단순화한다.</p>
<p>시크릿은 <code>NEXT_PUBLIC_</code>을 붙이지 않는다. 사이트 URL은 환경변수 한곳으로 모은다.</p>
<hr>

<p>혼합도 가능하다. 공개 <code>/posts</code>는 정적 HTML, <code>/manager</code>만 서버 앱. 다만 두 배포 파이프라인을 유지할 비용이 있다.</p>
<h3>환경변수</h3>

<p>프리뷰와 프로덕션 URL을 나눈다. OG·sitemap이 프리뷰 도메인을 가리키면 검색·공유가 꼬인다.</p>
<pre><code class="hljs language-ts"><span class="hljs-comment">// lib/site.ts</span>
<span class="hljs-keyword">export</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">getSiteUrl</span>(<span class="hljs-params"></span>): <span class="hljs-built_in">string</span> {
  <span class="hljs-keyword">const</span> url = process.<span class="hljs-property">env</span>.<span class="hljs-property">NEXT_PUBLIC_SITE_URL</span>;
  <span class="hljs-keyword">if</span> (!url) <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">Error</span>(<span class="hljs-string">&#x27;NEXT_PUBLIC_SITE_URL이 없다&#x27;</span>);
  <span class="hljs-keyword">return</span> url.<span class="hljs-title function_">replace</span>(<span class="hljs-regexp">/\/$/</span>, <span class="hljs-string">&#x27;&#x27;</span>);
}</code></pre>
<p>빌드 때 없으면 실패하게 두면 잘못된 배포가 나가지 않는다.</p>
<h3>정적 내보내기 흐름</h3>
<pre><code class="hljs language-bash">npm run build
<span class="hljs-comment"># out/ 을 S3, GitHub Pages, Nginx 루트에 업로드</span></code></pre>
<pre><code class="hljs language-ts"><span class="hljs-comment">// next.config.ts</span>
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> {<span class="hljs-title class_">NextConfig</span>} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next&#x27;</span>;

<span class="hljs-keyword">const</span> <span class="hljs-attr">nextConfig</span>: <span class="hljs-title class_">NextConfig</span> = {
  <span class="hljs-attr">output</span>: <span class="hljs-string">&#x27;export&#x27;</span>,
  <span class="hljs-attr">trailingSlash</span>: <span class="hljs-literal">true</span>,
  <span class="hljs-attr">images</span>: {<span class="hljs-attr">unoptimized</span>: <span class="hljs-literal">true</span>},
};

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> nextConfig;</code></pre>
<ul>
<li><code>trailingSlash</code>와 CDN/Nginx 디렉터리 인덱스 규칙을 맞춘다. <code>/posts/hello</code>와 <code>/posts/hello/</code>가 둘 다 200이면 중복이다.</li>
<li>SPA처럼 <code>/* → index.html</code>만 두면 상세 HTML이 없다. SEO에는 <strong>경로별 HTML</strong>이 맞다.</li>
<li>커스텀 도메인 + HTTPS. <code>metadataBase</code>와 인증서를 같은 호스트로.</li>
</ul>
<h3>Vercel형 흐름</h3>
<p>Git 연동 후 프리뷰 URL로 각 PR을 본다. 프로덕션은 메인 브랜치.</p>
<p>서버 기능(Action, <code>revalidateTag</code>, 미들웨어)이 살아 있는지 프리뷰에서 폼·로그인까지 눌러 본다. 빌드만 통과한 배포는 반쪽이다.</p>
<hr>
<h2>4. 프로덕션 체크리스트</h2>
<p>각 항목은 빼면 검색이 빠지거나, 키가 새거나, 장애 때 되돌리지 못한다.</p>
<h3>SEO</h3>
<ul>
<li><input disabled="" type="checkbox"> 공개 글 URL이 빌드된 HTML에 제목·본문을 담는다 — 크롤러는 JS 실행 전에 본문을 찾는다</li>
<li><input disabled="" type="checkbox"> <code>sitemap.xml</code>과 <code>robots.txt</code>가 실제 공개 URL과 같다 — 빠진 주소는 색인이 늦다</li>
<li><input disabled="" type="checkbox"> canonical·OG <code>url</code>이 <code>NEXT_PUBLIC_SITE_URL</code> + trailing slash 규칙과 같다 — 중복 문서로 잡히지 않게</li>
<li><input disabled="" type="checkbox"> <code>/login</code>, <code>/manager</code>는 <code>noindex</code>(그리고 robots disallow) — 인증 화면이 검색에 나오지 않게</li>
<li><input disabled="" type="checkbox"> <code>&lt;html lang=&quot;ko&quot;&gt;</code> — 언어가 맞아야 검색·스크린 리더가 올바르다</li>
</ul>
<h3>신뢰성</h3>
<ul>
<li><input disabled="" type="checkbox"> 필수 환경변수가 없으면 빌드 또는 기동이 실패한다 — 빈 URL로 sitemap이 나가지 않게</li>
<li><input disabled="" type="checkbox"> <code>not-found</code> / <code>error</code> 페이지가 있다 — 없는 글과 서버 실패를 사용자가 구분한다</li>
<li><input disabled="" type="checkbox"> 이전 배포로 롤백하는 방법을 적었다 — Vercel이면 이전 Promotion, 정적이면 이전 <code>out/</code> 재업로드</li>
<li><input disabled="" type="checkbox"> 시크릿이 Git에 없다 — <code>.env*</code>는 gitignore, 플랫폼 환경변수만 사용</li>
<li><input disabled="" type="checkbox"> 관리자 API는 서버에서 세션을 다시 본다 — UI 숨김만으로는 부족하다</li>
</ul>
<h3>성능</h3>
<ul>
<li><input disabled="" type="checkbox"> 히어로는 <code>next/image</code>(또는 export면 리사이즈된 정적 파일) — LCP 후보 용량을 제한</li>
<li><input disabled="" type="checkbox"> 본문 폰트는 <code>next/font</code> — 외부 폰트 CSS로 CLS가 나지 않게</li>
<li><input disabled="" type="checkbox"> <code>next build</code>에서 이상하게 큰 라우트가 없다 — Client 경계를 다시 본다</li>
<li><input disabled="" type="checkbox"> CDN/캐시 헤더가 정적 자산에 있다 — HTML은 짧게, hashed JS/CSS는 길게</li>
</ul>
<h3>정적 내보내기만</h3>
<ul>
<li><input disabled="" type="checkbox"> Route Handler·미들웨어·ISR에 의존하지 않는다 — 런타임 서버가 없다</li>
<li><input disabled="" type="checkbox"> <code>images.unoptimized</code> 또는 커스텀 로더 — 최적화 서버가 없다</li>
<li><input disabled="" type="checkbox"> <code>generateStaticParams</code>가 공개 slug를 모두 반환한다 — 빠진 글은 <code>out/</code>에 파일이 없다</li>
</ul>
<hr>
<h2>5. CI 스케치</h2>
<ol>
<li>lint / typecheck / test — 타입·깨진 링크를 배포 전에 막는다</li>
<li><code>next build</code> — 정적/동적 라우트 표를 로그에서 확인한다</li>
<li>artifact 업로드 또는 Vercel 연동 — 산출물이 곧 롤백 단위다</li>
<li>스모크: <code>/</code>, <code>/posts/</code>, 대표 글 URL, (서버형이면) 로그인 실패 리다이렉트</li>
</ol>
<hr>
<h2>정리</h2>
<p>배포는 “이 앱이 서버를 필요로 하는가”에 대한 답이다. 그 답이 페칭·인증·이미지를 가른다.</p>
<p>공개 문서는 정적 HTML, 동적 관리자는 서버 또는 별도 API. 체크리스트를 통과/미통과로 남기면 다음 배포에서 같은 구멍을 반복하지 않는다.</p>
<hr>
<h2>연습</h2>
<ol>
<li>현재 프로젝트가 Vercel형인지 <code>export</code>형인지 한 줄로 적고, 그 이유에 쓰는 기능(Action, 미들웨어 등)을 적는다.</li>
<li><code>NEXT_PUBLIC_SITE_URL</code>이 sitemap·canonical·OG에만 쓰이는지 검색한다. 하드코딩 도메인을 제거한다.</li>
<li>위 체크리스트를 통과/미통과로 표시하고, 미통과 항목의 수정 이슈를 연다.</li>
</ol>
