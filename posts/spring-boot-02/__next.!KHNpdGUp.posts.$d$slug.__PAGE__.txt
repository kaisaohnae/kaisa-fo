3:T2ec2,<h1>IoC, Bean, Configuration — 의존성 주입</h1>
<blockquote>
<p>요약: IoC 컨테이너가 Bean을 조립하는 방식을 이해하고, 생성자 주입과 타입 세이프 설정으로 의존성을 구성한다.</p>
</blockquote>
<hr>
<h2>1. 왜 IoC인가</h2>
<p><strong>IoC(Inversion of Control)</strong> 는 객체 생성과 생명주기 제어권을 프레임워크가 갖는 것이다. <strong>DI(Dependency Injection)</strong> 는 그 구현 방식으로, 필요한 의존성을 외부에서 넣어 준다.</p>
<p>직접 <code>new</code>로 조립하면 테스트에서 구현을 바꾸기 어렵다. Spring은 <strong>Bean</strong>—컨테이너가 만들고 주입하는 객체—으로 그래프를 짠다.</p>
<hr>
<h2>2. Bean이 되는 방법</h2>
<p>직접 만든 클래스는 스테레오타입, 외부 라이브러리 객체는 <code>@Bean</code>이 기본이다.</p>
<table>
<thead>
<tr>
<th>방식</th>
<th>언제</th>
</tr>
</thead>
<tbody><tr>
<td><code>@Component</code> / <code>@Service</code> / <code>@Repository</code> / <code>@Controller</code></td>
<td>우리가 작성한 클래스</td>
</tr>
<tr>
<td><code>@Bean</code> + <code>@Configuration</code></td>
<td>생성 과정이 있거나 남이 만든 타입</td>
</tr>
<tr>
<td><code>@ConfigurationProperties</code></td>
<td>설정값을 타입으로 바인딩</td>
</tr>
<tr>
<td>Auto-configuration</td>
<td>starter가 조건에 맞으면 등록</td>
</tr>
</tbody></table>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">OrderService</span> {
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> OrderRepository orderRepository;
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> PaymentClient paymentClient;

    <span class="hljs-type">public</span> <span class="hljs-title function_">OrderService</span><span class="hljs-params">(OrderRepository orderRepository, PaymentClient paymentClient)</span> {
        <span class="hljs-built_in">this</span>.orderRepository = orderRepository;
        <span class="hljs-built_in">this</span>.paymentClient = paymentClient;
    }
}</code></pre>
<p>생성자가 하나면 <code>@Autowired</code>는 생략한다.</p>
<hr>
<h2>3. 주입 방식</h2>
<p>생성자 주입이 기본선이다. <code>final</code>로 불변이고, 순환 의존성은 기동 시점에 드러나며, 테스트에서 목을 넣기 쉽다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">UserService</span> {
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> UserRepository userRepository;

    <span class="hljs-type">public</span> <span class="hljs-title function_">UserService</span><span class="hljs-params">(UserRepository userRepository)</span> {
        <span class="hljs-built_in">this</span>.userRepository = userRepository;
    }
}</code></pre>
<p><code>@Autowired</code> 필드 주입은 테스트와 불변성이 약하다. Setter는 정말 선택적 의존성일 때만 쓴다.</p>
<hr>
<h2>4. <code>@Configuration</code>과 <code>@Bean</code></h2>
<p>한 줄 정의: 설정 클래스는 <strong>조립 공장</strong>이고, <code>@Bean</code> 메서드 반환값이 컨테이너에 등록된다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Configuration</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">AppConfig</span> {

    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">Clock</span> <span class="hljs-title function_">clock</span><span class="hljs-params">()</span> {
        <span class="hljs-keyword">return</span> Clock.systemUTC();
    }

    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">ObjectMapper</span> <span class="hljs-title function_">objectMapper</span><span class="hljs-params">()</span> {
        <span class="hljs-keyword">return</span> JsonMapper.builder()
                .addModule(<span class="hljs-keyword">new</span> <span class="hljs-title class_">JavaTimeModule</span>())
                .disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS)
                .build();
    }
}</code></pre>
<p>기본 <code>@Configuration</code>은 CGLIB 프록시로 <code>@Bean</code> 메서드 간 호출을 싱글톤으로 맞춘다. <code>@Bean</code>끼리 서로 호출하지 않으면 <code>@Configuration(proxyBeanMethods = false)</code>(Lite)가 기동에 유리하다.</p>
<hr>
<h2>5. 스코프</h2>
<table>
<thead>
<tr>
<th>Scope</th>
<th>의미</th>
</tr>
</thead>
<tbody><tr>
<td><code>singleton</code> (기본)</td>
<td>컨테이너당 하나</td>
</tr>
<tr>
<td><code>prototype</code></td>
<td>조회마다 새 인스턴스</td>
</tr>
<tr>
<td><code>request</code> / <code>session</code></td>
<td>HTTP 요청·세션당 하나</td>
</tr>
</tbody></table>
<p>서비스·리포지토리는 거의 항상 singleton이다. <strong>요청 상태를 필드로 두지 않는다.</strong> 두면 스레드끼리 데이터가 섞인다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Bean</span>
<span class="hljs-meta">@Scope(&quot;prototype&quot;)</span>
<span class="hljs-type">ReportBuilder</span> <span class="hljs-title function_">reportBuilder</span><span class="hljs-params">()</span> {
    <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">ReportBuilder</span>();
}</code></pre>
<hr>
<h2>6. 조건부 Bean</h2>
<p>환경마다 구현을 바꾸려면 조건 어노테이션을 쓴다. 로컬에서만 가짜 클라이언트를 쓰는 전형적인 패턴이다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Bean</span>
<span class="hljs-meta">@ConditionalOnProperty(name = &quot;app.mail.enabled&quot;, havingValue = &quot;true&quot;)</span>
<span class="hljs-type">MailSender</span> <span class="hljs-title function_">mailSender</span><span class="hljs-params">(MailProperties props)</span> {
    <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">SmtpMailSender</span>(props);
}

<span class="hljs-meta">@Bean</span>
<span class="hljs-meta">@ConditionalOnMissingBean(MailSender.class)</span>
<span class="hljs-type">MailSender</span> <span class="hljs-title function_">noopMailSender</span><span class="hljs-params">()</span> {
    <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">NoopMailSender</span>();
}</code></pre>
<p><code>@Profile(&quot;!prod&quot;)</code>, <code>@ConditionalOnClass</code>, <code>@ConditionalOnWebApplication</code>도 같은 계열이다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-meta">@Profile(&quot;!prod&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">FakePaymentClient</span> <span class="hljs-keyword">implements</span> <span class="hljs-title class_">PaymentClient</span> { }</code></pre>
<hr>
<h2>7. <code>@ConfigurationProperties</code></h2>
<p>URL·타임아웃을 코드에 쓰지 않는다. Boot 3에서는 <strong>record + <code>@ConfigurationProperties</code></strong> 가 맞다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@ConfigurationProperties(prefix = &quot;app.payment&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">record</span> <span class="hljs-title class_">PaymentProperties</span><span class="hljs-params">(
        String baseUrl,
        Duration timeout,
        <span class="hljs-type">int</span> maxRetries
)</span> {}</code></pre>
<pre><code class="hljs language-yaml"><span class="hljs-attr">app:</span>
  <span class="hljs-attr">payment:</span>
    <span class="hljs-attr">base-url:</span> <span class="hljs-string">https://pay.example.com</span>
    <span class="hljs-attr">timeout:</span> <span class="hljs-string">3s</span>
    <span class="hljs-attr">max-retries:</span> <span class="hljs-number">2</span></code></pre>
<pre><code class="hljs language-java"><span class="hljs-meta">@Configuration</span>
<span class="hljs-meta">@EnableConfigurationProperties(PaymentProperties.class)</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">PaymentConfig</span> {

    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">PaymentClient</span> <span class="hljs-title function_">paymentClient</span><span class="hljs-params">(PaymentProperties props, RestClient.Builder builder)</span> {
        <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">HttpPaymentClient</span>(builder.baseUrl(props.baseUrl()).build(), props);
    }
}</code></pre>
<p>IDE 자동완성은 <code>spring-boot-configuration-processor</code>를 annotation processor로 넣으면 된다.</p>
<hr>
<h2>8. 포트로 의존성 끊기</h2>
<p>구현체가 아니라 <strong>인터페이스(포트)</strong> 에 의존하면 테스트에서 구현만 바꾸면 된다.</p>
<pre><code class="hljs language-java"><span class="hljs-keyword">public</span> <span class="hljs-keyword">interface</span> <span class="hljs-title class_">NotificationPort</span> {
    <span class="hljs-type">void</span> <span class="hljs-title function_">send</span><span class="hljs-params">(String to, String message)</span>;
}

<span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">EmailNotificationAdapter</span> <span class="hljs-keyword">implements</span> <span class="hljs-title class_">NotificationPort</span> { }</code></pre>
<hr>
<h2>9. 순환 의존성과 생명주기</h2>
<p>Boot 3는 순환 참조를 기본적으로 허용하지 않는다. 공통 로직을 제3 서비스로 빼거나 <code>ApplicationEventPublisher</code>로 결합을 낮춘다. <code>@Lazy</code>는 최후 수단이다.</p>
<p>기동·종료 훅은 <code>@PostConstruct</code> / <code>@PreDestroy</code> 또는 <code>@Bean(initMethod, destroyMethod)</code>다. 파일·스레드 풀처럼 닫을 자원이 있으면 destroy를 빠뜨리지 않는다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Bean(initMethod = &quot;start&quot;, destroyMethod = &quot;stop&quot;)</span>
<span class="hljs-type">MyWorker</span> <span class="hljs-title function_">myWorker</span><span class="hljs-params">()</span> {
    <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">MyWorker</span>();
}</code></pre>
