24:T5e7b,<h1>Spring Boot 실무 디자인 패턴 — 자주 쓰는 핵심 패턴 7가지</h1>
<blockquote>
<p>요약: 전략, 템플릿 콜백, 프록시, 어댑터, 옵저버 등 스프링 내부 원리와 실무 비즈니스 코드에 녹아 있는 디자인 패턴을 쉽게 풀어본다.</p>
</blockquote>
<hr>
<h2>1. 디자인 패턴, 왜 알아야 할까?</h2>
<p>디자인 패턴은 과거의 뛰어난 개발자들이 수많은 삽질 끝에 발견한 <strong>&quot;자주 발생하는 소프트웨어 설계 문제의 모범 정답지(Best Practice)&quot;</strong> 다.</p>
<p>특히 <strong>Spring Framework는 디자인 패턴의 거대한 집약체</strong>다.</p>
<ul>
<li>스프링이 왜 이렇게 만들어졌는지 내부 원리를 쉽게 이해할 수 있다.</li>
<li>지저분한 <code>if-else</code> 분기와 강한 결합도를 없애고 깔끔하고 유지보수하기 쉬운 코드를 짤 수 있다.</li>
</ul>
<p>실무에서 가장 유용하게 쓰이는 7가지 핵심 패턴을 비유와 실제 코드로 살펴보자.</p>
<hr>
<h2>2. 싱글톤 패턴 (Singleton Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>사무실에 100명의 직원이 있다고 해서 <strong>프린터를 100대 살 필요는 없다</strong>. 1대만 두고 모두가 공유해서 쓰는 것이 자원과 비용 면에서 효율적이다.</p>
<h3>스프링에서의 싱글톤</h3>
<p>스프링의 <code>@Service</code>, <code>@Repository</code>, <code>@Component</code> 등 모든 Bean은 기본적으로 <strong>단 1개만 생성되어 모든 요청 스레드가 공유하는 싱글톤(Singleton)</strong> 으로 관리된다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">UserService</span> {
    <span class="hljs-comment">// 스프링 컨테이너가 애플리케이션 실행 시 딱 1개의 인스턴스만 생성하여 관리함</span>
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> UserRepository userRepository;

    <span class="hljs-type">public</span> <span class="hljs-title function_">UserService</span><span class="hljs-params">(UserRepository userRepository)</span> {
        <span class="hljs-built_in">this</span>.userRepository = userRepository;
    }
}</code></pre>
<h3>⚠️ 실무 주의점: 상태를 가지면 안 된다 (Stateless)</h3>
<p>싱글톤 객체는 여러 사용자(스레드)가 동시에 사용한다. 따라서 <strong>인스턴스 변수에 특정 사용자의 상태나 데이터를 저장하면 다른 사용자의 데이터와 섞이는 치명적인 동시성 버그가 발생</strong>한다.</p>
<pre><code class="hljs language-java"><span class="hljs-comment">// [절대 금지: 상태를 필드에 저장]</span>
<span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">BadOrderService</span> {
    <span class="hljs-keyword">private</span> String currentUsername; <span class="hljs-comment">// 동시 요청 시 다른 사람의 이름으로 덮어씌워짐!</span>

    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">order</span><span class="hljs-params">(String username)</span> {
        <span class="hljs-built_in">this</span>.currentUsername = username;
        <span class="hljs-comment">// ...</span>
    }
}

<span class="hljs-comment">// [올바른 방법: 지역 변수나 파라미터 사용]</span>
<span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">GoodOrderService</span> {
    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">order</span><span class="hljs-params">(String username)</span> {
        <span class="hljs-comment">// 메서드 내부 로컬 변수로 안전하게 처리 (스레드별 독립 메모리 사용)</span>
    }
}</code></pre>
<hr>
<h2>3. 전략 패턴 (Strategy Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>우리가 네비게이션 앱을 쓸 때 목적지는 같지만 <strong>길 찾기 전략</strong>을 바꿀 수 있다:</p>
<ul>
<li>&#39;최소 시간 경로&#39;</li>
<li>&#39;무료 도로 우선&#39;</li>
<li>&#39;최단 거리 경로&#39;</li>
</ul>
<p>상황에 따라 다른 알고리즘을 부품(전략)처럼 갈아 끼울 수 있도록 만드는 패턴이다.</p>
<h3>실무 예제: 다중 결제 수단 처리 (<code>if-else</code> 없애기)</h3>
<p>카카오페이, 토스페이, 네이버페이 등 결제 수단이 늘어날 때 <code>switch-case</code>나 <code>if-else</code>로 도배하는 대신 전략 패턴을 쓰면 코드가 매우 깔끔해진다.</p>
<h4>1) 공통 전략 인터페이스 정의</h4>
<pre><code class="hljs language-java"><span class="hljs-keyword">public</span> <span class="hljs-keyword">interface</span> <span class="hljs-title class_">PaymentStrategy</span> {

    <span class="hljs-type">void</span> <span class="hljs-title function_">pay</span><span class="hljs-params">(<span class="hljs-type">int</span> amount)</span>;

    <span class="hljs-keyword">public</span> <span class="hljs-type">String</span> <span class="hljs-title function_">getPaymentCode</span><span class="hljs-params">()</span> { <span class="hljs-keyword">return</span> <span class="hljs-string">&quot;TOSS&quot;</span>; }

    <span class="hljs-meta">@Override</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">pay</span><span class="hljs-params">(<span class="hljs-type">int</span> amount)</span> {
        System.out.println(<span class="hljs-string">&quot;토스페이로 &quot;</span> + amount + <span class="hljs-string">&quot;원 결제 API 호출&quot;</span>);
    }
}</code></pre>
<h4>3) 스프링의 마법: 모든 전략을 Map/List로 한 번에 주입받기</h4>
<p>스프링은 동일한 인터페이스를 구현한 모든 빈을 <code>List</code>나 <code>Map</code>으로 한꺼번에 주입해 주는 기능을 기본 제공한다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">PaymentService</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> Map&lt;String, PaymentStrategy&gt; strategyMap;

    <span class="hljs-comment">// 스프링이 모든 PaymentStrategy 빈들을 찾아서 리스트로 꽂아줌</span>
    <span class="hljs-type">public</span> <span class="hljs-title function_">PaymentService</span><span class="hljs-params">(List&lt;PaymentStrategy&gt; strategies)</span> {
        <span class="hljs-built_in">this</span>.strategyMap = strategies.stream()
                .collect(Collectors.toMap(PaymentStrategy::getPaymentCode, s -&gt; s));
    }

    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">processPayment</span><span class="hljs-params">(String paymentCode, <span class="hljs-type">int</span> amount)</span> {
        <span class="hljs-type">PaymentStrategy</span> <span class="hljs-variable">strategy</span> <span class="hljs-operator">=</span> strategyMap.get(paymentCode);
        <span class="hljs-keyword">if</span> (strategy == <span class="hljs-literal">null</span>) {
            <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">IllegalArgumentException</span>(<span class="hljs-string">&quot;지원하지 않는 결제 수단: &quot;</span> + paymentCode);
        }
        
        <span class="hljs-comment">// if-else 없이 런타임에 알맞은 전략 실행!</span>
        strategy.pay(amount);
    }
}</code></pre>
<blockquote>
<p><strong>장점</strong>: 나중에 <code>NaverPayStrategy</code>가 추가되어도 <code>PaymentService</code> 코드는 1줄도 수정할 필요가 없다(<strong>개방-폐쇄 원칙, OCP 달성</strong>).</p>
</blockquote>

<h2>4. 템플릿 콜백 패턴 (Template Callback Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>라면 끓이기의 전체 흐름(물 끓이기 ➔ 라면/스프 넣기 ➔ 익히기)은 정해져 있지만, <strong>&#39;중간에 넣는 토핑(계란, 치즈, 떡)&#39;만 사용자가 원하는 대로 자유롭게 바꾸는 방식</strong>이다.</p>
<h3>스프링에서의 템플릿 콜백</h3>
<ul>
<li>매번 반복되는 번거로운 작업(DB 연결 열기, 트랜잭션 시작, 예외 처리, 연결 닫기)은 <strong>스프링 템플릿</strong>이 알아서 해준다.</li>
<li>개발자는 <strong>진짜 하고 싶은 비즈니스 람다(콜백 함수)</strong> 만 넘기면 된다.</li>
</ul>
<p>대표적인 예가 <code>TransactionTemplate</code>, <code>JdbcTemplate</code>, <code>RedisTemplate</code>이다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-meta">@RequiredArgsConstructor</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">CouponService</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> TransactionTemplate transactionTemplate;
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> CouponRepository couponRepository;

    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">issueCouponWithManualTransaction</span><span class="hljs-params">(Long couponId)</span> {
        <span class="hljs-comment">// [템플릿]: 트랜잭션 시작, 커밋, 롤백, 자원 반납 처리 자동화</span>
        <span class="hljs-comment">// [콜백(람다)]: 내가 수행할 핵심 쿠폰 발급 로직만 쏙 집어넣음</span>
        transactionTemplate.execute(status -&gt; {
            <span class="hljs-type">Coupon</span> <span class="hljs-variable">coupon</span> <span class="hljs-operator">=</span> couponRepository.findById(couponId).orElseThrow();
            coupon.decreaseStock();
            <span class="hljs-keyword">return</span> couponRepository.save(coupon);
        });
    }
}</code></pre>

<h2>5. 프록시 &amp; 데코레이터 패턴 (Proxy &amp; Decorator Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>비서가 사장님(원본 객체)을 대신하여:</p>
<ul>
<li>사장님이 바쁠 때 약속을 조율하고(접근 제어 ➔ <strong>프록시 패턴</strong>)</li>
<li>사장님이 말한 내용을 예쁜 보고서 양식으로 포장해 준다(부가 기능 덧붙이기 ➔ <strong>데코레이터 패턴</strong>)</li>
</ul>
<h3>스프링에서의 활용: <code>@Transactional</code></h3>
<p>우리가 서비스 메서드 위에 <code>@Transactional</code>을 달면, 스프링은 프록시(비서) 객체를 만든다.</p>
<pre><code class="hljs">[호출자<span class="hljs-punctuation">(</span>Controller<span class="hljs-punctuation">)</span>] 
        │
        ▼
[Service 프록시 객체 <span class="hljs-punctuation">(</span>비서<span class="hljs-punctuation">)</span>] ───▶ <span class="hljs-punctuation">(</span><span class="hljs-number">1</span><span class="hljs-punctuation">)</span> 트랜잭션 시작 <span class="hljs-punctuation">(</span>Begin Transaction<span class="hljs-punctuation">)</span>
        │
        ├────────────────────────▶ <span class="hljs-punctuation">(</span><span class="hljs-number">2</span><span class="hljs-punctuation">)</span> 실제 Service 메서드 실행
        │
        ▼
[Service 프록시 객체 <span class="hljs-punctuation">(</span>비서<span class="hljs-punctuation">)</span>] ───▶ <span class="hljs-punctuation">(</span><span class="hljs-number">3</span><span class="hljs-punctuation">)</span> 성공 시 Commit / 예외 시 Rollback</code></pre>
<p>비즈니스 코드에 <code>connection.setAutoCommit(false)</code> 같은 코드를 직접 쓰지 않아도 트랜잭션이 돌아가는 이유가 바로 이 프록시 패턴 덕분이다.</p>

<h2>6. 어댑터 패턴 (Adapter Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>해외여행 갈 때 110V 콘센트에 220V 플러그를 꽂으려면 <strong>돼지코 변환기(어댑터)</strong> 가 필요하다. 인터페이스 규격이 맞지 않는 두 객체를 이어주는 중간 다리 역할을 한다.</p>
<h3>실무 예제: 외부 SMS 알림 업체 연동</h3>
<p>우리 시스템은 <code>NotificationSender</code> 인터페이스를 표준으로 쓰는데, 외부 SMS 유료 라이브러리(<code>CoolSmsSdk</code>)의 메서드 이름과 파라미터가 완전히 다를 때 어댑터를 사용한다.</p>
<pre><code class="hljs language-java"><span class="hljs-comment">// 1. 우리 시스템 표준 인터페이스</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">interface</span> <span class="hljs-title class_">NotificationSender</span> {
    <span class="hljs-type">void</span> <span class="hljs-title function_">sendNotification</span><span class="hljs-params">(String target, String message)</span>;
}

<span class="hljs-comment">// 2. 외부 업체 라이브러리 (직접 수정 불가능한 클래스)</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">ExternalSmsClient</span> {
    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">transmit</span><span class="hljs-params">(String phoneNumber, String bodyText, String authKey)</span> {
        <span class="hljs-comment">// 타사 SMS 전송 로직</span>
    }
}

<span class="hljs-comment">// 3. 둘을 연결해 주는 어댑터 클래스</span>
<span class="hljs-meta">@Component</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">SmsAdapter</span> <span class="hljs-keyword">implements</span> <span class="hljs-title class_">NotificationSender</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> <span class="hljs-type">ExternalSmsClient</span> <span class="hljs-variable">externalClient</span> <span class="hljs-operator">=</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">ExternalSmsClient</span>();

<p>나중에 SMS 업체를 다른 곳으로 바꾸더라도 비즈니스 로직은 손대지 않고 <code>Adapter</code> 클래스만 새로 만들면 된다.</p>

<h2>7. 옵저버 / 이벤트 발행-구독 패턴 (Observer Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>유튜브 채널을 <strong>구독(Subscribe)</strong> 해 두면, 크리에이터가 새 영상을 <strong>발행(Publish)</strong> 했을 때 구독자들에게 자동으로 알림이 가는 구조다.</p>
<h3>실무 예제: 회원 가입 후 메일 발송 + 쿠폰 지급</h3>
<p>회원 가입 메서드 안에서 이메일 전송, 슬랙 알림, 가입 축하 쿠폰 지급을 전부 직접 호출하면 코드가 복잡해지고, 메일 서버가 다운되었을 때 회원 가입까지 실패하게 된다.</p>
<p>이를 <strong>이벤트(옵저버) 패턴</strong>으로 분리하면 결합도를 깔끔하게 끊을 수 있다.</p>
<h4>1) 이벤트 DTO (Record)</h4>
<pre><code class="hljs language-java"><span class="hljs-keyword">public</span> <span class="hljs-keyword">record</span> <span class="hljs-title class_">UserSignedUpEvent</span><span class="hljs-params">(Long userId, String email, String name)</span> {}</code></pre>
<h4>2) 이벤트 발행자 (Publisher)</h4>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-meta">@RequiredArgsConstructor</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">UserService</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> UserRepository userRepository;
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> ApplicationEventPublisher eventPublisher; <span class="hljs-comment">// 스프링 기본 이벤트 발행기</span>

    <span class="hljs-meta">@Transactional</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">Long</span> <span class="hljs-title function_">signUp</span><span class="hljs-params">(SignUpRequest request)</span> {
        <span class="hljs-type">User</span> <span class="hljs-variable">user</span> <span class="hljs-operator">=</span> userRepository.save(<span class="hljs-keyword">new</span> <span class="hljs-title class_">User</span>(request));

        <span class="hljs-comment">// &quot;회원 가입 완료됨!&quot;이라는 이벤트만 세상에 알리고 끝냄</span>

    }
}</code></pre>
<h4>3) 이벤트 구독자 (Listeners)</h4>

<h2>8. 빌더 패턴 (Builder Pattern)</h2>
<h3>쉽게 이해하기</h3>
<p>생성자에 파라미터가 7~8개씩 있으면 어떤 값이 나이이고 어떤 값이 전화번호인지 헷갈려서 인자 순서를 잘못 넣는 실수를 하기 쉽다. 빌더 패턴은 <strong>각 파라미터에 이름을 붙여서 명확하고 안전하게 객체를 조립</strong>할 수 있게 해준다.</p>
<pre><code class="hljs language-java"><span class="hljs-comment">// [생성자의 위험성: 순서 헷갈림]</span>
<span class="hljs-keyword">new</span> <span class="hljs-title class_">UserDto</span>(<span class="hljs-string">&quot;홍길동&quot;</span>, <span class="hljs-string">&quot;010-1234-5678&quot;</span>, <span class="hljs-string">&quot;hong@test.com&quot;</span>, <span class="hljs-number">25</span>, <span class="hljs-literal">true</span>);

        .age(<span class="hljs-number">25</span>)
        .isVerified(<span class="hljs-literal">true</span>)
        .build();</code></pre>

<h2>연습</h2>
<ol>
<li><code>DiscountPolicy</code> 인터페이스를 만들고, 정액 할인(<code>1000원 할인</code>)과 정률 할인(<code>10% 할인</code>) 전략을 구현한 뒤 주문 금액에 따라 전략을 적용해 본다.</li>
