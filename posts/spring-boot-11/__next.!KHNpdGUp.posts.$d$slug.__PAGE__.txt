<blockquote>
<p>요약: 공통 관심사(로깅, 트랜잭션 등)를 핵심 로직에서 분리하는 AOP의 원리와 실무 프록시 동작 방식을 친절하게 정리한다.</p>

<h2>1. AOP란 무엇인가? (쉬운 비유로 시작하기)</h2>
<p>식당에서 주문을 받고 요리하는 상황을 떠올려 보자.</p>
<ul>
<li><strong>주방장의 본업(핵심 로직)</strong>: 주문받은 요리 맛있게 만들기 (주문 생성, 결제 승인, 회원 가입 등)</li>
<li><strong>공통 부가 작업(횡단 관심사)</strong>:<ul>
<li>주방에 들어갈 때 손 소독하기 (인증/권한 검사)</li>
<li>요리 시작 시간과 끝난 시간 기록하기 (성능 측정 / 로깅)</li>
<li>재료가 상했으면 작업 취소하고 폐기하기 (트랜잭션 롤백 / 예외 처리)</li>
</ul>
</li>
</ul>
<p>만약 100가지 메뉴를 만들 때마다 주방장이 일일이 손 소독 코드를 넣고, 스톱워치를 켜고 끄는 코드를 모든 요리 메서드에 직접 적는다면 어떻게 될까?</p>
<pre><code class="hljs language-java"><span class="hljs-comment">// AOP 없이 작성한 비즈니스 코드의 비극</span>
<span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">orderMenu</span><span class="hljs-params">(OrderRequest req)</span> {
    <span class="hljs-comment">// 1. 공통 부가 작업: 권한 검사</span>
    authService.checkAdmin();
    <span class="hljs-comment">// 2. 공통 부가 작업: 시간 측정 시작</span>
    <span class="hljs-type">long</span> <span class="hljs-variable">start</span> <span class="hljs-operator">=</span> System.currentTimeMillis();

    <span class="hljs-keyword">try</span> {
        <span class="hljs-comment">// === [진짜 하고 싶었던 핵심 비즈니스 로직 2줄] ===</span>
        <span class="hljs-type">Order</span> <span class="hljs-variable">order</span> <span class="hljs-operator">=</span> orderRepository.save(<span class="hljs-keyword">new</span> <span class="hljs-title class_">Order</span>(req));
        paymentGateway.pay(order);
        <span class="hljs-comment">// ============================================</span>
    } <span class="hljs-keyword">catch</span> (Exception e) {
        <span class="hljs-comment">// 3. 공통 부가 작업: 에러 로깅 &amp; 알림</span>
        slackNotifier.sendError(e);
        <span class="hljs-keyword">throw</span> e;
    } <span class="hljs-keyword">finally</span> {
        <span class="hljs-comment">// 4. 공통 부가 작업: 실행 시간 로깅</span>
        <span class="hljs-type">long</span> <span class="hljs-variable">end</span> <span class="hljs-operator">=</span> System.currentTimeMillis();
        log.info(<span class="hljs-string">&quot;orderMenu 실행 시간: {}ms&quot;</span>, (end - start));
    }
}</code></pre>
<p>진짜 중요한 <strong>주문과 결제 로직은 2줄</strong>뿐인데, 부가 작업 코드가 앞뒤를 덮어버린다. 게다가 이런 메서드가 100개라면 시간 측정 방식을 바꿀 때 100개 메서드를 전부 수정해야 한다.</p>
<p>이 문제를 해결하기 위해 등장한 것이 바로 <strong>AOP(Aspect-Oriented Programming, 관점 지향 프로그래밍)</strong> 다. 부가 기능(횡단 관심사)을 한곳으로 쏙 뽑아내어 모듈화하고, 핵심 비즈니스 로직은 본연의 역할에만 집중하게 만든다.</p>

<h2>3. 스프링 AOP의 비밀: &#39;프록시(Proxy)&#39;란?</h2>
<p>스프링 AOP는 마법이 아니다. <strong>대리인(Proxy) 객체</strong>를 중간에 세워서 작동한다.</p>
<p>우리가 <code>@Autowired OrderService orderService</code>로 주입받는 객체는 실제 <code>OrderService</code>가 아니라, 스프링이 감싸서 만든 <strong>가짜 껍데기(Proxy 객체)</strong> 다.</p>
<pre><code class="hljs">[클라이언트<span class="hljs-punctuation">(</span>Controller<span class="hljs-punctuation">)</span>] 
       │ 
       ▼ <span class="hljs-punctuation">(</span><span class="hljs-number">1</span><span class="hljs-punctuation">)</span> orderService.order<span class="hljs-punctuation">(</span><span class="hljs-punctuation">)</span> 호출
[OrderService 프록시 <span class="hljs-punctuation">(</span>가짜 객체<span class="hljs-punctuation">)</span>] 
       │  ├─▶ [시간 측정 시작!] <span class="hljs-punctuation">(</span>Advice 실행<span class="hljs-punctuation">)</span>
       │  ▼ <span class="hljs-punctuation">(</span><span class="hljs-number">2</span><span class="hljs-punctuation">)</span> 진짜 메서드 실행 위임
[OrderService 원본 <span class="hljs-punctuation">(</span>진짜 타깃 객체<span class="hljs-punctuation">)</span>] 
       │  ├─▶ 핵심 주문 로직 실행
       │  ▼ <span class="hljs-punctuation">(</span><span class="hljs-number">3</span><span class="hljs-punctuation">)</span> 결과 반환
[OrderService 프록시 <span class="hljs-punctuation">(</span>가짜 객체<span class="hljs-punctuation">)</span>] 
       │  ├─▶ [시간 측정 종료 &amp; 로그 출력!] <span class="hljs-punctuation">(</span>Advice 실행<span class="hljs-punctuation">)</span>
       ▼ <span class="hljs-punctuation">(</span><span class="hljs-number">4</span><span class="hljs-punctuation">)</span> 최종 반환
[클라이언트<span class="hljs-punctuation">(</span>Controller<span class="hljs-punctuation">)</span>]</code></pre>
<h3>프록시 생성 방식 (CGLIB)</h3>
<p>Spring Boot는 기본적으로 <strong>CGLIB</strong>라는 바이트코드 조작 기술을 사용한다. 타깃 클래스를 상속받아 자식 클래스 프록시를 만들기 때문에, 인터페이스가 없어도 일반 클래스에 AOP를 바로 적용할 수 있다.</p>

<h2>5. 실전 예제: 내 손으로 직접 만드는 <code>@MeasureTime</code> (시간 측정 AOP)</h2>
<p>실무에서 가장 유용하게 쓰이는 <strong>커스텀 어노테이션 기반 시간 측정 AOP</strong>를 단계별로 만들어 보자.</p>
<h3>Step 1. 커스텀 어노테이션 만들기</h3>
<p>메서드 위에 붙일 스티커 같은 어노테이션을 정의한다.</p>
<pre><code class="hljs language-java"><span class="hljs-keyword">package</span> com.example.annotation;

<span class="hljs-keyword">import</span> java.lang.annotation.ElementType;
<span class="hljs-keyword">import</span> java.lang.annotation.Retention;
<span class="hljs-keyword">import</span> java.lang.annotation.RetentionPolicy;
<span class="hljs-keyword">import</span> java.lang.annotation.Target;

<span class="hljs-meta">@Target(ElementType.METHOD)</span> <span class="hljs-comment">// 메서드에 붙이겠다고 선언</span>
<span class="hljs-meta">@Retention(RetentionPolicy.RUNTIME)</span> <span class="hljs-comment">// 런타임까지 유지</span>
<span class="hljs-keyword">public</span> <span class="hljs-meta">@interface</span> MeasureTime {
    <span class="hljs-type">String</span> <span class="hljs-title function_">value</span><span class="hljs-params">()</span> <span class="hljs-keyword">default</span> <span class="hljs-string">&quot;&quot;</span>; <span class="hljs-comment">// 작업 이름 (옵션)</span>
}</code></pre>
<h3>Step 2. Aspect(부가기능 처리기) 만들기</h3>
<pre><code class="hljs language-java"><span class="hljs-keyword">package</span> com.example.aop;

<span class="hljs-keyword">import</span> com.example.annotation.MeasureTime;
<span class="hljs-keyword">import</span> lombok.extern.slf4j.Slf4j;
<span class="hljs-keyword">import</span> org.aspectj.lang.ProceedingJoinPoint;
<span class="hljs-keyword">import</span> org.aspectj.lang.annotation.Around;
<span class="hljs-keyword">import</span> org.aspectj.lang.annotation.Aspect;
<span class="hljs-keyword">import</span> org.springframework.stereotype.Component;

<span class="hljs-meta">@Slf4j</span>
<span class="hljs-meta">@Aspect</span>      <span class="hljs-comment">// 1. AOP 설정 클래스임을 명시</span>
<span class="hljs-meta">@Component</span>   <span class="hljs-comment">// 2. 스프링 빈으로 등록</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">ExecutionTimeAspect</span> {

    <span class="hljs-comment">// @MeasureTime 어노테이션이 붙은 메서드 전후(@Around)에 이 로직을 끼워넣음</span>

    <span class="hljs-keyword">public</span> <span class="hljs-type">Object</span> <span class="hljs-title function_">measureExecutionTime</span><span class="hljs-params">(ProceedingJoinPoint joinPoint, MeasureTime measureTime)</span> <span class="hljs-keyword">throws</span> Throwable {
        <span class="hljs-type">String</span> <span class="hljs-variable">taskName</span> <span class="hljs-operator">=</span> measureTime.value().isBlank() 
                ? joinPoint.getSignature().toShortString() 
                : measureTime.value();

        <span class="hljs-type">long</span> <span class="hljs-variable">startTime</span> <span class="hljs-operator">=</span> System.currentTimeMillis();
        log.info(<span class="hljs-string">&quot;[시작] {}&quot;</span>, taskName);

        <span class="hljs-keyword">try</span> {
            <span class="hljs-comment">// 진짜 타깃 메서드를 실행하는 핵심 코드!</span>
            <span class="hljs-type">Object</span> <span class="hljs-variable">result</span> <span class="hljs-operator">=</span> joinPoint.proceed();
            <span class="hljs-keyword">return</span> result;
        } <span class="hljs-keyword">finally</span> {
            <span class="hljs-type">long</span> <span class="hljs-variable">totalTime</span> <span class="hljs-operator">=</span> System.currentTimeMillis() - startTime;
            <span class="hljs-keyword">if</span> (totalTime &gt; <span class="hljs-number">1000</span>) {
                log.warn(<span class="hljs-string">&quot;[경고: 느린 작업] {} 완료! 소요시간: {}ms&quot;</span>, taskName, totalTime);
            } <span class="hljs-keyword">else</span> {
                log.info(<span class="hljs-string">&quot;[완료] {} 완료! 소요시간: {}ms&quot;</span>, taskName, totalTime);
            }
        }
    }
}</code></pre>

<h2>6. 실무 주의사항: 내부 호출(Self-Invocation)의 덫</h2>
<p>AOP를 처음 쓸 때 가장 많이 겪는 미스터리한 버그가 바로 <strong>같은 클래스 내부 호출 문제</strong>다.</p>
<h3>왜 내부 호출은 AOP가 안 먹힐까?</h3>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">OrderService</span> {

    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">createOrder</span><span class="hljs-params">()</span> {
        System.out.println(<span class="hljs-string">&quot;1. 주문 생성 로직&quot;</span>);
        
        <span class="hljs-comment">// 같은 클래스 안의 메서드를 호출함 (this.sendEmail())</span>
        <span class="hljs-built_in">this</span>.sendEmail(); 
    }

    <span class="hljs-meta">@MeasureTime(&quot;이메일 발송 시간 측정&quot;)</span> <span class="hljs-comment">// &lt;- 동작하지 않음!</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">sendEmail</span><span class="hljs-params">()</span> {
        System.out.println(<span class="hljs-string">&quot;2. 이메일 발송 로직&quot;</span>);
    }
}</code></pre>
<p><strong>이유:</strong>
외부(<code>Controller</code>)에서 <code>createOrder()</code>를 호출할 때는 <strong>프록시(대리인)</strong> 를 거친다. 하지만 <code>createOrder()</code> 내부에서 <code>sendEmail()</code>을 부를 때는 프록시가 아니라 <strong>자기 자신(<code>this</code>)의 원본 메서드를 직접 호출</strong>해 버리기 때문에 AOP 부가기능이 완전히 무시된다.</p>
<pre><code class="hljs">[외부 호출] ──▶ [<span class="hljs-title class_">OrderService</span> <span class="hljs-title class_">Proxy</span>] ──▶ [<span class="hljs-title class_">OrderService</span> 원본: <span class="hljs-title function_">createOrder</span>()]
                                                     │
                                            (<span class="hljs-keyword">this</span>.sendEmail 직접 호출)
                                                     ▼
                                          [<span class="hljs-title class_">OrderService</span> 원본: <span class="hljs-title function_">sendEmail</span>()] 
                                          ※ <span class="hljs-title class_">Proxy</span>를 거치지 않아 AOP 동작 안 함!</code></pre>
<h3>해결책: 가장 깔끔한 방법은 &#39;클래스 분리&#39;</h3>
<p>역할에 맞게 메일 발송 로직을 별도의 <code>NotificationService</code> 클래스로 분리하고 주입받아 호출하면 자연스럽게 프록시를 거치게 된다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-meta">@RequiredArgsConstructor</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">OrderService</span> {
    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> NotificationService notificationService; <span class="hljs-comment">// 별도 빈 주입</span>

    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">createOrder</span><span class="hljs-params">()</span> {
        System.out.println(<span class="hljs-string">&quot;1. 주문 생성&quot;</span>);
        notificationService.sendEmail(); <span class="hljs-comment">// 프록시를 통해 호출되므로 AOP 정상 작동!</span>
    }
}</code></pre>
<hr>
<h2>7. 핵심 요약 및 팁</h2>
<ol>
<li><strong>AOP는 횡단 관심사(로깅, 트랜잭션, 보안 등)를 깔끔하게 분리</strong>해 주는 기술이다.</li>
<li>스프링은 <strong>프록시(대리 객체)</strong> 를 통해 타깃 메서드 앞뒤에 Advice를 끼워 넣는다.</li>
<li>실무에서는 복잡한 Pointcut 표현식보다 <strong>커스텀 어노테이션(<code>@annotation</code>)</strong> 을 만들어 필요한 곳에 명시적으로 붙이는 방식이 훨씬 안전하다.</li>
<li><code>private</code> 메서드나 같은 클래스 내부 호출(<code>this.method()</code>)은 프록시를 거치지 않으므로 AOP가 적용되지 않는다.</li>
</ol>
<hr>
<h2>연습</h2>
<ol>
<li>Controller 메서드 진입 시 요청 파라미터를 예쁘게 출력해 주는 <code>@RequestLog</code> AOP를 구현해 본다.</li>
<li>실행 중 예외가 발생하면 콘솔에 에러 메시지와 함께 실행 메서드명을 출력하는 <code>@AfterThrowing</code> Advice를 작성해 본다.</li>
</ol>
