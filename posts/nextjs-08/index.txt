24:T3302,<h1>미들웨어와 인증 경계</h1>
<blockquote>
<p>요약: 요청이 페이지에 닿기 전에 경로를 가리고, 실제 권한은 서버 레이아웃에서 다시 확인한다.</p>
</blockquote>
<hr>
<h2>1. 왜 이 주제가 필요한가</h2>
<p>관리자 URL을 아는 사람만 막아도 부족하다. 주소가 열리기 전에 한 번 거르고, 페이지·API에서 세션을 다시 본다.</p>
<p><strong>미들웨어</strong>는 요청이 라우트 핸들러·페이지에 들어가기 전, 네트워크 경계에서 돌아가는 함수다. 리다이렉트·헤더·매처로 경로를 가른다. DB를 깊게 조회하는 자리가 아니다.</p>
<p>인증 정보(세션 쿠키 vs 토큰)를 어디에 둘지가 XSS·CSRF 표면을 가른다.</p>
<hr>
<h2>2. 한 줄 규칙</h2>
<p>미들웨어는 거친 차단(로그인 여부, 경로 prefix)만 한다. 역할·권한은 서버 레이아웃이나 Route Handler에서 다시 검사한다.</p>
<p>토큰은 HttpOnly 쿠키가 기본선이다. <code>localStorage</code>에 액세스 토큰만 두면 XSS에 그대로 노출된다.</p>
<hr>
<h2>3. 예제</h2>
<h3>middleware.ts (Next.js 15)</h3>
<p>프로젝트 루트 또는 <code>src/middleware.ts</code>다. <code>app/</code> 안이 아니다.</p>

<p>쿠키 존재만 본다. 서명 검증·DB 조회는 레이아웃으로 미룬다. 만료된 쿠키를 들고 온 사용자는 미들웨어를 통과한 뒤 레이아웃에서 <code>redirect</code>된다.</p>
<p>Next.js 16은 같은 역할을 <code>proxy.ts</code>로 옮기는 방향이다. 파일 이름과 런타임 기본값이 다를 수 있다. “경로를 가르는 네트워크 경계”라는 역할은 같다. 프로젝트 버전의 파일명을 확인한다.</p>

<p>관리자 API도 같은 <code>getSession</code>을 탄다. UI만 숨기고 API가 열려 있으면 의미가 없다.</p>

<h3>정적 내보내기와의 관계</h3>
<p><code>output: &#39;export&#39;</code>면 미들웨어·서버 세션이 제한되거나 없다.</p>
<p>그때의 선택:</p>
<ul>
<li>관리자만 서버가 있는 호스팅으로 분리</li>
<li>공개 글은 정적 HTML, 이슈·관리자는 별도 API + Client 가드</li>
</ul>
<p>Client 가드만 있으면 소스에 화면이 남아 있다. API가 401/403을 내야 데이터가 막힌다. UI 숨김은 편의일 뿐 보안이 아니다.</p>
<p>로그인·회원가입 페이지는 <code>robots: {index: false}</code>로 색인에서 뺀다.</p>

<h2>정리</h2>
<p>미들웨어는 문을 닫는 역할이다. 열쇠가 맞는지(서명·역할)는 서버 컴포넌트와 API가 본다.</p>
<p>공개 페이지는 정적 HTML, 관리자는 서버 또는 별도 API. 이 경계를 호스팅 선택과 같이 적는다.</p>
