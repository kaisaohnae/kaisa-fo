23:T2d88,<h1>MongoDB: 문서형 DB로 유연한 스키마 다루기</h1>
<blockquote>
<p>요약: 문서 단위로 읽고 쓰는 워크로드에 맞는 문서형 DB로, 임베드·인덱스·레플리카의 실무 경계를 정리한다.</p>
</blockquote>
<hr>
<h2>1. 언제 MongoDB인가</h2>
<p>MongoDB는 문서형(NoSQL) 데이터베이스다. 행이 아니라 <strong>JSON과 비슷한 문서</strong> 한 장을 기본 단위로 저장한다. 내부 저장은 BSON이다. BSON은 Binary JSON, JSON을 이진으로 확장한 형식이다.</p>
<p>“SQL이 싫어서”만으로 고르면 나중에 조인·일관성에서 비용이 커진다. <strong>함께 읽는 데이터가 한 문서에 모이는지</strong>가 선택 기준이다.</p>
<table>
<thead>
<tr>
<th>맞는 경우</th>
<th>덜 맞는 경우</th>
</tr>
</thead>
<tbody><tr>
<td>상품·게시글처럼 문서 구조가 자주 변할 때</td>
<td>주문·재고처럼 강한 조인·정규화가 핵심일 때</td>
</tr>
<tr>
<td>한 화면이 문서 하나면 충분할 때</td>
<td>여러 컬렉션을 매번 조인해야 할 때</td>
</tr>
<tr>
<td>수평 확장·샤딩을 전제로 키를 설계할 때</td>

<td>리포팅 SQL·제약 엔진이 필요할 때 (PostgreSQL/MySQL)</td>
</tr>
</tbody></table>
<p>유연함은 무기이자 부채다. 필드 이름이 문서마다 달라지면 조회·인덱스가 무너진다.</p>
<hr>
<h2>2. 핵심 개념</h2>
<p><strong>데이터베이스 → 컬렉션 → 문서.</strong> 컬렉션은 테이블에 가깝다. 문서에는 <code>_id</code>가 있다. 기본값은 ObjectId다.</p>
<p><strong>임베드 vs 참조.</strong> 자주 함께 읽는 작은 객체는 문서 안에 넣는다(임베드). 커지거나 수명주기가 다르면 <code>ObjectId</code>로 가리킨다(참조). 배열이 끝없이 늘어나면 문서 16MB 상한과 갱신 비용이 문제가 된다.</p>
<p><strong>단일 문서 갱신은 원자적</strong>이다. 한 문서 안의 여러 필드는 같이 커밋된다. 여러 문서에 걸친 트랜잭션은 가능하다. 다만 비용·제약이 있다. 관계형처럼 쓰려고 멀티 도큐먼트 트랜잭션을 남발하면 이득이 사라진다.</p>
<p><strong>레플리카 셋</strong>이 운영 기본이다. Primary에 쓰고 Secondary가 복제한다. 노드 하나짜리 단독 프로세스는 개발용으로만 둔다.</p>
<p><strong>스키마 검증(Schema Validation)</strong> 으로 “아무 필드나”를 완화한다. 완전 자유는 운영에서 디버깅 비용이 된다.</p>
<p><strong>TTL 인덱스</strong>는 Time To Live, 만료 후 삭제다. 세션·임시 문서에 쓴다. 캐시 전용이면 Redis가 더 단순한 경우가 많다.</p>
<p><strong>샤딩</strong>은 데이터를 여러 샤드에 나누는 기법이다. 샤드 키를 잘못 고르면 한 샤드에만 쓰기가 몰린다. 트래픽이 한 노드로 충분하면 샤딩을 미룬다. 레플리카로 읽기·가용성을 먼저 확보한다.</p>
<hr>

<p><code>IXSCAN</code>이 아니라 <code>COLLSCAN</code>이면 인덱스가 안 탄다. 쿼리 패턴이 바뀌면 인덱스도 다시 짠다. 인덱스는 쓰기 비용을 올린다. “나중에 쓸지도”로 만들지 않는다.</p>
<p>연결 문자열은 시크릿이다. 예시는 플레이스홀더만 쓴다.</p>
<pre><code class="hljs"><span class="hljs-symbol">mongodb:</span><span class="hljs-comment">//APP_USER:YOUR_DB_PASSWORD@db.internal:27017/app?authSource=admin</span></code></pre>
<hr>
<h2>4. 운영 시 주의</h2>
<p><strong>연결.</strong> 드라이버 풀 기본값을 앱 인스턴스 수와 곱해 본다. 유휴 연결이 너무 길면 방화벽이 끊는다. <code>retryWrites</code>와 타임아웃을 드라이버 문서대로 맞춘다.</p>
<p><strong>백업.</strong> Atlas 같은 관리형은 스냅샷·PITR을 상품으로 제공한다. PITR은 Point-In-Time Recovery다. 직접 운영이면 레플리카 + 주기 스냅샷을 최소로 둔다. <code>mongodump</code>는 논리 백업이다. 큰 클러스터에서는 시간과 부하를 계산한다. 복원을 스테이징에서 한 번 돌린다.</p>
<p><strong>보안.</strong> 인증을 켠다. 앱 사용자는 해당 DB만. 27017을 인터넷에 열지 않는다. VPC 또는 프라이빗 링크 안쪽에서만 붙는다.</p>
<p><strong>스키마 드리프트.</strong> 필드명 오타가 조용히 새 필드를 만든다. 검증 규칙이나 앱 DTO로 허용 필드를 고정한다.</p>
<p><strong>핫 도큐먼트.</strong> 한 문서의 배열에 댓글을 수만 개 붙이면 갱신이 싸워진다. 커지는 관계는 컬렉션을 나눈다.</p>
<p><strong>비용.</strong> Atlas 등 관리형은 클러스터 티어·스토리지·백업이 요금이다. 인덱스와 불필요 필드가 문서를 키운다. 프로젝션으로 큰 필드를 목록 조회에서 뺀다.</p>
<p><strong>관측.</strong> 프로파일러 또는 Atlas 슬로우 쿼리로 <code>COLLSCAN</code>을 찾는다. 커넥션 수와 replication lag를 대시보드에 둔다.</p>
<p>스키마 검증은 “완전 자유”를 한 단계 줄인다.</p>
<pre><code class="hljs language-js">db.<span class="hljs-title function_">createCollection</span>(<span class="hljs-string">&quot;posts&quot;</span>, {
  <span class="hljs-attr">validator</span>: {
    <span class="hljs-attr">$jsonSchema</span>: {
      <span class="hljs-attr">bsonType</span>: <span class="hljs-string">&quot;object&quot;</span>,
      <span class="hljs-attr">required</span>: [<span class="hljs-string">&quot;title&quot;</span>, <span class="hljs-string">&quot;createdAt&quot;</span>],
      <span class="hljs-attr">properties</span>: {
        <span class="hljs-attr">title</span>: { <span class="hljs-attr">bsonType</span>: <span class="hljs-string">&quot;string&quot;</span>, <span class="hljs-attr">minLength</span>: <span class="hljs-number">1</span> },
        <span class="hljs-attr">published</span>: { <span class="hljs-attr">bsonType</span>: <span class="hljs-string">&quot;bool&quot;</span> }
      }
    }
  }
})</code></pre>
<p>규칙은 느슨하게 시작해도 된다. 필수 필드만이라도 막으면 오타 필드가 줄어든다.</p>
<p><strong>흔한 실수.</strong> 댓글 배열을 글 문서에 무한히 붙이기, 인덱스 없이 <code>regex</code> 전체 스캔, 멀티 도큐먼트 트랜잭션으로 관계형을 흉내 내기. 세 가지가 운영 비용을 키운다.</p>
<hr>
<h2>5. 정리</h2>
<p>MongoDB는 유연함이 무기다. <strong>읽기 패턴에 맞는 문서 설계와 인덱스</strong> 없이 쓰면 관계형보다 더 아프다. 임베드는 작게, 트랜잭션은 드물게, 레플리카와 백업은 기본값으로 둔다.</p>
<h3>체크리스트</h3>
<ul>
<li><input disabled="" type="checkbox"> 화면 단위로 임베드/참조를 정한다. 조인을 전제로 시작하면 모델이 무너진다.</li>
<li><input disabled="" type="checkbox"> 실제 <code>find</code>/<code>sort</code>에 인덱스를 맞춘다. <code>explain</code>이 COLLSCAN이면 데이터가 커질수록 죽는다.</li>
<li><input disabled="" type="checkbox"> 레플리카 셋을 운영 기본으로 둔다. 단일 노드는 디스크 장애에 약하다.</li>
<li><input disabled="" type="checkbox"> 스키마 검증 또는 앱 계약으로 필드 난립을 막는다.</li>
<li><input disabled="" type="checkbox"> 인증·네트워크 범위를 최소로 두고 덤프/스냅샷 복원을 연습한다.</li>
</ul>

<li>같은 쿼리에 <code>explain(&quot;executionStats&quot;)</code>를 붙여 스캔 방식을 확인한다.</li>
<li><code>mongodump</code> 후 다른 DB 이름에 복원해 건수가 같은지 본다.</li>
