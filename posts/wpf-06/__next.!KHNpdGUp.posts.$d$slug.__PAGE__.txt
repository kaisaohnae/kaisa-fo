3:T186d,<h1>WPF 앱 실무 체크리스트</h1>
<blockquote>
<p>요약: MVVM 경계·성능·예외·배포·UX까지, WPF 앱을 내보내기 전에 항목마다 이유를 붙여 확인하는 실무 체크리스트다.</p>
</blockquote>
<hr>
<h2>1. 아키텍처</h2>
<ul>
<li><input disabled="" type="checkbox"> ViewModel이 <code>Window</code>/<code>MessageBox</code>/<code>OpenFileDialog</code>를 직접 호출하지 않는다 — UI 타입이 섞이면 테스트를 위해 창을 띄워야 한다.</li>
<li><input disabled="" type="checkbox"> 액션은 <code>ICommand</code>/<code>[RelayCommand]</code>로 노출한다 — 코드비하인드 <code>Click</code>에 저장이 있으면 책임이 뷰에 붙는다.</li>
<li><input disabled="" type="checkbox"> 대화상자·파일·설정은 서비스 인터페이스로 감싼다 — 구현만 갈아끼우면 CI에서 확인/취소를 시뮬레이션할 수 있다.</li>
<li><input disabled="" type="checkbox"> <code>Views</code> / <code>ViewModels</code> / <code>Services</code> / <code>Models</code> 폴더를 일관되게 쓴다 — 창 코드에 도메인 로직이 쌓이면 찾기 어렵다.</li>
<li><input disabled="" type="checkbox"> DataContext는 화면당 하나의 ViewModel을 루트로 둔다 — 컨트롤마다 다른 소스를 수동 대입하면 바인딩 오류를 못 본다.</li>
</ul>
<hr>
<h2>2. 바인딩·상태</h2>
<ul>
<li><input disabled="" type="checkbox"> 속성 변경에 <code>INotifyPropertyChanged</code> 또는 <code>[ObservableProperty]</code>가 있다 — 알림이 없으면 소스는 바뀌고 화면은 옛 값이다.</li>
<li><input disabled="" type="checkbox"> 목록은 <code>ObservableCollection&lt;T&gt;</code>다 — <code>List&lt;T&gt;.Add</code>는 UI에 추가분을 알리지 않는다.</li>
<li><input disabled="" type="checkbox"> 목록은 <code>ItemsSource</code> + <code>DataTemplate</code> + 알림 가능한 항목 객체다 — 행을 <code>string</code>만 쓰면 행 내용 변경이 화면에 반영되지 않는다.</li>
<li><input disabled="" type="checkbox"> 백그라운드 스레드에서 컬렉션을 바꾸지 않는다 — UI 스레드가 아니면 <code>NotSupportedException</code>이 난다.</li>
<li><input disabled="" type="checkbox"> 변환기·ViewModel에 <code>Visibility</code>/<code>Brush</code>를 남발하지 않는다 — UI 타입이 VM에 들어가면 재사용·테스트가 웹과 무관해진다.</li>
</ul>
<hr>
<h2>3. 성능</h2>
<ul>
<li><input disabled="" type="checkbox"> 큰 <code>ListBox</code>/<code>DataGrid</code>에서 가상화가 켜져 있는지 확인한다 — 가상화가 꺼지면 행 DOM(비주얼)이 모두 생긴다.</li>
<li><input disabled="" type="checkbox"> 무거운 <code>IValueConverter</code>와 과도한 <code>OneWayToSource</code> 루프를 점검한다 — 변환이 렌더마다 파일을 읽으면 입력이 버벅인다.</li>
<li><input disabled="" type="checkbox"> 이미지·아이콘 해상도를 창 크기에 맞게 줄인다 — 4K PNG를 툴바에 넣으면 메모리만 커진다.</li>
<li><input disabled="" type="checkbox"> 디스크·HTTP는 <code>async</code> 명령으로 두고 UI 스레드를 막지 않는다 — <code>Thread.Sleep</code>/<code>GetAwaiter().GetResult()</code>는 창이 하얗게 언다.</li>
<li><input disabled="" type="checkbox"> <code>Binding</code> 오류를 출력 창에서 없앤다 — 잘못된 Path는 예외 없이 빈 화면만 남긴다.</li>
</ul>
<hr>
<h2>4. 안정성</h2>
<ul>
<li><input disabled="" type="checkbox"> <code>App</code> 도메인 예외(<code>DispatcherUnhandledException</code> 등)를 로그로 남긴다 — 처리 안 된 예외는 프로세스만 죽고 원인은 사용자 PC에 없다.</li>
<li><input disabled="" type="checkbox"> 저장·로드 실패를 대화상자 서비스로 알린다 — 실패를 <code>catch</code>만 하면 사용자는 성공으로 안다.</li>
<li><input disabled="" type="checkbox"> 설정 파일에 버전을 두고 마이그레이션한다 — 필드가 빠지면 구버전 JSON이 역직렬화에 실패한다.</li>
<li><input disabled="" type="checkbox"> 종료 시 미저장 변경을 <code>Confirm</code>으로 묻는다 — OS 종료와 창 닫기를 같은 경로로 태운다.</li>
</ul>
<hr>
<h2>5. 배포</h2>
<ul>
<li><input disabled="" type="checkbox"> 대상 TFM이 <code>net8.0-windows</code> / <code>net9.0-windows</code> 등 실제 설치 환경과 같다 — 프레임워크 의존 배포인데 런타임이 없으면 앱이 안 뜬다.</li>
<li><input disabled="" type="checkbox"> self-contained vs framework-dependent를 명시한다 — 용량과 오프라인 설치 요구가 갈린다.</li>
<li><input disabled="" type="checkbox"> MSIX 또는 설치 프로그램에 코드 서명을 검토한다 — 미서명 exe는 SmartScreen에 막힌다.</li>
<li><input disabled="" type="checkbox"> 환경별 설정(로그 경로, API 주소)을 빌드 구성으로 나눈다 — 개발 URL이 고객 PC로 나가면 장애다.</li>
<li><input disabled="" type="checkbox"> 자동 업데이트 정책(없음/사이드카/스토어)을 문서화한다 — 구버전 클라이언트가 API와 어긋나기 쉽다.</li>
</ul>
<hr>
<h2>6. UX</h2>
<ul>
<li><input disabled="" type="checkbox"> Tab 순서가 읽기 순서와 같다 — <code>TabIndex</code>가 제각각이면 키보드만으로 저장에 못 간다.</li>
<li><input disabled="" type="checkbox"> <code>MinWidth</code>/<code>MinHeight</code>와 DPI 스케일을 실제 모니터에서 본다 — 125%에서 버튼이 잘리면 현장 PC와 다르다.</li>
<li><input disabled="" type="checkbox"> 기본 버튼(<code>IsDefault</code>)과 취소(<code>IsCancel</code>)를 폼에 둔다 — Enter/Esc가 아무 동작도 안 하면 데스크톱 습관과 어긋난다.</li>
<li><input disabled="" type="checkbox"> 고대비·다크 테마를 쓸 거면 브러시를 리소스 키로만 참조한다 — 하드코드 <code>#FFFFFF</code>는 다크에서 글자가 사라진다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>WPF 품질은 컨트롤 개수가 아니라 <strong>MVVM 규율과 배포 체크리스트를 끝까지 지키는 일</strong>이다. 항목을 건너뛸 때는 티켓에 이유를 남긴다.</p>
