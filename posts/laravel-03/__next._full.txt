24:T4e20,<h1>Eloquent ORM과 데이터베이스</h1>
<blockquote>
<p>요약: Eloquent는 테이블 한 행을 PHP 객체로 다루는 ORM이고, 마이그레이션·관계·N+1을 같이 잡아야 데이터가 깨지지 않는다.</p>
</blockquote>
<hr>
<h2>1. Eloquent란</h2>
<p><strong>Eloquent</strong>는 Laravel의 ORM(Object-Relational Mapping)이다. <code>posts</code> 테이블의 한 줄을 <code>Post</code> 객체처럼 읽고 저장한다. SQL을 매번 짜지 않아도 되지만, 결국 DB에 쿼리가 나간다. “마법”이 아니라 <strong>쿼리를 대신 만들어 주는 계층</strong>으로 보는 편이 안전하다.</p>
<p>스키마의 진실은 모델 PHP가 아니라 <strong>마이그레이션</strong>이다. 운영 DB를 손으로 고치면 팀원·CI·다음 배포가 서로 다른 테이블을 보게 된다.</p>

<h2>5. N+1</h2>
<p>목록에서 <code>$post-&gt;user-&gt;name</code>을 찍으면, 글 20개에 사용자 조회가 20번 더 나간다. 이게 <strong>N+1</strong>이다. 관계 정의를 잘못해서가 아니라, <strong>필요할 때 따로 조회(지연 로딩)</strong> 하기 때문이다.</p>
<pre><code class="hljs language-php"><span class="hljs-comment">// 나쁨</span>

    <span class="hljs-keyword">echo</span> <span class="hljs-variable">$post</span>-&gt;user-&gt;name;
}

<span class="hljs-comment">// 좋음 — 미리 한 번에</span>
<span class="hljs-variable">$posts</span> = <span class="hljs-title class_">Post</span>::<span class="hljs-title function_ invoke__">with</span>(<span class="hljs-string">&#x27;user&#x27;</span>, <span class="hljs-string">&#x27;tags&#x27;</span>)-&gt;<span class="hljs-title function_ invoke__">paginate</span>(<span class="hljs-number">20</span>);</code></pre>
<p>로컬에서 사고를 예외로 만들 수 있다.</p>
<pre><code class="hljs language-php"><span class="hljs-title class_">Model</span>::<span class="hljs-title function_ invoke__">preventLazyLoading</span>(! <span class="hljs-title function_ invoke__">app</span>()-&gt;<span class="hljs-title function_ invoke__">isProduction</span>());</code></pre>
<p>운영까지 끄면 장애가 난다. 로컬·테스트만 켜고, 터지는 지점을 <code>with</code>로 고친다.</p>

<h2>8. Soft delete</h2>
<p><code>delete()</code>는 <code>deleted_at</code>만 채운다. 기본 쿼리에서 빠진다. 진짜 삭제는 <code>forceDelete()</code>, 포함 조회는 <code>withTrashed()</code>다. 유니크 슬러그를 소프트 삭제 글과 다시 쓰려면 유니크 설계를 먼저 정한다.</p>
<p>생성 시 슬러그 자동 생성은 Observer 또는 모델 <code>creating</code> 훅에 둔다.</p>
<hr>
<h2>9. 흔한 실수</h2>
<ul>
<li><code>$guarded = []</code>로 모든 컬럼을 연다.</li>
<li><code>Post::all()</code> 뒤 루프에서 관계를 읽는다 (N+1).</li>
<li>운영에서 <code>migrate:fresh</code>를 친다.</li>
<li>마이그레이션 없이 운영 DB만 고친다.</li>
<li>긴 트랜잭션 안에서 메일·외부 API를 호출한다.</li>
</ul>
