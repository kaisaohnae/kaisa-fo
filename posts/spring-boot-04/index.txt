24:T39eb,<h1>Spring Data JPA와 영속성 계층</h1>
<blockquote>
<p>요약: JPA 엔티티와 트랜잭션 경계를 명확히 하고, N+1·OSIV·스키마 마이그레이션 함정을 피한다.</p>
</blockquote>
<hr>
<h2>1. 왜 JPA인가</h2>
<p><strong>JPA(Jakarta Persistence API)</strong> 는 객체를 테이블에 매핑하는 표준이다. Hibernate가 구현체고, Spring Data JPA는 리포지토리 인터페이스로 반복 쿼리를 줄인다.</p>
<table>
<thead>
<tr>
<th>계층</th>
<th>책임</th>
</tr>
</thead>
<tbody><tr>
<td>Entity</td>
<td>상태와 불변식</td>
</tr>
<tr>
<td>Repository</td>
<td>영속성 추상화</td>
</tr>
<tr>
<td>Service (<code>@Transactional</code>)</td>
<td>유스케이스 단위 트랜잭션</td>
</tr>
<tr>
<td>Controller</td>
<td>HTTP만</td>
</tr>
</tbody></table>
<p>컨트롤러에 <code>save</code>를 두거나, 리포지토리에 비즈니스 분기를 넣지 않는다.</p>
<hr>
<h2>2. 엔티티</h2>
<p>기본 생성자는 JPA용으로 <code>protected</code>, 변경은 setter 대신 도메인 메서드로 둔다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Entity</span>
<span class="hljs-meta">@Table(name = &quot;users&quot;)</span>
<span class="hljs-meta">@EntityListeners(AuditingEntityListener.class)</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">User</span> {

    <span class="hljs-meta">@Id</span>
    <span class="hljs-meta">@GeneratedValue(strategy = GenerationType.IDENTITY)</span>
    <span class="hljs-keyword">private</span> Long id;

    <span class="hljs-meta">@Column(nullable = false, unique = true, length = 100)</span>
    <span class="hljs-keyword">private</span> String email;

    <span class="hljs-meta">@Column(nullable = false, length = 50)</span>
    <span class="hljs-keyword">private</span> String name;

    <span class="hljs-meta">@CreatedDate</span>
    <span class="hljs-meta">@Column(nullable = false, updatable = false)</span>
    <span class="hljs-keyword">private</span> Instant createdAt;

    <span class="hljs-meta">@LastModifiedDate</span>
    <span class="hljs-keyword">private</span> Instant updatedAt;

    <span class="hljs-type">protected</span> <span class="hljs-title function_">User</span><span class="hljs-params">()</span> {}

    <span class="hljs-keyword">public</span> <span class="hljs-keyword">static</span> <span class="hljs-type">User</span> <span class="hljs-title function_">create</span><span class="hljs-params">(String email, String name)</span> {
        <span class="hljs-type">User</span> <span class="hljs-variable">user</span> <span class="hljs-operator">=</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">User</span>();
        user.email = email;
        user.name = name;
        <span class="hljs-keyword">return</span> user;
    }

    <span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">rename</span><span class="hljs-params">(String name)</span> {
        <span class="hljs-keyword">if</span> (name == <span class="hljs-literal">null</span> || name.isBlank()) {
            <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">IllegalArgumentException</span>(<span class="hljs-string">&quot;name required&quot;</span>);
        }
        <span class="hljs-built_in">this</span>.name = name;
    }
}</code></pre>
<p><code>@EnableJpaAuditing</code>을 켜야 <code>@CreatedDate</code>가 동작한다. <code>equals</code>/<code>hashCode</code>를 전 필드 Lombok으로 만들면 영속 전후 동등성이 깨지기 쉽다. 식별자 기준으로 신중히 구현한다.</p>
<p>공통 시각 필드는 <code>@MappedSuperclass</code>로 빼고, 소프트 삭제는 <code>deletedAt</code> 또는 Hibernate <code>@SoftDelete</code>로 명시한다.</p>
<hr>
<h2>3. 리포지토리</h2>
<p>파생 메서드 → JPQL <code>@Query</code> → <code>Specification</code> / QueryDSL 순으로 복잡도를 올린다.</p>
<pre><code class="hljs language-java"><span class="hljs-keyword">public</span> <span class="hljs-keyword">interface</span> <span class="hljs-title class_">UserRepository</span> <span class="hljs-keyword">extends</span> <span class="hljs-title class_">JpaRepository</span>&lt;User, Long&gt; {
    <span class="hljs-type">Optional</span>&lt;User&gt; <span class="hljs-title function_">findByEmail</span><span class="hljs-params">(String email)</span>;
    <span class="hljs-type">boolean</span> <span class="hljs-title function_">existsByEmail</span><span class="hljs-params">(String email)</span>;

    <span class="hljs-meta">@Query(&quot;select u from User u where u.name like %:keyword%&quot;)</span>
    <span class="hljs-type">List</span>&lt;User&gt; <span class="hljs-title function_">searchByName</span><span class="hljs-params">(<span class="hljs-meta">@Param(&quot;keyword&quot;)</span> String keyword)</span>;

    <span class="hljs-meta">@Modifying(clearAutomatically = true, flushAutomatically = true)</span>
    <span class="hljs-meta">@Query(&quot;update User u set u.name = :name where u.id = :id&quot;)</span>
    <span class="hljs-type">int</span> <span class="hljs-title function_">rename</span><span class="hljs-params">(<span class="hljs-meta">@Param(&quot;id&quot;)</span> Long id, <span class="hljs-meta">@Param(&quot;name&quot;)</span> String name)</span>;
}</code></pre>
<p>벌크 <code>@Modifying</code>은 영속성 컨텍스트를 건너뛴다. <code>clearAutomatically</code> 없이 같은 트랜잭션에서 엔티티를 다시 쓰면 DB와 객체가 어긋난다.</p>
<hr>
<h2>4. 트랜잭션</h2>
<p>한 줄 정의: 트랜잭션은 <strong>한 유스케이스가 전부 성공하거나 전부 롤백</strong>되는 경계다. 클래스를 <code>readOnly = true</code>로 두고 쓰기 메서드만 <code>@Transactional</code>을 연다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Service</span>
<span class="hljs-meta">@Transactional(readOnly = true)</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">UserService</span> {

    <span class="hljs-keyword">private</span> <span class="hljs-keyword">final</span> UserRepository userRepository;

    <span class="hljs-type">public</span> <span class="hljs-title function_">UserService</span><span class="hljs-params">(UserRepository userRepository)</span> {
        <span class="hljs-built_in">this</span>.userRepository = userRepository;
    }

    <span class="hljs-keyword">public</span> <span class="hljs-type">UserResponse</span> <span class="hljs-title function_">get</span><span class="hljs-params">(Long id)</span> {
        <span class="hljs-keyword">return</span> userRepository.findById(id)
                .map(UserMapper::toResponse)
                .orElseThrow(() -&gt; <span class="hljs-keyword">new</span> <span class="hljs-title class_">UserNotFoundException</span>(id));
    }

    <span class="hljs-meta">@Transactional</span>
    <span class="hljs-keyword">public</span> <span class="hljs-type">UserResponse</span> <span class="hljs-title function_">create</span><span class="hljs-params">(CreateUserRequest request)</span> {
        <span class="hljs-keyword">if</span> (userRepository.existsByEmail(request.email())) {
            <span class="hljs-keyword">throw</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">DuplicateEmailException</span>(request.email());
        }
        <span class="hljs-type">User</span> <span class="hljs-variable">saved</span> <span class="hljs-operator">=</span> userRepository.save(User.create(request.email(), request.name()));
        <span class="hljs-keyword">return</span> UserMapper.toResponse(saved);
    }
}</code></pre>
<p>전파·격리 수준은 기본값으로 대부분 충분하다. 긴 트랜잭션 안에서 외부 HTTP를 호출하면 커넥션을 붙잡은 채 대기한다.</p>
<hr>
<h2>5. 연관과 지연 로딩</h2>
<p>연관은 <strong>LAZY</strong>가 기본 전략이다. <code>EAGER</code>는 목록 조회마다 조인이 붙는 사고의 주범이다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@ManyToOne(fetch = FetchType.LAZY, optional = false)</span>
<span class="hljs-meta">@JoinColumn(name = &quot;user_id&quot;)</span>
<span class="hljs-keyword">private</span> User user;

<span class="hljs-meta">@OneToMany(mappedBy = &quot;order&quot;, cascade = CascadeType.ALL, orphanRemoval = true)</span>
<span class="hljs-keyword">private</span> <span class="hljs-type">List</span>&lt;OrderLine&gt; <span class="hljs-variable">lines</span> <span class="hljs-operator">=</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">ArrayList</span>&lt;&gt;();

<span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">addLine</span><span class="hljs-params">(OrderLine line)</span> {
    lines.add(line);
    line.setOrder(<span class="hljs-built_in">this</span>);
}</code></pre>
<p>양방향은 편의 메서드로 양쪽을 맞춘다.</p>
<hr>
<h2>6. N+1과 OSIV</h2>
<p><strong>N+1</strong>: 목록 1번 조회 후 연관에 접근할 때마다 쿼리가 N번 더 나간다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Query(&quot;select o from Order o join fetch o.user where o.id = :id&quot;)</span>
<span class="hljs-type">Optional</span>&lt;Order&gt; <span class="hljs-title function_">findWithUser</span><span class="hljs-params">(<span class="hljs-meta">@Param(&quot;id&quot;)</span> Long id)</span>;

<span class="hljs-meta">@EntityGraph(attributePaths = {&quot;lines&quot;})</span>
<span class="hljs-type">Optional</span>&lt;Order&gt; <span class="hljs-title function_">findWithLinesById</span><span class="hljs-params">(Long id)</span>;

<span class="hljs-meta">@Query(&quot;&quot;&quot;
        select new com.example.demo.order.OrderSummary(o.id, u.email, o.totalAmount)
        from Order o join o.user u
        where o.status = :status
        &quot;&quot;&quot;)</span>
<span class="hljs-type">List</span>&lt;OrderSummary&gt; <span class="hljs-title function_">findSummaries</span><span class="hljs-params">(OrderStatus status)</span>;</code></pre>
<p>읽기 전용 화면에 DTO 프로젝션이 가장 싸다. fetch join은 컬렉션을 두 개 이상 동시에 끌어오면 카테시안 곱이 난다.</p>
<p><strong>OSIV(Open Session In View)</strong> 는 뷰 렌더까지 영속성 컨텍스트를 열어 두는 설정이다. Boot 기본은 <code>true</code>이고, 운영은 <code>false</code>를 권장한다. 컨트롤러에서 지연 로딩이 터지면 쿼리를 고친다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">jpa:</span>
    <span class="hljs-attr">open-in-view:</span> <span class="hljs-literal">false</span></code></pre>
<hr>
<h2>7. Flyway와 낙관적 락</h2>
<p><code>ddl-auto: update</code>는 로컬 실험용이다. 운영 스키마의 진실은 <strong>Flyway/Liquibase 마이그레이션 파일</strong>이다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">jpa:</span>
    <span class="hljs-attr">hibernate:</span>
      <span class="hljs-attr">ddl-auto:</span> <span class="hljs-string">validate</span>
  <span class="hljs-attr">flyway:</span>
    <span class="hljs-attr">enabled:</span> <span class="hljs-literal">true</span></code></pre>
<pre><code class="hljs">db<span class="hljs-regexp">/migration/</span>
  V1__create_users.sql</code></pre>
<pre><code class="hljs language-sql"><span class="hljs-keyword">CREATE TABLE</span> users (
    id BIGSERIAL <span class="hljs-keyword">PRIMARY KEY</span>,
    email <span class="hljs-type">VARCHAR</span>(<span class="hljs-number">100</span>) <span class="hljs-keyword">NOT NULL</span> <span class="hljs-keyword">UNIQUE</span>,
    name <span class="hljs-type">VARCHAR</span>(<span class="hljs-number">50</span>) <span class="hljs-keyword">NOT NULL</span>,
    created_at TIMESTAMPTZ <span class="hljs-keyword">NOT NULL</span>,
    updated_at TIMESTAMPTZ
);</code></pre>
<p>동시 수정 충돌은 <code>@Version</code> 낙관적 락으로 잡는다. 실패 시 <code>OptimisticLockException</code> → 409 또는 재조회 후 재시도.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Version</span>
<span class="hljs-keyword">private</span> Long version;</code></pre>
<hr>
