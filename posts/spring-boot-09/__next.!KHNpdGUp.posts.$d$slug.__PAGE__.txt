3:T2881,<h1>캐시·Resilience·성능 최적화</h1>
<blockquote>
<p>요약: 측정 뒤에 캐시·재시도·서킷 브레이커·타임아웃을 넣고, 쿼리와 페이로드 병목을 줄인다.</p>
</blockquote>
<hr>
<h2>1. 왜 측정이 먼저인가</h2>
<p>감으로 캐시를 켜면 잘못된 키·TTL이 더 큰 장애가 된다. 순서는 측정 → 쿼리/N+1 → 풀·타임아웃 → 캐시 → 스케일 아웃이다. 가장 싼 최적화는 <strong>안 하는 일</strong>을 줄이는 것이다.</p>
<hr>
<h2>2. Spring Cache</h2>
<p>한 줄 정의: 같은 입력의 비싼 조회 결과를 <strong>이름 붙은 저장소</strong>에 잠시 두는 것이다. <code>@EnableCaching</code> + <code>@Cacheable</code> / <code>@CacheEvict</code>가 선언적 API다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Configuration</span>
<span class="hljs-meta">@EnableCaching</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">CacheConfig</span> {
    <span class="hljs-meta">@Bean</span>
    <span class="hljs-type">CacheManager</span> <span class="hljs-title function_">cacheManager</span><span class="hljs-params">()</span> {
        <span class="hljs-keyword">return</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">ConcurrentMapCacheManager</span>(<span class="hljs-string">&quot;products&quot;</span>, <span class="hljs-string">&quot;users&quot;</span>);
    }
}</code></pre>
<pre><code class="hljs language-java"><span class="hljs-meta">@Cacheable(cacheNames = &quot;products&quot;, key = &quot;#id&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-type">ProductResponse</span> <span class="hljs-title function_">get</span><span class="hljs-params">(Long id)</span> { }

<span class="hljs-meta">@CacheEvict(cacheNames = &quot;products&quot;, key = &quot;#id&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-type">void</span> <span class="hljs-title function_">update</span><span class="hljs-params">(Long id, UpdateProductRequest request)</span> { }</code></pre>
<p><code>ConcurrentMap</code>은 프로세스 하나용이고 TTL이 없다. 단일 인스턴스에서 TTL이 필요하면 Caffeine이 기본선이다. 인스턴스가 여러 개면 Redis(<code>spring-boot-starter-data-redis</code>)다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">cache:</span>
    <span class="hljs-attr">type:</span> <span class="hljs-string">caffeine</span>
    <span class="hljs-attr">caffeine:</span>
      <span class="hljs-attr">spec:</span> <span class="hljs-string">maximumSize=10_000,expireAfterWrite=5m</span></code></pre>
<p>캐시 키가 사용자와 무관하면 권한 데이터가 섞인다. TTL과 무효화를 같이 정한다. <strong>캐시 스탬피드</strong>는 만료 순간 요청이 한꺼번에 원본을 두드리는 현상이다. 락·singleflight 또는 소프트 만료로 줄인다. <code>@Cacheable</code> 메서드가 self-invocation(같은 클래스 내부 호출)이면 프록시를 안 타서 캐시가 비어 있다.</p>
<hr>
<h2>3. Resilience4j</h2>
<p>한 줄 정의: 원격 호출이 실패·지연할 때 <strong>재시도·차단·격리</strong>로 내 스레드와 의존성을 보호하는 라이브러리다. 아티팩트는 <code>resilience4j-spring-boot3</code>다.</p>
<p>외부 호출에는 타임아웃이 필수다. 타임아웃 없는 클라이언트는 가상 스레드든 플랫폼 스레드든 풀을 고갈시킨다.</p>
<pre><code class="hljs language-java"><span class="hljs-type">JdkClientHttpRequestFactory</span> <span class="hljs-variable">factory</span> <span class="hljs-operator">=</span> <span class="hljs-keyword">new</span> <span class="hljs-title class_">JdkClientHttpRequestFactory</span>();
factory.setReadTimeout(Duration.ofSeconds(<span class="hljs-number">3</span>));
<span class="hljs-type">RestClient</span> <span class="hljs-variable">client</span> <span class="hljs-operator">=</span> RestClient.builder()
        .requestFactory(factory)
        .baseUrl(props.baseUrl())
        .build();</code></pre>
<h3>Retry</h3>
<p>멱등하지 않은 POST에 무분별한 재시도는 결제를 두 번 만든다. 네트워크·408·429·5xx만, 그리고 Idempotency-Key가 있을 때만 재시도한다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">resilience4j:</span>
  <span class="hljs-attr">retry:</span>
    <span class="hljs-attr">instances:</span>
      <span class="hljs-attr">payment:</span>
        <span class="hljs-attr">maxAttempts:</span> <span class="hljs-number">3</span>
        <span class="hljs-attr">waitDuration:</span> <span class="hljs-string">200ms</span>
        <span class="hljs-attr">retryExceptions:</span>
          <span class="hljs-bullet">-</span> <span class="hljs-string">java.io.IOException</span></code></pre>
<pre><code class="hljs language-java"><span class="hljs-meta">@Retry(name = &quot;payment&quot;, fallbackMethod = &quot;payFallback&quot;)</span>
<span class="hljs-keyword">public</span> <span class="hljs-type">PaymentResult</span> <span class="hljs-title function_">pay</span><span class="hljs-params">(PaymentRequest request)</span> {
    <span class="hljs-keyword">return</span> paymentClient.charge(request);
}</code></pre>
<h3>Circuit Breaker</h3>
<p>한 줄 정의: 실패율이 임계를 넘으면 <strong>호출을 잠시 끊고</strong>(open) 연쇄 실패를 막은 뒤, 시험 호출(half-open)로 닫는다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">resilience4j:</span>
  <span class="hljs-attr">circuitbreaker:</span>
    <span class="hljs-attr">instances:</span>
      <span class="hljs-attr">payment:</span>
        <span class="hljs-attr">slidingWindowSize:</span> <span class="hljs-number">20</span>
        <span class="hljs-attr">failureRateThreshold:</span> <span class="hljs-number">50</span>
        <span class="hljs-attr">waitDurationInOpenState:</span> <span class="hljs-string">10s</span></code></pre>
<h3>Bulkhead / RateLimiter / Fallback</h3>
<p>Bulkhead는 동시 실행 수를 나눠 한 의존성이 스레드를 다 먹지 못하게 한다. Fallback은 비즈니스적으로 안전할 때만 쓴다. 가짜 성공은 재고·결제에서 금지다.</p>
<pre><code class="hljs language-java"><span class="hljs-keyword">private</span> <span class="hljs-type">PaymentResult</span> <span class="hljs-title function_">payFallback</span><span class="hljs-params">(PaymentRequest request, Throwable t)</span> {
    <span class="hljs-keyword">return</span> PaymentResult.failed(<span class="hljs-string">&quot;temporary unavailable&quot;</span>);
}</code></pre>
<hr>
<h2>4. DB와 페이로드</h2>
<ul>
<li><code>WHERE</code> / <code>JOIN</code> / <code>ORDER BY</code>에 인덱스, <code>EXPLAIN ANALYZE</code>로 확인</li>
<li>목록은 엔티티 그래프 대신 DTO 프로젝션</li>
<li>페이지 크기 상한, 장시간 트랜잭션 금지</li>
</ul>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">datasource:</span>
    <span class="hljs-attr">hikari:</span>
      <span class="hljs-attr">maximum-pool-size:</span> <span class="hljs-number">10</span>
      <span class="hljs-attr">connection-timeout:</span> <span class="hljs-number">3000</span></code></pre>
<p>Hikari <code>maximum-pool-size</code>는 인스턴스 수 × 풀이 DB <code>max_connections</code>를 넘지 않게 둔다. 풀을 키우기 전에 슬로우 쿼리와 트랜잭션 길이를 본다.</p>
<p>오프셋 <code>page=100000</code>은 깊게 갈수록 느리다. 피드성 API는 <strong>키셋 페이지네이션</strong>—이미 본 마지막 id보다 작은 행만 가져오기—이 맞다.</p>
<pre><code class="hljs language-java"><span class="hljs-type">List</span>&lt;Post&gt; <span class="hljs-title function_">findByIdLessThanOrderByIdDesc</span><span class="hljs-params">(Long cursor, Pageable pageable)</span>;</code></pre>
<p>큰 JSON은 전용 DTO와 <code>@JsonIgnore</code>로 줄이고, 파일은 오브젝트 스토리지 + CDN으로 뺀다.</p>
<hr>
<h2>5. 동시성과 멱등</h2>
<p>재고 차감은 낙관적 락·DB 제약·단일 큐 중 하나를 고른다. Redis 분산 락은 만료·펜싱 토큰 없이 쓰기 쉽다.</p>
<pre><code class="hljs language-java"><span class="hljs-meta">@Entity</span>
<span class="hljs-meta">@Table(name = &quot;idempotency_keys&quot;,
        uniqueConstraints = @UniqueConstraint(columnNames = &quot;key_value&quot;))</span>
<span class="hljs-keyword">public</span> <span class="hljs-keyword">class</span> <span class="hljs-title class_">IdempotencyKey</span> {
    <span class="hljs-meta">@Id</span>
    <span class="hljs-keyword">private</span> String keyValue;
    <span class="hljs-keyword">private</span> String responseHash;
}</code></pre>
<p>컨테이너 메모리 한도에 heap을 맞춘다(<code>MaxRAMPercentage</code>). Native Image는 기동·RSS에 유리하지만 빌드와 리플렉션 제약이 있다.</p>
<hr>
<h2>6. 부하 테스트</h2>
<p>k6·Gatling·JMeter로 <strong>같은 시나리오</strong>를 최적화 전후에 돌린다. RPS, p50/p95/p99, 에러율, CPU·힙·GC, DB 커넥션·slow query, 외부 의존성 지연을 같이 본다.</p>
