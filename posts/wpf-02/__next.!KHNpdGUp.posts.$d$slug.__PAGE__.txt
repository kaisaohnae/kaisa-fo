3:T3485,<h1>데이터 바인딩과 ObservableCollection</h1>
<blockquote>
<p>요약: INotifyPropertyChanged와 ObservableCollection으로 값·목록 변경을 화면에 반영하고, DataTemplate로 행 UI를 분리하는 방법을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 왜 바인딩인가</h2>
<p>WPF 컨트롤에 <code>textBlock.Text = name</code>을 매번 대입하면 View와 상태가 섞인다. 바인딩은 <strong>소스 속성 ↔ 컨트롤 속성</strong>을 XAML이 연결한다. 소스가 “바뀌었다”고 알려야 화면이 따라간다.</p>
<p>언제 무엇을 쓰는가.</p>
<table>
<thead>
<tr>
<th>상황</th>
<th>선택</th>
</tr>
</thead>
<tbody><tr>
<td>이름·체크처럼 필드 하나</td>
<td><code>INotifyPropertyChanged</code> 속성</td>
</tr>
<tr>
<td>추가·삭제가 있는 목록</td>
<td><code>ObservableCollection&lt;T&gt;</code></td>
</tr>
<tr>
<td>행의 모양</td>
<td><code>DataTemplate</code></td>
</tr>
<tr>
<td>표시 형식만 다름 (bool → 색)</td>
<td><code>IValueConverter</code></td>
</tr>
</tbody></table>
<p><code>List&lt;T&gt;</code>에 <code>Add</code>해도 UI는 모른다. 컬렉션 변경 알림이 있는 <code>ObservableCollection&lt;T&gt;</code>를 쓴다.</p>
<hr>
<h2>2. 핵심 구성</h2>
<table>
<thead>
<tr>
<th>구성</th>
<th>한 줄</th>
</tr>
</thead>
<tbody><tr>
<td>DataContext</td>
<td>이 화면이 바라보는 데이터 소스. 바인딩의 루트</td>
</tr>
<tr>
<td>Path</td>
<td><code>User.Name</code>처럼 속성 경로</td>
</tr>
<tr>
<td>Mode</td>
<td><code>OneWay</code> 표시만, <code>TwoWay</code> 입력도 소스로</td>
</tr>
<tr>
<td>UpdateSourceTrigger</td>
<td><code>LostFocus</code> 기본. 타이핑마다면 <code>PropertyChanged</code></td>
</tr>
<tr>
<td><code>INotifyPropertyChanged</code></td>
<td>속성 setter에서 UI에 변경을 알린다</td>
</tr>
<tr>
<td><code>ObservableCollection&lt;T&gt;</code></td>
<td>항목 추가·삭제·이동을 UI에 알린다</td>
</tr>
</tbody></table>
<p><code>TextBox.Text</code>의 기본 Mode는 TwoWay다. <code>TextBlock.Text</code>는 OneWay다.</p>
<hr>
<h2>3. 동작하는 예: 사용자 목록</h2>
<p><code>ViewModels/UserItem.cs</code>:</p>
<pre><code class="hljs language-csharp"><span class="hljs-keyword">using</span> CommunityToolkit.Mvvm.ComponentModel;

<span class="hljs-keyword">namespace</span> <span class="hljs-title">MyApp.ViewModels</span>;

<span class="hljs-keyword">public</span> <span class="hljs-keyword">partial</span> <span class="hljs-keyword">class</span> <span class="hljs-title">UserItem</span> : <span class="hljs-title">ObservableObject</span>

<p>항목 안의 <code>Name</code>이 바뀌려면 항목 자체도 알림 객체여야 한다. <code>record</code> 문자열만 바꿔서는 행 텍스트가 안 바뀐다.</p>

<li><code>ItemsSource</code> — 목록 소스</li>
<li><code>ItemTemplate</code> — 한 행이 바라보는 DataContext는 <code>UserItem</code></li>
<li><code>SelectedItem</code> — 현재 선택. TwoWay로 ViewModel과 맞춘다</li>
<li><code>AddUserCommand</code> — <code>[RelayCommand] AddUser</code>가 생성하는 명령 이름</li>
</ul>
<p>툴킷 없이 알림을 직접 쓰려면:</p>
<pre><code class="hljs language-csharp"><span class="hljs-keyword">public</span> <span class="hljs-keyword">event</span> PropertyChangedEventHandler? PropertyChanged;

<span class="hljs-function"><span class="hljs-keyword">private</span> <span class="hljs-keyword">void</span> <span class="hljs-title">OnPropertyChanged</span>(<span class="hljs-params">[CallerMemberName] <span class="hljs-built_in">string</span>? name = <span class="hljs-literal">null</span></span>)</span>
    =&gt; PropertyChanged?.Invoke(<span class="hljs-keyword">this</span>, <span class="hljs-keyword">new</span> PropertyChangedEventArgs(name));</code></pre>
<p>setter에서 <code>_name = value</code> 뒤에 <code>OnPropertyChanged()</code>를 호출한다. 알림이 없으면 바인딩 소스는 바뀌었는데 화면은 옛 값이다.</p>
<hr>
<h2>4. 변환과 모드</h2>
<pre><code class="hljs language-xml"><span class="hljs-tag">&lt;<span class="hljs-name">TextBlock</span> <span class="hljs-attr">Text</span>=<span class="hljs-string">&quot;{Binding Price, StringFormat={}{0:N0}원}&quot;</span> /&gt;</span></code></pre>
<p>형식만이면 <code>StringFormat</code>으로 충분하다. bool → Visibility는 내장 <code>BooleanToVisibilityConverter</code> 또는 작은 <code>IValueConverter</code>다. ViewModel에 UI 타입(<code>Visibility</code>, <code>Brush</code>)을 넣지 않는 편이 테스트가 쉽다.</p>
<p>백그라운드 스레드에서 컬렉션을 바꾸면 예외가 난다. UI 스레드(<code>Dispatcher.Invoke</code>) 또는 <code>BindingOperations.EnableCollectionSynchronization</code>을 검토한다. 기본은 UI 스레드에서만 <code>Add</code>/<code>Remove</code>한다.</p>
<hr>
<h2>5. 주의 / 흔한 실수</h2>
<ul>
<li><strong>속성 알림 없이 <code>Name = x</code>.</strong> 화면이 안 바뀐다. 툴킷 또는 <code>OnPropertyChanged</code>.</li>
<li><strong><code>List&lt;T&gt;</code>를 <code>ItemsSource</code>에 넣고 나중에 <code>Add</code>.</strong> 초기 표시만 되고 추가분이 안 붙는다.</li>
<li><strong>컬렉션 프로퍼티를 get-only가 아닌 채 재할당.</strong> <code>Users = new ObservableCollection&lt;...&gt;()</code>는 새 객체라, 바인딩이 옛 컬렉션을 볼 수 있다. <code>Clear</code> 후 <code>Add</code>하거나 알림이 있는 setter로 교체한다.</li>
<li><strong>행 모델이 <code>string</code>뿐인데 행 내용을 바꾸고 기대.</strong> 문자열은 알림이 없다. <code>UserItem</code>처럼 객체를 둔다.</li>
<li><strong><code>UpdateSourceTrigger</code> 기본값으로 타이핑마다 검증.</strong> <code>TextBox</code>는 포커스를 잃어야 소스가 갱신된다. 즉시면 <code>PropertyChanged</code>를 명시한다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>WPF 생산성은 컨트롤 종류가 아니라 <strong>변경 통지 + 컬렉션 + 템플릿</strong>이다.</p>
<ul>
<li>필드 → <code>INotifyPropertyChanged</code> / <code>[ObservableProperty]</code></li>
<li>목록 → <code>ObservableCollection&lt;T&gt;</code></li>
<li>행 UI → <code>DataTemplate</code> (행의 DataContext = 항목)</li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li>추가 버튼으로 이름이 목록에 붙는지, 선택 삭제로 빠지는지 확인한다.</li>
<li>행의 <code>CheckBox</code>를 토글해 <code>IsActive</code>가 유지되는지 확인한다.</li>
<li><code>Users</code>를 <code>List&lt;UserItem&gt;</code>으로 바꿔 <code>Add</code>한 뒤 화면이 안 바뀌는 것을 보고 다시 <code>ObservableCollection</code>으로 되돌린다.</li>
</ol>
