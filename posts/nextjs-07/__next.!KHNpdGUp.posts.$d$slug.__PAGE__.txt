3:T3faf,<h1>Route Handler와 Server Actions</h1>
<blockquote>
<p>요약: 앱 밖 API는 Route Handler로, 같은 앱의 폼 저장은 Server Action으로 나누고, 정적 호스팅 제약을 확인한다.</p>
</blockquote>
<hr>
<h2>1. 왜 이 주제가 필요한가</h2>
<p>브라우저만으로는 메일을 보내거나 DB에 쓰지 못한다. 그 작업은 서버가 한다.</p>
<p>App Router에는 길이 두 개다. <strong>Route Handler</strong>는 <code>app/api/.../route.ts</code>에 HTTP 메서드를 여는 방식이다. <strong>Server Action</strong>은 함수를 서버에서 실행하고, 폼의 <code>action</code>에 바로 연결한다.</p>
<p>둘 다 Node 서버가 있는 배포에서 의미가 있다. <code>output: &#39;export&#39;</code>면 이 런타임이 없다.</p>
<hr>
<h2>2. 한 줄 규칙</h2>
<p>외부 시스템·웹훅·다른 클라이언트가 치는 엔드포인트는 Route Handler다. 같은 Next 앱의 폼·뮤테이션은 Server Action이다.</p>
<p>입력은 반드시 검증한다. 시크릿은 서버 파일에만 둔다.</p>
<hr>
<h2>3. 예제</h2>
<h3>Route Handler</h3>

<span class="hljs-keyword">import</span> {<span class="hljs-title class_">NextResponse</span>} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next/server&#x27;</span>;

}

<span class="hljs-keyword">export</span> <span class="hljs-keyword">async</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">POST</span>(<span class="hljs-params"><span class="hljs-attr">request</span>: <span class="hljs-title class_">Request</span></span>) {

<p><code>GET</code> / <code>POST</code> / <code>PUT</code> / <code>PATCH</code> / <code>DELETE</code>를 함수 이름으로 export한다. URL은 폴더 경로다. 위 파일은 <code>/api/hello</code>.</p>
<p>용도: 결제 웹훅, 모바일 앱이 치는 API, 브라우저 CORS를 피해 서버에서 외부 API를 대신 호출하는 프록시.</p>
<p>Next.js 15부터 GET Handler도 기본적으로 캐시하지 않는다. 캐시가 필요하면 응답 헤더나 Route Segment Config를 명시한다.</p>
<pre><code class="hljs language-ts"><span class="hljs-keyword">export</span> <span class="hljs-keyword">const</span> dynamic = <span class="hljs-string">&#x27;force-dynamic&#x27;</span>;</code></pre>
<p>정적 내보내기에서는 이 파일이 빌드 산출물에 서버로 남지 않거나 지원이 제한된다. 정적 호스팅이면 백엔드를 별도 서버(Cafe24, 클라우드 함수 등)로 둔다.</p>
<h3>Server Actions</h3>
<pre><code class="hljs language-ts"><span class="hljs-comment">// app/contact/actions.ts</span>

  <span class="hljs-keyword">const</span> parsed = schema.<span class="hljs-title function_">safeParse</span>({
    <span class="hljs-attr">email</span>: formData.<span class="hljs-title function_">get</span>(<span class="hljs-string">&#x27;email&#x27;</span>),
    <span class="hljs-attr">body</span>: formData.<span class="hljs-title function_">get</span>(<span class="hljs-string">&#x27;body&#x27;</span>),

  <span class="hljs-keyword">if</span> (!parsed.<span class="hljs-property">success</span>) {
    <span class="hljs-keyword">return</span> {<span class="hljs-attr">ok</span>: <span class="hljs-literal">false</span> <span class="hljs-keyword">as</span> <span class="hljs-keyword">const</span>, <span class="hljs-attr">error</span>: <span class="hljs-string">&#x27;입력 형식이 맞지 않는다&#x27;</span>};

<p><code>&#39;use server&#39;</code>는 이 파일의 export 함수가 서버에서만 실행된다는 표시다. 클라이언트는 네트워크 호출로 이 함수를 부른다. 함수 본문은 브라우저에 안 실리는 것이 정상이다.</p>
<pre><code class="hljs language-tsx"><span class="hljs-comment">// app/contact/page.tsx</span>

      <span class="hljs-tag">&lt;/<span class="hljs-name">label</span>&gt;</span>
      <span class="hljs-tag">&lt;<span class="hljs-name">label</span>&gt;</span>
        내용
        <span class="hljs-tag">&lt;<span class="hljs-name">textarea</span> <span class="hljs-attr">name</span>=<span class="hljs-string">&quot;body&quot;</span> <span class="hljs-attr">required</span> /&gt;</span>
      <span class="hljs-tag">&lt;/<span class="hljs-name">label</span>&gt;</span>
      <span class="hljs-tag">&lt;<span class="hljs-name">button</span> <span class="hljs-attr">type</span>=<span class="hljs-string">&quot;submit&quot;</span>&gt;</span>보내기<span class="hljs-tag">&lt;/<span class="hljs-name">button</span>&gt;</span>
    <span class="hljs-tag">&lt;/<span class="hljs-name">form</span>&gt;</span></span>
  );

<p>폼은 Server Component에 둬도 된다. <code>action</code>에 서버 함수를 넘긴다. JS가 꺼져 있어도 폼 submit은 HTML 기본 동작으로 진행되는 쪽에 가깝다.</p>
<p>진행 상태·에러 메시지를 화면에 바로 쓰려면 Client에서 <code>useActionState</code>를 쓴다.</p>
<pre><code class="hljs language-tsx"><span class="hljs-string">&#x27;use client&#x27;</span>;

<h3>보안</h3>
<ul>
<li>Action·Handler 모두 스키마로 입력 검증</li>
<li>쿠키 세션이 있으면 핸들러·액션 안에서 다시 확인</li>
<li><strong>CSRF(Cross-Site Request Forgery, 다른 사이트가 사용자를 대신해 요청을 보내는 공격)</strong> : Server Actions는 Origin 검사를 한다. 팀 정책과 SameSite 쿠키를 확인한다</li>
<li><code>NEXT_PUBLIC_</code>이 붙은 값은 브라우저에 노출된다. API 키는 붙이지 않는다</li>
</ul>

<h2>정리</h2>
<p>Route Handler는 HTTP 엔드포인트다. Server Action은 앱 내부 서버 함수다.</p>
<p>서버가 있는 호스팅에서만 둘 다 살아 있다. 정적 사이트면 쓰기 작업을 외부 API로 빼고, Next는 HTML을 굽는 쪽에 둔다.</p>
<hr>
<h2>연습</h2>
<ol>
<li>Node 런타임 호스팅에서 <code>POST /api/echo</code> Route Handler를 만들고 JSON을 그대로 돌려준다.</li>
<li>이메일 필드가 있는 Server Action 폼을 만들고, 실패 시 메시지를 보여 준다.</li>
<li>현재 배포가 export면 Next API 없이 연락 폼이 어디로 POST되는지 한 장으로 그린다.</li>
</ol>
