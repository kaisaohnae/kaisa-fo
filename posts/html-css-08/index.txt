24:T1a55,<h1>HTML/CSS 실무 체크리스트</h1>
<blockquote>
<p>요약: 페이지를 내보내기 전에 시맨틱·박스·레이아웃·반응형·토큰·포커스를 한 번씩 확인한다.</p>
</blockquote>
<hr>
<h2>언제 이 목록을 보는가</h2>
<p>기능은 됐는데 모바일에서 가로 스크롤이 나거나, Tab으로 버튼을 못 찾거나, 제목이 <code>div</code>인 페이지에 쓴다. 앞 글에서 다룬 규칙을 한 화면에서 다시 통과시키려는 목록이다.</p>
<p>새 페이지를 열기 전과 리뷰 직전에 같은 순서로 훑는다. 항목마다 “왜”가 붙어 있다. 체크만 하고 이유를 건너뛰면 다음 페이지에서 같은 실수가 반복된다.</p>
<hr>
<h2>1. HTML 뼈대</h2>
<ul>
<li><input disabled="" type="checkbox"> <code>html</code>에 <code>lang</code>을 실제 언어로 둔다. 스크린 리더 발음과 번역 힌트가 여기서 갈린다.</li>
<li><input disabled="" type="checkbox"> <code>charset</code>과 <code>viewport</code> 메타가 있다. 없으면 한글이 깨지거나 모바일에서 화면이 축소되지 않는다.</li>
<li><input disabled="" type="checkbox"> 페이지 <code>h1</code>은 하나이고 제목은 계층을 건너뛰지 않는다. 문서 목차가 스크린 리더 탐색 경로이다.</li>
<li><input disabled="" type="checkbox"> <code>main</code>은 문서당 하나이다. 반복 헤더·내비와 본문을 구분한다.</li>
<li><input disabled="" type="checkbox"> 이동은 <code>a</code>, 동작은 <code>button</code>이다. 클릭 가능한 <code>div</code>는 키보드 초점에서 빠진다.</li>
<li><input disabled="" type="checkbox"> 의미 있는 이미지에 구체적 <code>alt</code>를 두고, 장식은 <code>alt=&quot;&quot;</code>이다. 빈 <code>alt=&quot;이미지&quot;</code>는 소음이다.</li>
<li><input disabled="" type="checkbox"> <code>img</code>에 <code>width</code>·<code>height</code>(또는 동등한 aspect-ratio)를 둔다. 로드 전 자리 붕괴(CLS, 누적 레이아웃 이동)를 줄인다.</li>
<li><input disabled="" type="checkbox"> 폼 입력은 <code>label</code>의 <code>for</code>와 <code>id</code>가 연결된다. <code>placeholder</code>만으로는 이름이 남지 않는다.</li>
</ul>
<hr>
<h2>2. 박스와 레이아웃</h2>
<ul>
<li><input disabled="" type="checkbox"> 전역 <code>box-sizing: border-box</code>이다. <code>width</code>에 padding·border가 포함되어야 칸이 안 넘친다.</li>
<li><input disabled="" type="checkbox"> 한 줄·한 열 정렬은 Flex, 행과 열을 함께 정할 때는 Grid이다. 역할을 섞으면 예외 CSS가 는다.</li>
<li><input disabled="" type="checkbox"> 아이템 간격은 부모 <code>gap</code>으로 통일한다. 자식 <code>margin</code>이 겹치면 세로 간격이 의도와 달라진다.</li>
<li><input disabled="" type="checkbox"> Grid 열 넘침은 <code>minmax(0, 1fr)</code>, Flex 자식 넘침은 <code>min-width: 0</code>을 검토한다. 기본 최소 너비가 내용 크기이기 때문이다.</li>
<li><input disabled="" type="checkbox"> 본문 폭은 <code>min(100% - gutter, max)</code>처럼 상한을 둔다. <code>width: 100%</code>만 있으면 좌우 여백이 사라진다.</li>
</ul>
<hr>
<h2>3. 반응형·시각</h2>
<ul>
<li><input disabled="" type="checkbox"> 좁은 화면 스타일이 기본이고, <code>min-width</code>로만 확장한다. 데스크톱을 깎아 모바일 예외를 만들면 분기가 쌓인다.</li>
<li><input disabled="" type="checkbox"> 브레이크포인트는 기기 이름이 아니라 레이아웃이 깨지는 폭이다. 비슷한 px가 파일마다 흩어지지 않게 한다.</li>
<li><input disabled="" type="checkbox"> 제목 크기에 상한이 있는지 본다. <code>vw</code>만 쓰면 넓은 모니터에서 제목이 과해진다. <code>clamp</code>를 검토한다.</li>
<li><input disabled="" type="checkbox"> 색·간격·글자는 CSS 변수(토큰)를 참조한다. 컴포넌트 hex가 흩어지면 다크 모드와 리브랜딩이 빠진다.</li>
<li><input disabled="" type="checkbox"> 본문과 배경 대비를 확인한다. 브랜드 색을 본문 색으로 쓰지 않는다.</li>
<li><input disabled="" type="checkbox"> 호버 전용 정보가 터치에서도 열리는지 본다. <code>hover: hover</code> 미디어로 장식 호버만 제한한다.</li>
</ul>
<hr>
<h2>4. 접근성·품질</h2>
<ul>
<li><input disabled="" type="checkbox"> <code>:focus-visible</code> 윤곽이 있다. <code>outline: none</code>만 남기면 Tab 위치를 잃는다.</li>
<li><input disabled="" type="checkbox"> 키보드만으로 주요 흐름(내비, 폼 제출, 모달 닫기)이 가능하다. 커스텀 위젯은 Tab·Enter·Esc를 직접 확인한다.</li>
<li><input disabled="" type="checkbox"> 오류·성공은 색 옆 텍스트가 있다. 스크린 리더와 색각 사용자에게 색만으로는 부족하다.</li>
<li><input disabled="" type="checkbox"> <code>prefers-reduced-motion</code>에서 장식 애니메이션을 끈다. 전정기관 부담과 집중 방해를 줄인다.</li>
<li><input disabled="" type="checkbox"> 아이콘 단독 버튼에 <code>aria-label</code>(또는 보이는 텍스트)이 있다. 장식 SVG는 <code>aria-hidden=&quot;true&quot;</code>이다.</li>
<li><input disabled="" type="checkbox"> 불필요한 <code>!important</code>와 과한 특이도를 줄인다. 다음 수정이 덮이지 않는 쪽이 기본선이다.</li>
</ul>
