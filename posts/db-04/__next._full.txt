23:T246f,<h1>Redis: 인메모리 키-값으로 캐시·세션·큐</h1>
<blockquote>
<p>요약: 캐시·세션·카운터처럼 빠르고 만료가 자연스러운 계층에 쓰는 인메모리 저장소의 패턴과 운영 주의를 정리한다.</p>
</blockquote>
<hr>
<h2>1. 언제 Redis인가</h2>
<p>Redis는 메모리 위에서 움직이는 키-값 저장소다. 디스크 DB를 대체하는 도구가 아니다. <strong>빠르고, 만료(TTL)가 자연스럽고, 조금 유실되어도 앱이 다시 만들 수 있는 데이터</strong>에 둔다. TTL은 Time To Live, 키의 수명이다.</p>
<table>
<thead>
<tr>
<th>맞는 경우</th>
<th>덜 맞는 경우</th>
</tr>
</thead>
<tbody><tr>
<td>API 응답·핫 키 캐시</td>
<td>주문·결제처럼 유실되면 안 되는 원본 데이터</td>
</tr>
<tr>
<td>로그인 세션 스토어</td>
<td>복잡한 조인·제약·리포팅 (PostgreSQL/MySQL)</td>
</tr>
<tr>
<td>초당 카운터, 레이트 리밋</td>
<td>문서 구조가 큰 도메인 모델 (MongoDB)</td>
</tr>
<tr>
<td>단순 큐, Streams 로그</td>
<td>파일 하나면 충분한 로컬 SQL (SQLite)</td>
</tr>
<tr>
<td>짧은 분산 락(신중히)</td>
<td>영구 보관이 목적인 아카이브</td>
</tr>
</tbody></table>
<p>주 데이터베이스 앞에 <strong>저지연 계층</strong>으로 두는 그림이 정석이다. Redis만 믿고 원본을 안 남기면 재시작·퇴출(eviction) 때 데이터가 사라진다.</p>
<hr>
<h2>2. 핵심 개념</h2>
<p>키는 문자열이다. 값은 자료구조로 고른다.</p>
<table>
<thead>
<tr>
<th>타입</th>
<th>용도</th>
</tr>
</thead>
<tbody><tr>
<td>String</td>
<td>캐시 블롭, 카운터(<code>INCR</code>)</td>
</tr>
<tr>
<td>Hash</td>
<td>객체 필드 여러 개</td>
</tr>
<tr>
<td>List</td>
<td>단순 큐(왼쪽 push, 오른쪽 pop)</td>
</tr>
<tr>
<td>Set</td>
<td>중복 없는 태그</td>
</tr>
<tr>
<td>Sorted Set</td>
<td>점수 랭킹</td>
</tr>
<tr>
<td>Stream</td>
<td>메시지 로그, 컨슈머 그룹</td>
</tr>
</tbody></table>
<p><strong>TTL</strong>을 기본으로 설계한다. 만료 없는 키는 메모리를 영원히 먹는다.</p>
<p><strong>maxmemory와 eviction.</strong> 메모리가 가득 차면 정책을 따른다. 캐시면 <code>allkeys-lru</code>가 흔하다. LRU는 Least Recently Used, 오래 안 쓴 키부터 지운다. 세션처럼 지우면 안 되는 키와 캐시를 한 인스턴스에 섞을 때는 DB 번호나 키 prefix로 경계를 긋는다.</p>
<p><strong>영속성.</strong> RDB는 특정 시점 스냅샷이다. AOF는 Append Only File, 쓰기를 로그로 남긴다. 둘 다 “디스크 DB만큼” 안전하지 않을 수 있다. <code>fsync</code> 주기에 따라 수 초 유실이 있다. 캐시 전용이면 재시작 유실을 전제로 앱이 동작해야 한다.</p>
<p><strong>핫 키.</strong> 한 키에 트래픽이 몰리면 스케일 아웃 전에 그 노드가 병목이다. 키 설계와 로컬 캐시를 검토한다.</p>
<p><strong>키 이름.</strong> <code>서비스:환경:객체:id:필드</code>처럼 접두를 통일한다. <code>FLUSHDB</code> 사고와 키 충돌을 줄인다. 운영 명령을 앱에서 호출하지 않는다.</p>
<p>센티널은 장애 시 프라이머리를 고른다. 클러스터는 슬롯으로 키를 나눈다. 단일 인스턴스로 충분하면 둘 다 미룬다. 운영 복잡도가 먼저 온다.</p>
<hr>
<h2>3. 최소 예제 — 프로필 캐시와 레이트 리밋</h2>
<p>사용자 프로필을 1시간 캐시하고, 분당 요청 수를 센다.</p>
<pre><code class="hljs language-bash"><span class="hljs-comment"># 프로필 캐시 (1시간)</span>
SET user:42:profile <span class="hljs-string">&#x27;{&quot;name&quot;:&quot;Ada&quot;,&quot;plan&quot;:&quot;pro&quot;}&#x27;</span> EX 3600

GET user:42:profile

<span class="hljs-comment"># 분당 레이트 리밋</span>
INCR ratelimit:42:2026082615
EXPIRE ratelimit:42:2026082615 60</code></pre>
<p>앱 쪽 골격은 이렇다. DB가 원본이고 Redis는 가속이다.</p>
<pre><code class="hljs language-python"><span class="hljs-comment"># 의사 코드. 비밀번호는 YOUR_REDIS_PASSWORD 로 주입한다.</span>
<span class="hljs-keyword">def</span> <span class="hljs-title function_">get_profile</span>(<span class="hljs-params">user_id: <span class="hljs-built_in">int</span></span>) -&gt; <span class="hljs-built_in">dict</span>:
    key = <span class="hljs-string">f&quot;user:<span class="hljs-subst">{user_id}</span>:profile&quot;</span>
    cached = redis.get(key)
    <span class="hljs-keyword">if</span> cached:
        <span class="hljs-keyword">return</span> json.loads(cached)

    profile = db.fetch_profile(user_id)  <span class="hljs-comment"># PostgreSQL 등 원본</span>
    redis.setex(key, <span class="hljs-number">3600</span>, json.dumps(profile))
    <span class="hljs-keyword">return</span> profile</code></pre>
<p>프로필이 바뀌면 캐시를 지운다. <code>DEL user:42:profile</code>. TTL만 기다리면 최대 1시간 낡은 데이터가 나간다.</p>
<p>단순 큐는 리스트로 충분할 때가 많다.</p>
<pre><code class="hljs language-bash">LPUSH <span class="hljs-built_in">jobs</span> <span class="hljs-string">&#x27;{&quot;type&quot;:&quot;email&quot;,&quot;to&quot;:&quot;ada@example.com&quot;}&#x27;</span>
BRPOP <span class="hljs-built_in">jobs</span> 5</code></pre>
<p>작업이 유실되면 안 되면 Redis List만 믿지 않는다. 원본 테이블이나 전용 큐를 검토한다.</p>
<p>연결은 인증을 켠다.</p>
<pre><code class="hljs"><span class="hljs-attribute">redis</span>://:YOUR_REDIS_PASSWORD@redis.internal:<span class="hljs-number">6379</span>/<span class="hljs-number">0</span></code></pre>

<h2>4. 운영 시 주의</h2>
<p><strong>연결.</strong> 앱마다 연결을 무한히 열지 않는다. 풀을 쓰고, 서버리스면 연결 폭주를 특히 조심한다. <code>CLIENT LIST</code>로 이상 연결을 본다.</p>
<p><strong>메모리.</strong> <code>INFO memory</code>로 사용량을 본다. 큰 키 하나(<code>LRANGE</code>로 수백만 건)는 조회 한 번에 서버를 멈출 수 있다. 컬렉션 크기에 상한을 둔다.</p>
<p><strong>백업·유실.</strong> 캐시면 AOF를 꺼도 된다. 세션·큐면 유실 허용 범위를 팀에 합의한다. RDB/AOF는 백업이지 원본 DB 대체가 아니다. 복원 후 앱이 캐시 미스로 원본을 채울 수 있는지 확인한다.</p>
<p><strong>보안.</strong> 기본 포트 6379를 인터넷에 열지 않는다. <code>protected-mode</code>, 비밀번호 또는 ACL, VPC 내부만. <code>FLUSHALL</code> 권한이 앱 계정에 있으면 실수 한 번에 전체가 날아간다.</p>
<p><strong>비용.</strong> 관리형 Redis는 메모리 크기가 곧 요금이다. TTL 없는 키와 개발용 인스턴스 방치가 비용을 만든다.</p>
<p><strong>분산 락.</strong> <code>SET key token NX EX</code> 패턴을 쓰더라도 만료·프로세스 일시 정지에 깨질 수 있다. 결제처럼 치명적이면 DB 제약이나 전용 잠금 서비스를 검토한다.</p>
<p><strong>캐시 스탬피드.</strong> 만료가 한순간에 겹치면 원본 DB가 맞는다. 지터(만료를 조금 흩뿌리기)나 단일 채움 락을 검토한다. 측정 없이 미리 복잡하게 만들지 않는다.</p>
<p><strong>관측.</strong> <code>INFO stats</code>의 <code>evicted_keys</code>, <code>keyspace_hits</code>/<code>misses</code>를 본다. 미스율이 높으면 TTL이 너무 짧거나 키가 난립한 것이다.</p>
<p>캐시와 세션을 한 Redis에 둘 거면 DB 번호나 prefix로 나눈다. 캐시 eviction이 세션 키를 지우면 전원이 로그아웃된다. 트래픽이 커지면 인스턴스를 분리하는 편이 낫다.</p>
<p><strong>흔한 실수.</strong> <code>KEYS *</code>를 운영에서 실행하기(블로킹), 큰 <code>SMEMBERS</code> 한 방, 비밀번호 없는 6379 퍼블릭 오픈. 모니터링은 <code>SCAN</code>을 쓴다.</p>
<hr>
<h2>5. 정리</h2>
<p>Redis는 DB라기보다 <strong>저지연 데이터 구조 서버</strong>다. TTL·메모리·유실 허용을 먼저 합의한다. 원본은 관계형(또는 문서형)에 두고, Redis는 캐시·세션·카운터 계층으로 둔다.</p>
<h3>체크리스트</h3>
<ul>
<li><input disabled="" type="checkbox"> 모든 캐시 키에 TTL을 단다. 만료 없는 키는 메모리 누수다.</li>
<li><input disabled="" type="checkbox"> <code>maxmemory</code>와 eviction 정책을 정한다. 가득 차면 쓰기가 거절되거나 키가 지워진다.</li>
<li><input disabled="" type="checkbox"> 캐시 미스 때 원본에서 다시 채울 수 있는지 확인한다. Redis만의 데이터는 재시작에 약하다.</li>
<li><input disabled="" type="checkbox"> 6379를 프라이빗 네트워크와 인증 뒤로 둔다.</li>
<li><input disabled="" type="checkbox"> <code>FLUSHALL</code>·관리 명령을 앱 계정에서 뺀다.</li>
</ul>
<h3>연습</h3>
<ol>
<li><code>SET</code>/<code>GET</code>/<code>EXPIRE</code>로 프로필 캐시를 재현하고 TTL이 0이 되는지 확인한다.</li>
<li><code>INCR</code>+<code>EXPIRE</code>로 분당 10회 제한을 흉내 낸다.</li>
<li>키를 지운 뒤 앱이 DB에서 다시 읽는지(캐시 미스) 경로를 그려 본다.</li>
</ol>
