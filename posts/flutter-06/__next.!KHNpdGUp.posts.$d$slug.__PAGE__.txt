3:T39dc,<h1>비동기·HTTP·JSON으로 서버 연동</h1>
<blockquote>
<p>요약: 서버 연동은 호출 성공이 아니라 로딩·실패·JSON 계약을 UI가 흡수하는 일이다.</p>
</blockquote>
<hr>
<h2>1. 왜 / 언제</h2>
<p>목록 화면은 서버를 기다린다. 기다리는 동안에도 화면은 살아 있어야 한다. Dart의 <code>async</code>/<code>await</code>는 UI 스레드를 막지 않는다. <code>await</code> 지점에서 함수가 잠시 멈추고, 그동안 프레임은 그려진다.</p>
<p>성공만 그리면 실무에서 깨진다. 네트워크는 실패한다. JSON 필드가 빠진다. 토큰이 만료된다. <strong>로딩·성공·실패 세 상태</strong>를 항상 화면에 대응한다.</p>
<p>이 글은 <code>http</code> + <code>jsonDecode</code> + 모델 <code>fromJson</code>의 기본 계약이다. 복잡한 캐시·재시도는 클라이언트 래퍼나 쿼리 계층으로 나중에 올린다.</p>
<hr>
<h2>2. 핵심</h2>
<p><code>Future</code>는 “나중에 값이 온다”는 약속이다. <code>async</code> 함수는 <code>Future</code>를 돌려준다. <code>await</code>는 그 약속이 끝날 때까지 다음 줄을 미룬다.</p>
<p>HTTP는 부가 효과다. 위젯 <code>build</code> 안에서 호출하지 않는다. <code>build</code>는 여러 번 돈다. 호출은 <code>initState</code>, 버튼 콜백, 또는 상태 계층이 맡는다.</p>
<p>JSON은 문자열이다. <code>jsonDecode</code> 결과는 <code>Map</code>/<code>List</code>/<code>num</code>/<code>String</code>/<code>bool</code>/<code>null</code>의 조합이다. 앱이 쓰는 타입으로 바꾸는 문이 <code>fromJson</code>이다. 서버 계약이 깨지면 여기서 실패해야 한다. 조용히 <code>null</code>을 심으면 화면이 틀린 데이터를 보여 준다.</p>
<p>UI는 세 갈래다.</p>
<table>
<thead>
<tr>
<th>상태</th>
<th>화면</th>
</tr>
</thead>

<td>스피너 또는 스켈레톤</td>
</tr>

<td>성공</td>
<td>데이터 위젯</td>

<td>메시지 + 재시도</td>
</tr>

<p><code>FutureBuilder</code>는 간단한 화면에 맞다. 화면이 커지면 로딩/데이터/에러를 상태 계층에서 모델링한다.</p>
<p>파싱이 매우 크면 <code>compute</code>로 Isolate를 검토한다. 일반 REST 한 건은 메인 isolate로 충분하다.</p>

<p><code>json_serializable</code> / freezed는 팀 합의 후 도입한다. 코드젠이 계약을 없애 주지는 않는다. 서버 필드가 바뀌면 생성 코드도 갱신한다.</p>
<p>목록은 다음 글의 <code>ListView.builder</code>와 맞춘다. 한 번에 받은 JSON 배열을 <code>Column</code> + <code>map</code>으로 펼치지 않는다.</p>
<hr>
<h2>정리</h2>
<p>네트워킹은 호출이 200을 돌려주는가가 아니다. <strong>실패·로딩·파싱 계약을 UI가 흡수하는가</strong>다. <code>async</code>/<code>await</code>로 기다리고, 모델에서 JSON을 검증하고, 세 상태를 그린다.</p>
<hr>
<h2>연습</h2>
<ol>
<li><code>User.fromJson</code>이 필드 타입이 다를 때 예외를 내게 한다.</li>
<li><code>fetchUser</code>에 타임아웃과 non-200 처리를 넣는다.</li>
<li><code>FutureBuilder</code>로 로딩·에러·이름을 그리고, 재시도 버튼을 붙인다.</li>
<li><code>build</code>가 아니라 <code>initState</code>에서 Future를 만들도록 고친다.</li>
