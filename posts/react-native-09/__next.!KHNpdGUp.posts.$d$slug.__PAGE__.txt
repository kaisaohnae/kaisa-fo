3:T2916,<h1>테스트·디버깅·성능</h1>
<blockquote>
<p>요약: 테스트·디버깅·성능 점검을 체크리스트로 두고, 각 항목이 필요한 이유를 한 줄로 적는다.</p>
</blockquote>
<hr>
<h2>1. 왜 측정과 테스트가 먼저인가</h2>
<p>버벅임은 느낌으로 고치면 잘못된 곳을 <code>memo</code>하게 된다. 크래시는 스토어 리뷰로 드러난다. 로그인·결제처럼 돈과 세션이 걸린 흐름은 자동화하지 않으면 회귀한다.</p>
<p>RN은 단위 테스트(Jest)와 사용자 관점 컴포넌트 테스트(Testing Library), 기기 E2E(Maestro 등)를 나눈다. 전부 같은 비중일 필요는 없다. <strong>핵심 폼과 리스트</strong>부터 둔다.</p>
<hr>
<h2>2. 핵심 개념</h2>
<table>
<thead>
<tr>
<th>종류</th>
<th>도구</th>
<th>왜</th>
</tr>
</thead>
<tbody><tr>
<td>단위</td>
<td>Jest + Testing Library</td>
<td>포맷터·훅·검증 로직이 깨져도 화면을 안 켠다</td>
</tr>
<tr>
<td>컴포넌트</td>
<td><code>@testing-library/react-native</code></td>
<td>사용자가 보는 라벨·버튼 기준으로 회귀를 잡는다</td>
</tr>
<tr>
<td>E2E</td>
<td>Maestro / Detox</td>
<td>로그인→홈처럼 OS와 네이티브가 섞인 길을 확인한다</td>
</tr>
</tbody></table>
<p>쿼리는 접근성 역할/라벨이 먼저다. <code>testID</code>는 최후다. 접근성 라벨이 테스트와 스크린 리더를 동시에 받쳐 준다.</p>
<p>Query 테스트는 <code>retry: false</code>인 전용 <code>QueryClient</code>로 감싼다. SecureStore와 <code>fetch</code>는 mock한다. 실제 키체인을 치면 CI가 실패한다.</p>
<p>성능은 JS FPS / UI FPS를 본 다음 리스트 가상화, 이미지 크기, 리렌더 순으로 간다.</p>
<hr>

<h2>5. 정리 — 체크리스트</h2>
<p>각 항목은 <strong>한 줄 이유</strong>다. 통과/미통과만 표시한다.</p>
<h3>테스트</h3>
<ul>
<li><input disabled="" type="checkbox"> LoginForm 성공/실패 테스트 — 인증 진입점이 깨지면 앱 전체가 막힌다</li>
<li><input disabled="" type="checkbox"> 쿼리를 역할·라벨로 작성 — 스크린 리더와 테스트가 같은 이름을 쓴다</li>
<li><input disabled="" type="checkbox"> SecureStore·fetch mock — CI가 실기기 키체인에 의존하지 않는다</li>
<li><input disabled="" type="checkbox"> QueryClient <code>retry: false</code> — 실패한 테스트가 재시도로 느려지지 않는다</li>
<li><input disabled="" type="checkbox"> 핵심 플로우 E2E 하나 — 로그인→홈은 단위 테스트가 못 대신한다</li>
</ul>
<h3>디버깅·관측</h3>
<ul>
<li><input disabled="" type="checkbox"> RN DevTools로 재현 — 추측 로그보다 컴포넌트 트리가 빠르다</li>
<li><input disabled="" type="checkbox"> 개발만 네트워크 로그 — 프로덕션 로그에 헤더·바디가 남으면 사고다</li>
<li><input disabled="" type="checkbox"> Sentry + 릴리즈 매핑 — 스토어 빌드 크래시를 버전과 연결해야 고친다</li>
<li><input disabled="" type="checkbox"> 브레드크럼에 화면·API 실패 — 크래시 직전 사용자 길을 복원한다</li>
<li><input disabled="" type="checkbox"> PII 스크러빙 — 이메일·토큰이 이슈 트래커에 쌓이면 규정 문제가 된다</li>
</ul>
<h3>성능</h3>
<ul>
<li><input disabled="" type="checkbox"> 먼저 FPS를 본다 — 최적화 대상이 JS인지 UI 스레드인지 갈린다</li>
<li><input disabled="" type="checkbox"> FlatList/FlashList — 긴 목록을 한 번에 마운트하지 않는다</li>
<li><input disabled="" type="checkbox"> <code>keyExtractor</code>에 안정 id — index 키는 삽입 시 행을 잘못 재사용한다</li>
<li><input disabled="" type="checkbox"> 행 <code>memo</code> — 부모 리렌더가 보이는 행까지 흔들지 않게 한다</li>
<li><input disabled="" type="checkbox"> <code>expo-image</code> + 크기 — 원본 해상도 디코드가 스크롤을 끊는다</li>
<li><input disabled="" type="checkbox"> Reanimated는 UI 스레드 — <code>setState</code> 애니메이션은 JS를 막는다</li>
<li><input disabled="" type="checkbox"> barrel <code>index.ts</code> 과다 금지 — 쓰지도 않는 모듈이 기동 번들에 들어간다</li>
<li><input disabled="" type="checkbox"> 스플래시에 필수 데이터만 — 기동 때 전부 fetch하면 첫 화면이 늦다</li>
<li><input disabled="" type="checkbox"> <code>useCallback</code>/<code>memo</code>는 측정 후 — 모든 콜백을 감싸면 읽기만 어려워진다</li>
</ul>
<p>Hermes는 Expo 기본에 가깝다. 끄지 않는다.</p>
<h2>연습</h2>
<ol>
<li>LoginForm 단위 테스트 2개(성공/실패)를 작성한다.</li>
<li>SecureStore·fetch를 mock한 Auth 훅 테스트를 만든다.</li>
<li>리스트 행을 <code>memo</code>하고 스크롤을 비교한다.</li>
<li>(선택) Maestro로 로그인→홈을 자동화한다.</li>
<li>위 체크리스트를 통과/미통과로 표시한다.</li>
</ol>
