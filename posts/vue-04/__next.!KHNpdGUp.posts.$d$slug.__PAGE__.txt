3:T416a,<h1>Vue Router와 Pinia로 화면·상태 구성</h1>
<blockquote>
<p>요약: URL과 화면을 라우터로 맞추고, 여러 화면이 공유하는 상태는 Pinia 스토어에 두는 SPA 구성 방법을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 왜 둘을 나누는가</h2>
<p>SPA(단일 페이지 애플리케이션)는 페이지를 통째로 새로고침하지 않고 화면만 바꾼다.</p>
<ul>
<li><strong>Vue Router</strong> — URL ↔ 화면. 주소가 북마크·뒤로 가기의 진실이다.</li>
<li><strong>Pinia</strong> — 여러 화면이 공유하는 클라이언트 상태 창고. 로그인 사용자, UI 설정처럼 서버에 없는 값.</li>
</ul>
<p>폼 입력, 모달 열림처럼 <strong>한 화면만</strong> 아는 값은 컴포넌트 <code>ref</code>에 둔다. 목록 캐시처럼 서버 데이터는 나중 단계에서 TanStack Query 등을 검토한다. 모든 것을 Pinia에 넣지 않는다.</p>
<hr>
<h2>2. 핵심 개념</h2>

<p>Vue 3의 상태 라이브러리는 Vuex가 아니라 <strong>Pinia</strong>가 기본 권장이다.</p>

<h2>4. 상태를 어디에 둘 것인가</h2>
<table>
<thead>
<tr>
<th>상태</th>
<th>위치</th>
</tr>
</thead>
<tbody><tr>
<td>입력 중인 검색어</td>
<td>페이지 컴포넌트 <code>ref</code></td>
</tr>
<tr>
<td>로그인 세션</td>
<td>Pinia (+ httpOnly 쿠키는 서버)</td>
</tr>
<tr>
<td>현재 글 id</td>
<td>URL <code>params</code> (스토어 복제 금지)</td>
</tr>
<tr>
<td>서버 목록 캐시</td>
<td>페칭 라이브러리 검토. Pinia에 수동 복사하지 않음</td>
</tr>
</tbody></table>
<p>URL에 있는 값을 스토어에 또 넣으면 둘이 어긋난다. <code>id</code>는 라우트만 진실로 둔다.</p>
<hr>
<h2>5. 주의 / 흔한 실수</h2>
<ul>
<li><strong>라우터보다 Pinia를 늦게 등록.</strong> <code>beforeEach</code>에서 <code>useAuthStore()</code>가 실패한다.</li>
<li><strong>가드에서 <code>next()</code> (Vue Router 3).</strong> Vue Router 4는 <code>return { name: &#39;login&#39; }</code> 또는 아무것도 반환하지 않으면 통과다.</li>
<li><strong>모든 페이지를 한 번에 import.</strong> <code>() =&gt; import(...)</code> lazy가 초기 번들을 줄인다.</li>
<li><strong>스토어에서 컴포넌트 <code>useRouter()</code>로 화면을 바꾸기.</strong> 스토어는 데이터. 이동은 뷰/가드.</li>
<li><strong>Pinia에 서버 리스트를 미러링.</strong> 중복·만료·페이지네이션이 한 창고에 섞인다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>Router는 <strong>주소와 화면</strong>, Pinia는 <strong>공유 클라이언트 상태</strong>다. 경계를 지키면 SPA가 단순해진다.</p>
<ul>
<li>화면 전환 → <code>routes</code> + <code>RouterView</code></li>
<li>인증 문 → <code>meta</code> + <code>beforeEach</code></li>
<li>공유 상태 → setup 스토어 <code>return { ... }</code></li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li><code>/about</code> 라우트를 lazy 컴포넌트로 추가하고 홈에서 <code>RouterLink</code>로 이동한다.</li>
<li><code>requiresAuth</code> 메타를 홈에도 걸고, 로그아웃 후 홈 진입이 로그인으로 리다이렉트되는지 확인한다.</li>
<li><code>useCounterStore</code>를 만들어 홈과 다른 페이지에서 같은 <code>count</code>가 보이는지 확인한다.</li>
</ol>
