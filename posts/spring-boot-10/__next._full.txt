24:T2933,<h1>운영 배포 — Docker, 설정, Native Image, 프로덕션 체크리스트</h1>
<blockquote>
<p>요약: 환경변수와 컨테이너로 배포하고, 헬스 프로브·그레이스풀 종료·Native Image를 운영 기본선에 맞춘다.</p>
</blockquote>
<hr>
<h2>1. 왜 설정과 프로세스를 나누는가</h2>
<p>앱은 코드와 설정을 분리하고, 로그는 stdout으로 보내며, 종료 신호를 받으면 요청을 비운 뒤 죽는다. Boot에서는 프로파일·환경변수와 <strong>graceful shutdown</strong>이 그 기본선이다.</p>
<p>한 줄 정의: graceful shutdown은 새 요청을 끊고, 진행 중 요청이 끝날 때까지 기다린 다음 프로세스를 종료하는 것이다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">server:</span>
  <span class="hljs-attr">shutdown:</span> <span class="hljs-string">graceful</span>

<span class="hljs-attr">spring:</span>
  <span class="hljs-attr">lifecycle:</span>
    <span class="hljs-attr">timeout-per-shutdown-phase:</span> <span class="hljs-string">30s</span></code></pre>
<p>로드밸런서가 인스턴스를 빼는 시간보다 <code>timeout-per-shutdown-phase</code>가 짧으면 요청이 잘린다.</p>
<hr>
<h2>2. 시크릿</h2>
<p><code>application-prod.yml</code>에 DB 비밀번호를 커밋하거나 이미지에 굽지 않는다. <code>SPRING_PROFILES_ACTIVE=prod</code>, 값은 환경변수·K8s Secret·Secrets Manager·Vault다. 필수 시크릿이 없으면 <strong>기동 실패</strong>가 기본값으로 떠서 잘못된 DB에 붙는 것보다 낫다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">spring:</span>
  <span class="hljs-attr">datasource:</span>
    <span class="hljs-attr">url:</span> <span class="hljs-string">${DB_URL}</span>
    <span class="hljs-attr">username:</span> <span class="hljs-string">${DB_USER}</span>
    <span class="hljs-attr">password:</span> <span class="hljs-string">${DB_PASSWORD}</span></code></pre>

<h2>3. Dockerfile</h2>
<p>Java 21 런타임, non-root, 컨테이너 메모리의 일부만 힙으로 쓴다.</p>
<pre><code class="hljs language-dockerfile"><span class="hljs-keyword">FROM</span> eclipse-temurin:<span class="hljs-number">21</span>-jdk-alpine AS build
<span class="hljs-keyword">WORKDIR</span><span class="language-bash"> /workspace</span>

<h2>5. Kubernetes 프로브</h2>
<p><strong>liveness</strong>는 프로세스가 죽었으면 재시작하고, <strong>readiness</strong>는 준비가 안 됐으면 트래픽을 빼는 검사다. 둘을 같은 URL로 묶으면, 의존성 장애 때 재시작 루프가 난다. Actuator probes를 켜고 관리 포트(예: 8081)를 가리킨다.</p>
<pre><code class="hljs language-yaml"><span class="hljs-attr">livenessProbe:</span>
  <span class="hljs-attr">httpGet:</span>

<span class="hljs-attr">readinessProbe:</span>
  <span class="hljs-attr">httpGet:</span>
    <span class="hljs-attr">path:</span> <span class="hljs-string">/actuator/health/readiness</span>
    <span class="hljs-attr">port:</span> <span class="hljs-number">8081</span>
<span class="hljs-attr">resources:</span>
  <span class="hljs-attr">requests:</span>

  <span class="hljs-attr">limits:</span>
    <span class="hljs-attr">memory:</span> <span class="hljs-string">&quot;768Mi&quot;</span></code></pre>
<p>메모리 limit 없이 JVM만 올리면 노드 OOMKill이 난다. CPU limit은 스로틀이 커질 수 있어 request와 함께 본다.</p>

<h2>7. GraalVM Native Image</h2>
<p>한 줄 정의: 미리 AOT 컴파일한 <strong>네이티브 실행 파일</strong>이다. 기동이 빠르고 RSS가 낮다. Boot 3에서 정식이다.</p>
<pre><code class="hljs language-bash">./mvnw -Pnative native:compile</code></pre>
<p>빌드 시간이 길고, 리플렉션·프록시 힌트가 필요할 수 있다. 서버리스·스케일-to-zero에 잘 맞는다. 상시 트래픽 큰 서비스는 JVM + 컨테이너 메모리 튜닝으로도 충분한 경우가 많다. 라이브러리가 네이티브를 지원하는지 먼저 본다.</p>
<hr>
<h2>8. 로그·시간대</h2>
<p>액세스/감사 로그를 애플리케이션 로그와 나누고 PII를 마스킹한다. 서버 시각은 UTC, 표시만 로컬이다.</p>
