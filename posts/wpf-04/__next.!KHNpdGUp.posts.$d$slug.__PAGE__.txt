3:T31eb,<h1>스타일·리소스·테마 관리</h1>
<blockquote>
<p>요약: ResourceDictionary에 색과 스타일을 모아 StaticResource/DynamicResource로 참조하고, 파일 분리로 테마를 운영하는 방법을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 왜 리소스인가</h2>
<p>창마다 <code>Background=&quot;#0B6E4F&quot;</code>를 복사하면 브랜드 색을 바꿀 때 누락이 생긴다. WPF는 <strong>키로 찾는 리소스 사전</strong>에 브러시·스타일·템플릿을 둔다. 화면은 키만 참조한다.</p>
<p>언제 사전을 나누는가.</p>
<table>
<thead>
<tr>
<th>상황</th>
<th>위치</th>
</tr>
</thead>
<tbody><tr>
<td>이 버튼만</td>
<td>컨트롤 <code>Resources</code></td>
</tr>
<tr>
<td>이 창만</td>
<td><code>Window.Resources</code></td>
</tr>
<tr>
<td>앱 전역 색·기본 버튼</td>
<td><code>App.xaml</code> 또는 병합 사전</td>
</tr>
<tr>
<td>라이트/다크 전환</td>
<td>테마별 <code>ResourceDictionary</code> + <code>DynamicResource</code></td>
</tr>
</tbody></table>
<hr>
<h2>2. 핵심 개념</h2>
<table>
<thead>
<tr>
<th>개념</th>
<th>한 줄</th>
</tr>
</thead>
<tbody><tr>
<td><code>x:Key</code></td>
<td>사전에서 리소스를 찾는 이름</td>
</tr>
<tr>
<td><code>StaticResource</code></td>
<td>로드 시 한 번 해석. 일반 색·스타일</td>
</tr>
<tr>
<td><code>DynamicResource</code></td>
<td>런타임에 키가 바뀌면 다시 적용. 테마 전환</td>
</tr>
<tr>
<td><code>Style</code></td>
<td>같은 타입에 Setter로 속성을 묶는다</td>
</tr>
<tr>
<td><code>TargetType</code></td>
<td>키 없이 그 타입 전체에 암시 스타일</td>
</tr>
<tr>
<td><code>MergedDictionaries</code></td>
<td>여러 <code>.xaml</code> 사전을 한곳으로 합친다</td>
</tr>
</tbody></table>
<p><code>StaticResource</code>가 더 싸다. 실행 중 색을 갈아끼울 때만 <code>DynamicResource</code>를 쓴다. 없는 키는 로드 시 예외(<code>Static</code>) 또는 빈 값(<code>Dynamic</code>)으로 나타난다.</p>
<hr>

<hr>
<h2>4. 테마 전환</h2>
<p>다크 사전 <code>Resources/Colors.Dark.xaml</code>에 같은 <strong>키 이름</strong>으로 다른 <code>Color</code>를 둔다. 런타임에 <code>MergedDictionaries</code>의 해당 항목을 교체한다.</p>
<pre><code class="hljs language-csharp"><span class="hljs-keyword">var</span> appDict = Application.Current.Resources.MergedDictionaries;
<span class="hljs-keyword">var</span> old = appDict.First(d =&gt; d.Source?.OriginalString.Contains(<span class="hljs-string">&quot;Colors&quot;</span>) == <span class="hljs-literal">true</span>);
appDict.Remove(old);
appDict.Insert(<span class="hljs-number">0</span>, <span class="hljs-keyword">new</span> ResourceDictionary
{
    Source = <span class="hljs-keyword">new</span> Uri(<span class="hljs-string">&quot;Resources/Colors.Dark.xaml&quot;</span>, UriKind.Relative),
});</code></pre>
<p>브러시 참조는 <code>DynamicResource</code>여야 교체가 화면에 반영된다.</p>
<pre><code class="hljs language-xml"><span class="hljs-tag">&lt;<span class="hljs-name">TextBlock</span> <span class="hljs-attr">Foreground</span>=<span class="hljs-string">&quot;{DynamicResource TextBrush}&quot;</span> /&gt;</span></code></pre>
<p>키 이름을 테마마다 다르게 만들면 화면 XAML을 다 고쳐야 한다. <strong>같은 키, 다른 값</strong>이 테마의 규칙이다.</p>
<hr>
<h2>5. 주의 / 흔한 실수</h2>
<ul>
<li><strong>병합 순서 반대로.</strong> 스타일이 색보다 먼저면 <code>StaticResource PrimaryBrush</code>를 못 찾는다.</li>
<li><strong>암시 스타일(<code>TargetType</code>만)을 서드파티 컨트롤에 광역 적용.</strong> 라이브러리 버튼까지 브랜드 색이 덮인다. 앱 컨트롤만 키 스타일로 제한하는 편이 안전하다.</li>
<li><strong>테마는 <code>StaticResource</code>로 색을 고정.</strong> 사전을 갈아도 이미 해석된 값이 남는다. 전환 대상은 <code>DynamicResource</code>.</li>
<li><strong><code>Style</code> 안에서 같은 사전의 키를 <code>DynamicResource</code>로 순환 참조.</strong> 로드가 실패한다.</li>
<li><strong>창 <code>Resources</code>에 앱과 같은 키를 다시 정의.</strong> 가까운 사전이 이긴다. 의도가 아니면 중복 키를 만들지 않는다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>WPF UI 일관성은 창을 하나씩 고치는 일이 아니라 <strong>리소스 사전을 시스템으로 두는 일</strong>이다.</p>
<ul>
<li>색·간격 → <code>Colors.xaml</code> 키</li>
<li>컨트롤 기본 모습 → <code>Style</code> + <code>MergedDictionaries</code></li>
<li>테마 → 같은 키 + <code>DynamicResource</code> + 사전 교체</li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li><code>PrimaryBrush</code> 색을 바꾸고 저장·암시 스타일 버튼이 같이 바뀌는지 확인한다.</li>
<li><code>GhostButton</code>만 테두리를 추가해 기본 버튼과 구분되게 한다.</li>
<li><code>Colors.Dark.xaml</code>을 만들고 <code>TextBrush</code>를 밝은 색으로 둔 뒤, 버튼을 눌러 사전을 교체해 본다 (<code>DynamicResource</code> 필요).</li>
</ol>
