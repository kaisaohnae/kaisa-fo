3:T2873,<h1>Next.js App Router로 프로젝트 시작하기</h1>
<blockquote>
<p>요약: App Router와 TypeScript로 Next.js 프로젝트를 만들고, 폴더·페이지·레이아웃의 역할을 구분한다.</p>
</blockquote>
<hr>
<h2>1. 왜 이 주제가 필요한가</h2>
<p>Next.js는 React로 웹을 만들 때 라우팅·렌더·배포를 한 프레임워크에서 처리한다.</p>
<p>예전에는 <code>pages/</code> 폴더가 URL이 되는 <strong>Pages Router</strong>를 썼다. 지금은 <strong>App Router</strong>가 기본이다. <code>app/</code> 폴더 구조가 URL이 되고, 레이아웃을 중첩할 수 있으며, 컴포넌트는 서버에서 먼저 돈다.</p>
<p>신규 프로젝트는 Pages Router를 기본선으로 두지 않는다. 레거시 코드에서만 만난다.</p>
<p>실무 기본 조합은 <strong>Next.js 15/16 + TypeScript + App Router</strong>다.</p>
<hr>
<h2>2. 한 줄 규칙</h2>
<p>폴더가 곧 URL이다. <code>page.tsx</code>가 있는 폴더만 공개 주소가 된다.</p>
<p>호스팅을 먼저 고른다. 서버가 있는 배포(Vercel 등)와 HTML만 올리는 정적 배포는 쓸 수 있는 기능이 다르다.</p>
<hr>
<h2>3. 예제</h2>
<h3>프로젝트 생성</h3>
<pre><code class="hljs language-bash">npx create-next-app@latest my-app
<span class="hljs-built_in">cd</span> my-app
npm run dev</code></pre>
<p>권장 옵션: TypeScript, ESLint, App Router, Tailwind는 팀 취향.</p>
<p><code>src/</code> 디렉터리 여부는 팀 규칙이다. 이 글은 <code>src/app/</code> 기준으로 적는다. <code>app/</code>이 프로젝트 루트에 있어도 규칙은 같다.</p>
<p>브라우저에서 <code>http://localhost:3000</code>이 열리면 준비된 것이다.</p>
<h3>디렉터리</h3>

<p><code>layout.tsx</code>만 있고 <code>page.tsx</code>가 없으면 그 경로는 주소가 아니다.</p>
<h3>루트 레이아웃과 첫 페이지</h3>
<pre><code class="hljs language-tsx"><span class="hljs-comment">// src/app/layout.tsx</span>
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> {<span class="hljs-title class_">ReactNode</span>} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;react&#x27;</span>;
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> {<span class="hljs-title class_">Metadata</span>} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next&#x27;</span>;
<span class="hljs-keyword">import</span> <span class="hljs-title class_">Link</span> <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next/link&#x27;</span>;
<span class="hljs-keyword">import</span> <span class="hljs-string">&#x27;./globals.css&#x27;</span>;

<span class="hljs-keyword">export</span> <span class="hljs-keyword">const</span> <span class="hljs-attr">metadata</span>: <span class="hljs-title class_">Metadata</span> = {
  <span class="hljs-attr">title</span>: <span class="hljs-string">&#x27;My App&#x27;</span>,
  <span class="hljs-attr">description</span>: <span class="hljs-string">&#x27;Next.js App Router 예제&#x27;</span>,
};

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">RootLayout</span>(<span class="hljs-params">{children}: {children: ReactNode}</span>) {
  <span class="hljs-keyword">return</span> (
    <span class="language-xml"><span class="hljs-tag">&lt;<span class="hljs-name">html</span> <span class="hljs-attr">lang</span>=<span class="hljs-string">&quot;ko&quot;</span>&gt;</span>
      <span class="hljs-tag">&lt;<span class="hljs-name">body</span>&gt;</span>
        <span class="hljs-tag">&lt;<span class="hljs-name">header</span>&gt;</span>
          <span class="hljs-tag">&lt;<span class="hljs-name">Link</span> <span class="hljs-attr">href</span>=<span class="hljs-string">&quot;/&quot;</span>&gt;</span>홈<span class="hljs-tag">&lt;/<span class="hljs-name">Link</span>&gt;</span>
        <span class="hljs-tag">&lt;/<span class="hljs-name">header</span>&gt;</span>
        {children}
      <span class="hljs-tag">&lt;/<span class="hljs-name">body</span>&gt;</span>
    <span class="hljs-tag">&lt;/<span class="hljs-name">html</span>&gt;</span></span>
  );
}</code></pre>
<p>루트 레이아웃은 <code>&lt;html&gt;</code>과 <code>&lt;body&gt;</code>를 가진다. 앱에 루트 레이아웃은 하나다.</p>
<pre><code class="hljs language-tsx"><span class="hljs-comment">// src/app/page.tsx</span>
<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> <span class="hljs-keyword">function</span> <span class="hljs-title function_">HomePage</span>(<span class="hljs-params"></span>) {
  <span class="hljs-keyword">return</span> (
    <span class="language-xml"><span class="hljs-tag">&lt;<span class="hljs-name">main</span>&gt;</span>
      <span class="hljs-tag">&lt;<span class="hljs-name">h1</span>&gt;</span>Hello, Next.js<span class="hljs-tag">&lt;/<span class="hljs-name">h1</span>&gt;</span>
    <span class="hljs-tag">&lt;/<span class="hljs-name">main</span>&gt;</span></span>
  );
}</code></pre>
<p><code>app/</code> 아래 파일은 기본이 서버 컴포넌트다. <code>useState</code>나 <code>onClick</code>이 없으면 <code>&#39;use client&#39;</code>를 붙이지 않는다.</p>
<h3>렌더 모드를 먼저 고른다</h3>
<p>페이지가 HTML을 언제 만드는지가 배포를 가른다.</p>
<table>
<thead>
<tr>
<th>모드</th>
<th>의미</th>
<th>언제</th>
</tr>
</thead>

<td>빌드할 때 HTML을 미리 만든다</td>
<td>문서, 마케팅, 블로그</td>
</tr>
<tr>

<td>요청마다 서버가 HTML을 만든다</td>

</tr>
<tr>
<td>혼합</td>
<td>목록은 정적, 일부만 동적</td>
<td>공개 글 + 관리자</td>
</tr>
</tbody></table>
<p>GitHub Pages처럼 서버 없이 HTML만 올리면 <code>output: &#39;export&#39;</code>를 검토한다. 정적 내보내기는 Route Handler·미들웨어·요청마다 다시 그리는 기능이 제한된다. 호스팅과 함께 결정한다.</p>
<pre><code class="hljs language-ts"><span class="hljs-comment">// next.config.ts</span>
<span class="hljs-keyword">import</span> <span class="hljs-keyword">type</span> {<span class="hljs-title class_">NextConfig</span>} <span class="hljs-keyword">from</span> <span class="hljs-string">&#x27;next&#x27;</span>;

<span class="hljs-keyword">const</span> <span class="hljs-attr">nextConfig</span>: <span class="hljs-title class_">NextConfig</span> = {
  <span class="hljs-comment">// 정적 호스팅이 필요할 때만 켠다</span>
  <span class="hljs-attr">output</span>: <span class="hljs-string">&#x27;export&#x27;</span>,
  <span class="hljs-attr">trailingSlash</span>: <span class="hljs-literal">true</span>,
};

<span class="hljs-keyword">export</span> <span class="hljs-keyword">default</span> nextConfig;</code></pre>
<p><code>trailingSlash: true</code>면 주소 끝이 <code>/</code>다. 링크와 CDN 설정을 같은 규칙으로 맞춘다.</p>

<h2>4. 흔한 실수</h2>
<table>
<thead>
<tr>
<th>실수</th>
<th>결과</th>
<th>대안</th>
</tr>
</thead>
<tbody><tr>
<td>페이지를 <code>pages/</code>에 만든다</td>
<td>App Router가 그 주소를 모른다</td>
<td><code>app/</code> 아래 <code>page.tsx</code></td>
</tr>
<tr>
<td><code>page.tsx</code> 없이 폴더만 만든다</td>
<td>URL이 생기지 않는다</td>
<td>공개할 경로에 <code>page.tsx</code></td>
</tr>
<tr>
<td>첫 파일부터 <code>&#39;use client&#39;</code></td>
<td>서버에서 데이터를 못 읽는다</td>
<td>상호작용 있는 잎만 Client</td>
</tr>
<tr>
<td>정적 호스팅인데 API Route를 넣는다</td>
<td>빌드가 깨지거나 런타임이 없다</td>
<td>호스팅을 먼저 고른다</td>
</tr>
<tr>
<td>루트 레이아웃에서 <code>&lt;html&gt;</code>을 뺀다</td>
<td>문서 뼈대가 깨진다</td>
<td>루트에만 <code>&lt;html&gt;</code> / <code>&lt;body&gt;</code></td>
</tr>
</tbody></table>
<hr>
<h2>정리</h2>
<p>App Router 시작은 폴더 이름 = URL, <code>page</code> = 화면, <code>layout</code> = 공통 셸이다.</p>
<p>정적 HTML만 올릴지, 서버가 있는 플랫폼에 올릴지를 프로젝트 첫날에 적는다. 그 선택이 데이터 페칭·인증·API 설계를 가른다.</p>
<hr>
<h2>연습</h2>
<ol>
<li><code>create-next-app</code>으로 TypeScript + App Router 프로젝트를 만든다.</li>
<li><code>/about</code>용 <code>app/about/page.tsx</code>와 공통 헤더가 있는 루트 <code>layout.tsx</code>를 추가한다.</li>
<li>팀 호스팅이 정적 내보내기인지 서버인지 한 줄로 적고, <code>output: &#39;export&#39;</code>가 필요한지 결정한다.</li>
</ol>
