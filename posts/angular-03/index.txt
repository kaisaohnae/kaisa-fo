24:T38f5,<h1>시그널·서비스·의존성 주입</h1>
<blockquote>
<p>요약: signal로 화면 상태를 두고, providedIn 서비스와 inject로 공유 로직을 연결하는 Angular 상태·DI 패턴을 정리한다.</p>
</blockquote>
<hr>
<h2>1. 왜 시그널과 서비스인가</h2>
<p>컴포넌트 필드는 그 화면만 안다. 로그인 사용자처럼 <strong>여러 화면이 같은 값</strong>을 보면 서비스로 올린다.</p>
<p>시그널(signal)은 <strong>값이 바뀌면 그 값을 읽는 템플릿만 다시 그리는 상자</strong>다. Vue의 <code>ref</code>와 역할이 비슷하다. 읽을 때 <code>count()</code>처럼 함수로 연다.</p>
<p>DI(의존성 주입)는 <strong>클래스가 <code>new AuthService()</code>를 하지 않고, Angular가 인스턴스를 넣어 주는 방식</strong>이다. 테스트에서 가짜 구현으로 갈아끼우기 쉽다.</p>
<table>
<thead>
<tr>
<th>층</th>
<th>역할</th>
</tr>
</thead>
<tbody><tr>
<td><code>signal</code> / <code>computed</code></td>
<td>이 화면 또는 서비스의 상태·파생 값</td>
</tr>
<tr>
<td><code>effect</code></td>
<td>값이 바뀔 때 로그·연동. 남용하지 않는다</td>
</tr>
<tr>
<td><code>@Injectable</code> 서비스</td>
<td>공유 로직·HTTP·인증</td>
</tr>
<tr>
<td><code>inject()</code></td>
<td>생성자 대신 현재 주입 컨텍스트에서 꺼내 온다</td>
</tr>
</tbody></table>

<p>구독은 서비스 한곳에서 시그널로 접는다. 컴포넌트가 <code>subscribe</code>를 들고 있으면 <code>destroy</code> 때 해제를 잊기 쉽다. <code>async</code> 파이프를 쓸 때는 템플릿에서 구독 수명을 맡긴다.</p>
<p>생성자 주입도 된다. <code>inject()</code>가 필드 초기화와 짧다. <code>inject</code>는 생성자·필드 초기화·<code>runInInjectionContext</code> 안에서만 호출한다. 임의 클릭 핸들러에서 부르면 실패한다.</p>

<h2>4. 제공 범위</h2>
<table>
<thead>
<tr>
<th>범위</th>
<th>언제</th>
</tr>
</thead>

<tr>
<td>컴포넌트 <code>providers: [X]</code></td>

</tr>
<tr>
<td>라우트 <code>providers</code></td>
<td>그 기능 라우트만. NgModule 대체</td>
</tr>
</tbody></table>
<p>테스트:</p>
<pre><code class="hljs language-ts"><span class="hljs-title class_">TestBed</span>.<span class="hljs-title function_">configureTestingModule</span>({
  <span class="hljs-attr">providers</span>: [{ <span class="hljs-attr">provide</span>: <span class="hljs-title class_">AuthService</span>, <span class="hljs-attr">useValue</span>: fakeAuth }],

<p>DI가 있는 이유다. <code>new AuthService()</code>를 컴포넌트 안에 쓰면 테스트가 실제 네트워크를 탄다.</p>
<hr>
<h2>5. 주의 / 흔한 실수</h2>
<ul>
<li><strong>시그널을 <code>count</code>로 출력.</strong> 템플릿도 <code>count()</code>다.</li>
<li><strong><code>computed</code>에 대입.</strong> 파생 값이다. 쓰기는 원본 <code>signal</code>.</li>
<li><strong><code>effect</code>에서 다른 시그널을 <code>set</code>해 연쇄 갱신.</strong> 순환이 난다. 이벤트 핸들러에서 갱신한다.</li>
<li><strong>컴포넌트에서 <code>HttpClient</code>를 직접 구독하고 해제 생략.</strong> 라우트를 나가도 콜백이 산다.</li>
<li><strong><code>providedIn: &#39;root&#39;</code> 서비스를 컴포넌트 <code>providers</code>에 또 등록.</strong> 인스턴스가 둘이라 로그인이 화면에 안 보인다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>상태는 <strong>시그널</strong>, 공유 로직은 <strong>서비스</strong>, 연결은 <strong>DI</strong>다.</p>
<ul>
<li>화면 국소 값 → 컴포넌트 <code>signal</code></li>
<li>앱 공유 값 → <code>providedIn: &#39;root&#39;</code> + <code>signal</code></li>
<li>꺼내기 → <code>inject(AuthService)</code> (생성자·필드에서만)</li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li><code>AuthService</code>의 <code>login</code>/<code>logout</code> 후 <code>isLoggedIn()</code>이 헤더와 홈에서 같이 바뀌는지 확인한다.</li>
<li><code>UserService.load</code> 실패 시 <code>error</code> 문구가 보이는지, 성공 시 목록이 바뀌는지 확인한다.</li>
<li><code>Home</code>에 <code>providers: [AuthService]</code>를 잠시 넣고, 헤더와 홈의 로그인 상태가 어긋나는지 본 뒤 제거한다.</li>
</ol>
