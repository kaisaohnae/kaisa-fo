<h2>1. 왜 컨트롤러에서 검증을 빼나</h2>
<p>검증 규칙이 컨트롤러에 쌓이면 유스케이스가 안 보인다. Laravel은 이 역할을 <strong>Form Request</strong>에 둔다. HTTP 요청 하나를 위한 클래스이며, “이 사용자가 이 동작을 해도 되는지”(<code>authorize</code>)와 “필드가 올바른지”(<code>rules</code>)를 함께 담는다.</p>

<h2>5. API Resource</h2>

<h2>8. 흔한 실수</h2>
<ul>
<li><code>$request-&gt;all()</code>을 <code>Post::create</code>에 그대로 넣는다.</li>
<li>모델 JSON을 그대로 반환해 숨겨야 할 컬럼이 나간다.</li>
<li>수정 시 <code>unique</code>에 <code>ignore</code>가 없다.</li>
<li><code>authorize()</code>를 항상 true로 두고 Policy를 우회한다.</li>
<li>생성 응답을 200으로 보낸다. 생성은 201이 계약에 맞다.</li>
</ul>
<hr>
<h2>연습</h2>
<ol>
<li><code>StorePostRequest</code>와 <code>UpdatePostRequest</code>를 나눈다. 수정의 unique에는 ignore를 넣는다.</li>
<li>show/index를 <code>PostResource</code>로 통일한다.</li>
<li>API 검증 실패 JSON 포맷을 <code>withExceptions</code>에서 맞춘다.</li>
