24:T331b,<h1>큐·Job·이벤트·스케줄링</h1>
<blockquote>
<p>요약: 메일·이미지처럼 느린 일은 Job 큐로 넘기고, 이벤트와 스케줄러로 후처리와 매일 할 일을 운영한다.</p>
</blockquote>
<hr>
<h2>1. 왜 요청 안에서 메일을 보내지 않나</h2>
<p>HTTP 요청은 짧게 끝나야 한다. 아래는 요청 스레드에 두지 않는다.</p>
<ul>
<li>메일·SMS</li>
<li>이미지 리사이즈</li>
<li>외부 API를 여러 번 호출</li>
<li>대량 CSV 내보내기</li>
</ul>
<p><strong>큐(queue)</strong> 는 “나중에 할 일”을 저장하는 대기열이다. <strong>Job</strong>은 그 대기열에 넣는 작업 한 건이다. 사용자는 201을 바로 받고, 워커 프로세스가 메일을 보낸다.</p>
<pre><code class="hljs language-env"><span class="hljs-attr">QUEUE_CONNECTION</span><span class="hljs-operator">=</span>database
<span class="hljs-comment"># 운영은 redis를 흔히 쓴다</span></code></pre>
<pre><code class="hljs language-bash">php artisan queue:table
php artisan queue:failed-table
php artisan migrate
php artisan queue:work</code></pre>
<p><code>queue:work</code>가 안 떠 있으면 Job은 테이블에만 쌓이고 아무 일도 안 일어난다. 로컬에서 “메일이 안 간다”의 원인 1위가 이것이다.</p>
<hr>

<h2>3. 멱등성과 중복</h2>
<p>큐는 최소 한 번이 아니라 <strong>적어도 한 번, 가끔 두 번</strong>이라고 가정한다. 네트워크 타임아웃 후 재시도가 겹칠 수 있다.</p>
<p>같은 환영 메일이 두 번 나가지 않게:</p>
<pre><code class="hljs language-php"><span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">SendWelcomeEmail</span> <span class="hljs-keyword">implements</span> <span class="hljs-title">ShouldQueue</span>, <span class="hljs-title">ShouldBeUnique</span>

    </span>{
        <span class="hljs-keyword">return</span> (<span class="hljs-keyword">string</span>) <span class="hljs-variable language_">$this</span>-&gt;user-&gt;id;
    }
}</code></pre>
<p>결제·웹훅은 unique만으로 부족하다. 처리한 id를 테이블에 남기는 <strong>idempotency key</strong>와 함께 설계한다.</p>
<hr>
<h2>4. 이벤트와 리스너</h2>
<p><strong>이벤트</strong>는 “주문이 접수됐다”처럼 도메인에서 일어난 일의 이름이다. 주문 서비스가 메일·재고·통계를 직접 알 필요가 없다. 리스너가 각자 구독한다.</p>
<pre><code class="hljs language-bash">php artisan make:event OrderPlaced
php artisan make:listener SendOrderConfirmation --event=OrderPlaced</code></pre>
<pre><code class="hljs language-php"><span class="hljs-title class_">OrderPlaced</span>::<span class="hljs-title function_ invoke__">dispatch</span>(<span class="hljs-variable">$order</span>);</code></pre>
<p>리스너에 <code>ShouldQueue</code>를 붙이면 발행은 가볍고 후처리는 워커가 한다. 서비스 클래스가 비대해지는 것을 막는 것이 목적이다. 이벤트를 남발하면 흐름이 안 보인다. <strong>여러 관심사가 한 유스케이스에 붙을 때</strong>만 쓴다.</p>

});</code></pre>
<p>또는 Job에 <code>ShouldDispatchAfterCommit</code>을 붙인다. 커밋 전 디스패치 → 롤백됐는데 메일은 나가고, 워커는 없는 주문을 찾는 레이스가 난다.</p>
<pre><code class="hljs language-php"><span class="hljs-class"><span class="hljs-keyword">class</span> <span class="hljs-title">SendWelcomeEmail</span> <span class="hljs-keyword">implements</span> <span class="hljs-title">ShouldQueue</span>, <span class="hljs-title">ShouldDispatchAfterCommit</span></span></code></pre>
<hr>
<h2>6. Horizon</h2>
<p><strong>Horizon</strong>은 Redis 큐를 위한 대시보드이자 프로세스 관리자다. 큐별 워커 수, 대기 시간, 실패 Job을 UI로 본다. <code>QUEUE_CONNECTION=database</code>면 Horizon의 본래 가치가 없다. Redis일 때 쓴다.</p>
<pre><code class="hljs language-bash">composer require laravel/horizon
php artisan horizon:install
php artisan horizon</code></pre>
<p>운영에서는 <code>queue:work</code>를 SSH에 띄워 두지 않는다. Supervisor(또는 컨테이너)가 Horizon/워커를 재시작한다.</p>
<hr>
<h2>7. 실패와 스케줄</h2>
<pre><code class="hljs language-bash">php artisan queue:failed
php artisan queue:retry all</code></pre>
<pre><code class="hljs language-php"><span class="hljs-keyword">public</span> <span class="hljs-function"><span class="hljs-keyword">function</span> <span class="hljs-title">retryUntil</span>(<span class="hljs-params"></span>): <span class="hljs-title">DateTime</span>
</span>{
    <span class="hljs-keyword">return</span> <span class="hljs-title function_ invoke__">now</span>()-&gt;<span class="hljs-title function_ invoke__">addHour</span>();
}</code></pre>
<p>실패를 삼키고 <code>failed()</code>도 없으면 사용자는 “메일이 안 온다”만 본다. Slack/메일 알림 또는 Horizon 알림을 붙인다. <code>$timeout</code>을 안 주면 워커가 한 Job에 영원히 묶일 수 있다.</p>
<p>스케줄은 Laravel 11+에서 <code>routes/console.php</code>에 둔다. 서버 cron은 <strong>1분마다 <code>schedule:run</code> 한 줄</strong>만 있으면 된다.</p>
<pre><code class="hljs language-php"><span class="hljs-keyword">use</span> <span class="hljs-title">Illuminate</span>\<span class="hljs-title">Support</span>\<span class="hljs-title">Facades</span>\<span class="hljs-title">Schedule</span>;

<span class="hljs-title class_">Schedule</span>::<span class="hljs-title function_ invoke__">command</span>(<span class="hljs-string">&#x27;reports:daily&#x27;</span>)-&gt;<span class="hljs-title function_ invoke__">dailyAt</span>(<span class="hljs-string">&#x27;01:00&#x27;</span>);
<span class="hljs-title class_">Schedule</span>::<span class="hljs-title function_ invoke__">job</span>(<span class="hljs-keyword">new</span> <span class="hljs-title class_">PruneOldTokens</span>)-&gt;<span class="hljs-title function_ invoke__">hourly</span>();
<span class="hljs-title class_">Schedule</span>::<span class="hljs-title function_ invoke__">call</span>(fn () =&gt; <span class="hljs-title class_">Cache</span>::<span class="hljs-title function_ invoke__">forget</span>(<span class="hljs-string">&#x27;homepage&#x27;</span>))-&gt;<span class="hljs-title function_ invoke__">everyFiveMinutes</span>();</code></pre>
<pre><code class="hljs language-cron">* * * * * <span class="hljs-built_in">cd</span> /path &amp;&amp; php artisan schedule:run &gt;&gt; /dev/null 2&gt;&amp;1</code></pre>
<p>겹쳐 돌면 안 되는 작업은 <code>withoutOverlapping()</code>을, 여러 서버면 <code>onOneServer()</code>를 쓴다.</p>
<hr>
<h2>8. 메일·알림</h2>
<pre><code class="hljs language-bash">php artisan make:mail WelcomeMail --markdown=mail.welcome
php artisan make:notification InvoicePaid</code></pre>
<pre><code class="hljs language-php"><span class="hljs-variable">$user</span>-&gt;<span class="hljs-title function_ invoke__">notify</span>(<span class="hljs-keyword">new</span> <span class="hljs-title class_">InvoicePaid</span>(<span class="hljs-variable">$invoice</span>));</code></pre>
<p>채널은 mail, database, slack 등이다. 로컬은 Mailpit 또는 <code>log</code> 드라이버로 실제 발송을 끈다.</p>
<hr>
<h2>9. 흔한 실수</h2>
<ul>
<li>워커를 안 켜 두고 Job이 “먹통”이라고 한다.</li>
<li>트랜잭션 안에서 바로 <code>dispatch</code>한다.</li>
<li>큐 payload에 HTML·파일 전체를 넣는다. id만 넣고 워커가 읽는다.</li>
<li><code>$tries</code> / <code>$timeout</code>이 없어 무한 재시도·무한 점유.</li>
<li>메일·결제 Job을 우선순위 없이 <code>default</code> 한 줄에 넣는다. <code>mail</code> / <code>high</code>로 나눈다.</li>
</ul>

<h2>연습</h2>
<ol>
<li>회원가입 후 <code>SendWelcomeEmail</code>을 afterCommit으로 보낸다.</li>
<li><code>OrderPlaced</code> 이벤트와 큐 리스너를 만든다.</li>
<li>Job을 실패시키고 <code>queue:failed</code>를 확인한다.</li>
<li>매일 자정 임시 파일 정리 스케줄을 등록한다.</li>
</ol>
