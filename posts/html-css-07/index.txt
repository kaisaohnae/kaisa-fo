24:T2451,<h1>폼·포커스·접근성 기본</h1>
<blockquote>
<p>요약: label 연결, 보이는 포커스, 네이티브 컨트롤로 키보드와 스크린 리더가 쓸 수 있는 폼을 만든다.</p>
</blockquote>
<hr>
<h2>언제 이 기준을 적용하는가</h2>
<p>입력·버튼·메뉴가 있는 화면은 마우스만 전제로 두지 않는다. Tab으로 이동하고, Enter·Space로 실행하고, 스크린 리더가 이름을 읽어야 한다.</p>
<p>접근성은 배포 직전 덧칠이 아니다. <code>label</code>과 <code>button</code>을 처음부터 올바르게 쓰면 대부분의 기본선은 채워진다. ARIA(접근 가능한 리치 인터넷 애플리케이션)는 네이티브 태그가 부족한 곳에만 보탠다.</p>
<hr>
<h2>폼의 최소 규칙</h2>
<p>모든 입력에는 보이는 레이블이 있다. <code>placeholder</code>는 힌트이지 레이블이 아니다.</p>
<pre><code class="hljs language-html"><span class="hljs-tag">&lt;<span class="hljs-name">form</span> <span class="hljs-attr">action</span>=<span class="hljs-string">&quot;/signup&quot;</span> <span class="hljs-attr">method</span>=<span class="hljs-string">&quot;post&quot;</span>&gt;</span>
  <span class="hljs-tag">&lt;<span class="hljs-name">label</span> <span class="hljs-attr">for</span>=<span class="hljs-string">&quot;email&quot;</span>&gt;</span>이메일<span class="hljs-tag">&lt;/<span class="hljs-name">label</span>&gt;</span>
  <span class="hljs-tag">&lt;<span class="hljs-name">input</span>
    <span class="hljs-attr">id</span>=<span class="hljs-string">&quot;email&quot;</span>
    <span class="hljs-attr">name</span>=<span class="hljs-string">&quot;email&quot;</span>
    <span class="hljs-attr">type</span>=<span class="hljs-string">&quot;email&quot;</span>
    <span class="hljs-attr">autocomplete</span>=<span class="hljs-string">&quot;email&quot;</span>
    <span class="hljs-attr">required</span>
  /&gt;</span>
  <span class="hljs-tag">&lt;<span class="hljs-name">p</span> <span class="hljs-attr">id</span>=<span class="hljs-string">&quot;email-error&quot;</span> <span class="hljs-attr">class</span>=<span class="hljs-string">&quot;error&quot;</span> <span class="hljs-attr">hidden</span>&gt;</span>올바른 이메일을 입력한다.<span class="hljs-tag">&lt;/<span class="hljs-name">p</span>&gt;</span>

  <span class="hljs-tag">&lt;<span class="hljs-name">button</span> <span class="hljs-attr">type</span>=<span class="hljs-string">&quot;submit&quot;</span>&gt;</span>가입<span class="hljs-tag">&lt;/<span class="hljs-name">button</span>&gt;</span>
<span class="hljs-tag">&lt;/<span class="hljs-name">form</span>&gt;</span></code></pre>
<p><code>label</code>의 <code>for</code>와 <code>input</code>의 <code>id</code>가 같아야 클릭이 입력으로 연결된다. <code>name</code>은 서버로 나가는 필드 이름이다.</p>
<p>에러는 입력 바로 아래에 텍스트로 둔다. 테두리 색만 바꾸면 스크린 리더와 색각 사용자에게 전달되지 않는다. 에러를 보여줄 때 <code>aria-describedby=&quot;email-error&quot;</code>로 입력과 문구를 잇는다.</p>
<p>아이콘만 있는 버튼에는 접근 가능한 이름을 준다.</p>
<pre><code class="hljs language-html"><span class="hljs-tag">&lt;<span class="hljs-name">button</span> <span class="hljs-attr">type</span>=<span class="hljs-string">&quot;button&quot;</span> <span class="hljs-attr">aria-label</span>=<span class="hljs-string">&quot;검색&quot;</span>&gt;</span>

<span class="hljs-tag">&lt;/<span class="hljs-name">button</span>&gt;</span></code></pre>
<p>장식 아이콘은 <code>aria-hidden=&quot;true&quot;</code>이다. 스크린 리더가 아이콘 파일명을 읽지 않게 한다.</p>
<p><code>div</code>로 만든 가짜 체크박스는 키보드·역할·상태를 직접 구현해야 한다. 네이티브 <code>input type=&quot;checkbox&quot;</code>를 먼저 쓴다.</p>
<hr>
<h2>포커스가 보여야 한다</h2>
<p>키보드로 이동 중일 때 지금 어디인지 보여 줘야 한다. <code>outline: none</code>만 남기고 대체 스타일을 안 주면 Tab 사용자는 위치를 잃는다.</p>
<pre><code class="hljs language-css"><span class="hljs-selector-pseudo">:focus-visible</span> {
  <span class="hljs-attribute">outline</span>: <span class="hljs-number">2px</span> solid <span class="hljs-built_in">var</span>(--color-accent);
  <span class="hljs-attribute">outline-offset</span>: <span class="hljs-number">2px</span>;
}</code></pre>
<p><code>:focus-visible</code>은 키보드 포커스에 가깝다. 마우스 클릭마다 두꺼운 테두리가 생기는 것을 피하면서, Tab 이동에는 윤곽을 남긴다.</p>
<p>커스텀 포커스를 디자인하더라도 대비가 되는 선이나 배경이 있어야 한다. 색 차이만 2%인 테두리는 포커스가 아니다.</p>

<hr>
<h2>움직임과 대비</h2>
<p>애니메이션이 불편한 사용자를 위해 시스템 설정을 존중한다.</p>
<pre><code class="hljs language-css"><span class="hljs-keyword">@media</span> (<span class="hljs-attribute">prefers-reduced-motion</span>: reduce) {
  *,
  *<span class="hljs-selector-pseudo">::before</span>,
  *<span class="hljs-selector-pseudo">::after</span> {
    <span class="hljs-attribute">animation</span>: none <span class="hljs-meta">!important</span>;
    <span class="hljs-attribute">transition</span>: none <span class="hljs-meta">!important</span>;
  }
}</code></pre>
<p>색 대비와 텍스트 확대(200% 전후)를 실제 브라우저에서 한 번 확인한다. 확대 시 버튼이 잘리거나 가로 스크롤만 생기면 레이아웃을 고친다.</p>
<hr>
<h2>흔한 실수</h2>
<ul>
<li><code>placeholder=&quot;이메일&quot;</code>만 두고 <code>label</code>을 생략한다. 값이 채워지면 이름이 사라진다.</li>
<li><code>outline: none</code>만 넣고 포커스 대체 스타일이 없다.</li>
<li>클릭 가능한 <code>div</code>로 체크박스·탭을 만든다. 네이티브 또는 역할·키보드를 모두 구현해야 한다.</li>
<li>오류를 <code>alert()</code>나 토스트만으로 보여 주고 입력 옆 문구가 없다.</li>
<li><code>aria-label</code>을 보이는 텍스트와 다르게 적어 스크린 리더와 화면이 어긋난다.</li>
</ul>
<hr>
<h2>정리</h2>
<p>접근성의 상당수는 HTML을 역할에 맞게 쓰는 습관이다. 레이블을 연결하고, 포커스를 보이게 하고, 네이티브 컨트롤을 우선하면 된다. ARIA는 그다음에 필요한 칸만 채운다.</p>
<hr>
<h2>연습</h2>
<ol>
<li>로그인 폼을 <code>label for</code>·<code>id</code>로 연결하고, 잘못된 비밀번호 오류를 입력 아래 텍스트로 보여 준다.</li>
<li>사이트 전역에서 <code>outline: none</code>을 검색한 뒤, 있으면 <code>:focus-visible</code> 스타일로 대체한다.</li>
<li>키보드만으로 헤더 내비 → 본문 링크 → 푸터까지 이동되는지 확인하고, 막히는 커스텀 위젯을 목록으로 적는다.</li>
</ol>
